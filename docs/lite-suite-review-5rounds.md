# LiteSuite 全11ツールの5回レビュー

2026-10-15。全11ツールについて「レビュー → 修正」を5回ずつ行った記録です。既存の操作と配布形式は維持し、コード上で実際の入力から不具合に至る経路を確認できた指摘だけを修正しました。

## 進め方

各ツールを独立したブランチで並行して見直し、毎回観点を変えて担当ファイル全体を読み直しました。

| 回 | 観点 |
| --- | --- |
| 1 | 主要ロジックの正しさ（誤判定・取りこぼし・境界値） |
| 2 | kintone REST API の扱い（上限・分割・revision・ゲストスペース・部分成功の表示） |
| 3 | UI 状態と操作の安全性（入力検証・二重実行・古い結果の残留・確認内容・キーボード・狭い幅） |
| 4 | 出力とセキュリティ（エスケープ・CSV 数式・ファイル名・ZIP・文字コード・性能） |
| 5 | 1〜4回目の差分を含めた総点検（回帰・テスト不足・資料との齟齬） |

指摘が無かった回は変更していません（kintoneJS取得の2回目、設定取得とプレビュー反映の5回目）。

## ツール別の主な修正

| ツール | 主な修正 |
| --- | --- |
| 差分比較 | 大量フィールドでの改名候補検出・影響範囲索引の二乗時間を解消。ゲストIDの事前検証、プラグイン設定取得の再試行、欠落要素で表示が止まる問題を修正。貼り付けで選択範囲を置き換え。HTML の無視キーを読める文字で表示。結果一覧の内部名・誤ラベルを修正 |
| プレビュー反映 | ゲストスペースのアプリを通常スペースと取り違える経路を修正。プリセット上限超過を通知。項目の途中で止まった書き込み済み操作を結果に明記。狭い幅の文字欠け、実行中の再起動、JSON の再選択を修正。大量一覧の差分を高速化し、`label` などのフィールドコードを属性名に訳さない |
| フィールド追加 | プレフィックス一括変更の JSON を既存フィールドのコード変更（変更前コードをキー）として出力。追加後の更新失敗で部分成功を表示。最終確認に対象コードと削除0件を表示。反映前にコード重複・不正な ID を検出し、何も書かずに中止 |
| kintoneJS取得 | 全置換で外れる件数を最終確認に表示。配列でない指定を拒否。取得元の表示・ID 検証・一括取得のゲスト指定を修正。ZIP 内ファイル名の安全化と大文字小文字の重複対策。取得時 revision を基準に、取得後の別更新を競合として検出 |
| 設定取得 | スペース取込のゲストID検証と空結果の警告保持。結果表に失敗セクション名と本文を取得できなかった JS/CSS ファイル数を表示。アプリ名を補完。ZIP ライブラリを取得前に確認 |
| 設計書作成 | 日本語のフィールドコード参照の誤検出を修正。Excel が選択した取得環境を使い、明示したゲストIDだけで接続先を決める。取得失敗・部分成功を完了表示で隠さない。単体 Excel の中断、狭い幅を修正。Markdown・Excel のエスケープとセル上限に対応 |
| ER図 | 起点IDの検証・正規化と、アプリ名で起動スクリプトが壊れる問題を修正。逆引き走査の取得失敗を表示。ダイアログのフォーカス、共有URL、ポップアップの順序を修正。代替 CDN が機能していなかった問題を修正。未取得の参照先へ移動できるようにした |
| プロセス実行 | 開始状態の判定とプロセス無効時のソース出力を修正。想定外の応答を明示。シミュレーション通知のトーンと簡易表示の理由を修正。強調表示をコピー用ソースに含めない。読み込み済みの mermaid にも strict を適用 |
| kintoneレコード取得 | コピー時のテーブル内の型不一致と CSV 取込の全空行を修正。一括書き込み失敗時に行・フィールドの詳細を表示。コピー先の取り違えで空レコードを作らない。キャンセルを完了扱いにしない。添付の上書き、ZIP 名、CSV の文字化け（Shift_JIS）を書き込み前に検出 |
| CSV出力 | 作成者・更新者・作業者・カテゴリーを JSON 文字列でなく値で出力し、値を持たない部品の空列を除外。部分成功の内訳を画面に表示。limit / offset を含む条件を確認前に停止。利用者指定のファイル名を安全化 |
| データ品質チェック | 先頭0付きアプリIDの二重検査を修正。設定応答が空のときのエラー表示を修正。単体パネルの入力検証・二重実行・古い完了表示を修正。結果 CSV の数値セルに数式対策の記号を付けない |

統合時に、全ツール共通の問題も修正しました。ゲストスペースのアプリ画面で開くと、既定の対象にアプリIDだけが入り、通常スペースの同じ番号のアプリを指していました。既定値とアプリ表の「現在のアプリ」で、ゲストスペースIDも入れるようにしています。

## 検証結果

| 検証 | 結果 |
| --- | --- |
| `npm run check` | 成功。ブラウザストレージ検査、通常・strict 型検査、76ファイル・1241テスト、11本のビルド |
| `npm run test:all -- --browser chromium` | 12スイートすべて成功。共通パネル、レコード補助、データ品質、8ツールの操作フロー、プレビュー反映、差分比較4種、ER図の表示比較、ファイル出力 |

Chromium で実行する場合、ロケールが未設定の環境では保存ファイル名が `download` になり、プレビュー反映と差分比較の表示比較が失敗します。`LANG=C.UTF-8` を指定して実行してください。

## 未対応・判断が必要な点

- JS/CSS 設定の反映は、取得した JSON の FILE の fileKey をそのまま送ります。別アプリへの反映は kintone に拒否されます（確認画面で警告）。ファイルを再アップロードする対応は機能追加のため見送りました。
- （対応済み）JS/CSS 本文の取得と REST API の GET に応答待ちの上限を設け、全ツールの実行中に「中止」ボタンを追加しました。通信が止まったまま処理中が続くことはなくなりました。
- 設定取得でプラグインを選ぶと、プラグイン設定値がそのまま出力されます。機微な値を含む場合があります。
- ER図は本番の設定だけを対象にします。プレビューにしかないアプリは図にできません。
- 設計書の Excel が取得する Webhook 設定の API は、公式仕様で確認できていません。取得できない場合は「API取得失敗レポート」に載ります。
- 画面検証は合成データとテスト用の API 応答で行いました。実アプリへの反映や運用データでの確認は含みません。
