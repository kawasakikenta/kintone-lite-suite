# kintone lite ツール群 機能説明

対象: `tools/*.js` の単機能liteバンドル

## 概要

このドキュメントは、共通ソースから生成するkintone向けliteツール群の機能仕様をまとめたものです。廃止済みの `tools/統合ツール.js` を読み込むのではなく、目的に応じて `tools/差分比較.js`、`tools/ER図.js` などの単機能バンドルを使用します。以下の「タブ」は機能分類または各liteパネル内の画面を指し、全機能を1つの画面から起動する構成ではありません。

> SQL 実行は共通ビルドに含まれません。別リポジトリ `kintone-data-utilities` の `kintoneSQL.js` を利用してください。

主な用途は以下です。

- 開発環境と本番環境の設定差分を確認する
- 比較元の設定を比較先のプレビュー環境へ反映する
- フィールドや JS/CSS 設定を個別に移送する
- 設計書や差分レポートを出力する
- 複数アプリの設定をまとめて保存する
- フィールド参照・通知・権限・レイアウトを横断的に分析する
- レコード運用や可視化作業をまとめて行う

## 基本概念

- 比較元: コピー元、参照元となるアプリ
- 比較先: 差分確認先、反映先となるアプリ
- プレビュー: アプリ設定の未デプロイ領域
- バンドル: 各種設定をまとめて取得した JSON データ
- セクション: アプリ設定の比較単位

比較対象セクションは主に以下です。

- アプリ設定
- フィールド設定
- レイアウト設定
- フォーム設定
- ビュー設定
- レポート設定
- プロセス管理
- プラグイン
- JS/CSS 設定
- アクション設定
- アプリ権限
- フィールド権限
- レコード権限
- 通知設定
- レコード条件通知
- リマインダー通知
- カテゴリ設定

## 共通設定

各liteパネル上部の接続設定は、その機能で利用する比較元・比較先・ゲストスペースを指定します。

### 接続先設定

- 比較元アプリ ID / ゲスト ID / プレビュー指定
- 比較先アプリ ID / ゲスト ID / プレビュー指定
- 比較元を現在アプリに設定
- 比較元の内容を比較先へコピー
- 比較元と比較先の入れ替え

### 環境プロファイル

- 比較元 / 比較先の組み合わせを名前付きで保存
- 開発、検証、本番などの環境切替を簡略化

### ルックアップ参照先アプリ ID 変換

- フィールド反映時に参照先アプリ ID を置換
- 環境ごとにアプリ ID が異なる場合の移送を補助

### 作業履歴

- 作業状態（接続先・選択状態など）をセッション内メモリへ手動保存・復元
- 履歴の個別削除 / 全削除
- ブラウザ再読み込みで消去されます（ブラウザストレージは使用しません）

### 共通データ取得 / クイック実行

- 比較元 / 比較先の共通データを先読み
- 差分比較から反映プラン確認までを連続実行

## タブ別機能

### 1. 差分比較

公開中の `差分比較.js` は単一パネルで比較条件、結果確認、ファイル出力までを完結します。以下は現行 lite 版と、そこから生成する自己完結 HTML レポートの機能です。判定規則と上限の正本は [差分比較ロジック説明](../docs/diff-comparison-logic.md) です。

#### 非フィールド差分の検出精度

フィールド以外のセクションも、エンティティ単位で安定して差分を検出します。

- **ドメイン識別子マッチング**: アプリ権限はエンティティ（type:code）、フィールド権限・レコード権限のエンティティ配列も対象エンティティ、一般通知は宛先エンティティ、レコード条件通知・リマインダー通知はタイトル、遷移アクションは name|from|to の組み合わせで左右をマッチング。並び替えは added/removed の組ではなく moved 行へ集約され、個別の変更は「どのエンティティの何が変わったか」単位で出力されます
- **純粋並び替え検出**: 中身が同一で並びだけ違う配列（レイアウト行など）は moved 行のみで報告
- **moved 統合（LCS）**: 並び替えと追加/削除が混在する配列でも、同一内容が別位置に現れた added/removed ペアを moved 1 行（移動位置「N番目 → M番目」付き）に統合
- **表記ゆれ・空値ゆれの注記**: `"100"` ⇄ `100`、`"true"` ⇄ `true` などの差分は「表記のみ」、空文字 / null / 空配列 / 空オブジェクト同士の差分は「空値の差のみ」と注記。差分行自体は残します
- **改名検出**: フィールドコード変更やビュー / ステータス / 通知などのエンティティ改名を added/removed のペアから推定し「改名候補」として表示。プロセス管理のステータス改名は遷移アクションの from/to 参照カスケードを自動吸収し、改名 1 行に集約
- **客観分類**: 変更種別（追加 / 削除 / 内容変更 / 移動 / 同一）と存在状況（比較元のみ / 比較先のみ / 両方）を分離して表示。重要度や対応優先度は自動判定しません
- **関連設定の表示**: フィールド削除・改名時はフィールド権限・レコード権限等で見つかった参照を、ステータス削除・改名時は参照している遷移アクションを「関連している設定」として表示。業務影響や因果関係の断定ではありません
- **プラグイン取得結果**: プラグインセクション直下の `fetched` / `skipped` / `failed` は設定差分へ数えません。`failed` または `skipped` が1件以上なら、通常の差分ではなく取得不完全の警告として扱い、そのセクションを比較不能にします。現在の設定取得でも、ID欠落や不正な応答で設定を取得できなかった項目は同じ扱いです

#### 比較条件

- 比較対象セクションの選択
- 無視キーの設定
- **よく使う除外**: 「環境固有ID（アプリ・一覧・グラフ・アクション）を比較から除外」を折りたたまずに表示し、比較対象・参照先のApp IDと、一覧・グラフ・アクション自身の内部IDだけを除外。既定はオフで、フィールドコード、一覧条件、アクションの対応付け、プラグインID、独自設定内の一般的な `app` / `id` は比較対象に残します。変更後は再比較が必要で、差分件数・画面結果・Excelへ同じ条件を反映します
- セクション別の順序、監査情報、文言、外観、有効フラグ等を対象にした正規化プリセットの適用
- **比較条件プロファイル**: セクション、無視ルール、正規化、同一行、文字差分、表示密度、左右／上下の比較レイアウトをJSONで保存・読込。アプリID、設定本文、認証情報は含めない
- 無視キーの保存 / 読込
- 比較元 / 比較先バンドルの読込、解除、保存
- **3つの比較方法**: 1件ずつ比較する「1対1比較」、1つの比較元を複数の比較先へ照合する「1対多比較」、複数の比較元と比較先を各行で1対1に対応付ける「ペア一括比較」を切り替えられます。
- **ペア一括比較**: 比較元App ID / Guest ID / 運用・プレビューと、比較先App ID / Guest ID / 運用・プレビューを最大50ペア登録し、登録順に1件ずつ比較します。2列または4列の表をまとめて貼り付けできます。片側欠落、同じペア、比較元または比較先の重複は行番号付きで実行前に表示します。API取得時は同一接続先同士も止めます。途中失敗後も後続を続け、結果表には両側のアプリと環境を残します。成功行ごとにExcelまたはHTMLを保存できます。
- **複数対複数のフォルダ取込**: ペア一括比較で「比較元（変更前）フォルダ」と「比較先（変更後）フォルダ」を選択し、配下の設定JSONを再帰的に読み込めます。一意なアプリ名、次に一意なApp IDだけを自動対応し、曖昧な組み合わせは対応確認表で手動選択します。App ID一致・フォルダ順候補は行ごとの確認チェック、対象外にする行や未使用の比較先も明示チェックで確定し、確認済みペアで現在の表を置き換えます。フォルダ由来の行は設定JSONと接続情報を固定し、同一App IDの旧／新スナップショットを比較できます。不足分をAPIで補わず、左右のキャッシュも共有しません。再読込を始めた時点で旧結果と保存導線を無効化し、読込中の比較も止めます。1回の選択上限は全ファイル2,000件、JSON 500件、JSON合計128MB、1フォルダ50アプリです。
- **差分比較の実行 → HTML レポート出力**: 「差分比較を実行」を押すと、比較完了と同時に差分 HTML レポートをダウンロードします（出力ボタンを別途押す必要はありません）。「1対多比較」でも比較先ごとに HTML を自動保存します。「ペア一括比較」はブラウザの複数ダウンロード確認を避けるため、結果行から必要なHTMLを保存します。
- **差分一覧 Excel 出力**: Lite版から保存する `.xlsx` は「比較概要」と「変更一覧」を索引として常設し、実差分があるAPIだけを `API_01_アプリ一般設定` から `API_20_カテゴリー設定` のAPI別シートへ分けます。対応APIを特定できない差分は `API_99_API未特定` にまとめ、差分がないAPIの空シートは作りません。プラグイン個別設定は `API_10_プラグイン個別設定`、カスタマイズファイル本文は `API_12_カスタマイズ本文` へ分け、プロセスのアクションは `API_08_プロセス管理`、アプリアクションは `API_13_アプリアクション` として混在させません。「設定値詳細」には全実差分の比較元・比較先のAPI原文を同じNo.で収録し、各API別シートから内部リンクで移動できます。取得失敗・一部未検証・件数上限がある場合は「確認できなかった範囲」を概要の直後に追加します。同一行は収録せず、表示専用行はテーブル全体の追加・削除を内包フィールドへ展開する子行だけに限定します。権限・通知・プラグイン・JS/CSS設定を含む実差分は1差分1行で収録します。並び順変更とkintoneの `index` は、意味が確定する設定だけ比較元・比較先を1始まりの「N番目」「M番目」で示します。独自設定の `index`、`no`、`size` は変換しません。設定値詳細は状態・型の専用列を設けず、不存在・undefined・null・空文字を値列へ直接表示します。長文は必要時だけ「長文原文」へ分割します。差分0件でも「変更一覧」に罫線付きの「差分はありません」行を出して保存できます。
- **フォームフィールドの専用表示**: `API_03_フォームフィールド` では「配置 / フィールド名 / フィールドコード / フィールド種別 / 差分プロパティ / フィールド存在 / 設定値存在」を別列にします。フィールド自体の追加・削除は変更前後を「存在」「存在しません」で示し、個別プロパティだけが片側にない場合とは存在列で区別します。テーブルと内包フィールドは親子表示し、配置列に親テーブルの名称とコードを示します。子行はExcelのアウトラインで折りたたみ・展開できます。
- **Excel のレビュー向けレイアウト**: 変更一覧は「No. / 変更区分 / 分類 / 設定対象 / 差分プロパティ / 変更前 / 変更後」の7列です。人が読める名称を優先し、ログインユーザーなどの条件関数、対象種別、`WRITE / READ / NONE`、プロセス作業者方式、フィールド・一覧・グラフ・カスタマイズの列挙値をセクションとパスの文脈に合わせて日本語化します。条件式の引用符内と自由入力は置換しません。変更前は淡い赤、変更後は淡い緑、存在しない側は無彩色で表示します。空欄や比較対象が存在しない側を含め、すべての表の全行・全列へ同じ細い淡色の四辺罫線を適用し、強調は背景色と文字色で行います。シート・行・列を非表示にせず、セル数式と外部リンクも生成しません。概要には完全性、「変更対象一覧」と同じ対象単位の変更対象件数、機能別の差分明細件数、比較条件、掲載範囲を表示します。重要度・影響度や対応要否は自動判定しません。
- **Excel の一括保存**: 1対多比較とペア一括比較では、「Excelをまとめて保存（N件・ZIP）」からExcelを1つのZIPで保存します。先頭の `000_一括比較結果.xlsx` でExcel生成対象の結果、差分内訳、アプリ名の不一致、個別Excel名を確認でき、個別Excelは登録順の番号と短い業務名で命名します。差分0件と取得不完全の結果も含み、比較失敗とExcel生成失敗は個別Excelから除外します。Excel生成失敗は、少なくとも1件を保存できる場合には集計へ状態を残します。ZIPには `.xlsx` 以外を入れず、上限は200MiBです。
- HTML レポートは「差分一覧」「フィールド単位」の 2 タブ構成（サマリー / 比較対象設定タブは廃止）。レポート内の「詳細オプション」で、出力前と同じ無視キー・順序無視などの条件を後から選択して表示を絞り込み可能
- 「範囲」で全件 / 表示中を選び、Excel保存または HTML の再出力が可能
- **HTML内容モード**: 既定の「差分行のみ（全設定は未収録）」は比較元/先の全設定スナップショットを埋め込まず、元設定JSON・フィールド詳細・反映JSONを収録しません。「比較設定込み（取扱注意）」を明示選択した場合だけ詳細機能を有効化します。どちらのHTMLにも差分行の比較元/先の値は残り、Excelにも同じ差分値を加工せず収録します。共有前に内容を確認してください。
- **画面内レビュー**: 変更種別・セクション・キーワード等で絞り込み、`J` / `K` と前後ボタンで実差分を先頭・末尾の範囲内で移動。固定ヘッダーは BEFORE / 現在位置 / AFTER の3レーンで比較方向を保ち、有効な絞り込み条件は個別解除できるチップで表示します。表示密度、全折りたたみ / 展開、左右／上下の比較レイアウトも切り替え可能です。
- **連続レビュー**: HTMLレポートでは全体とセクション別の確認済み件数・進捗率を表示し、「確認して次へ」または `R` キーで現在行を確認済みにして次の未確認差分へ移動できます。集中表示でも比較元 / 比較先のアプリ名と App ID、現在位置、未確認数を残します。コンパクト密度ではカード余白を縮めて大量差分を高速に読み進められます。
- **レビュー状態の持ち運び**: 「レビュー状態JSON保存 / 読込」で確認済み状態を明示的に保存し、後から同じ比較結果へ復元できます。別レポート用のJSON、未知・重複した行、2MBを超えるファイルは現在状態を変えずに拒否します。ブラウザ内へ状態を自動保存しません。
- **大量差分向けの軽量表示**: 検索文字列を行単位でキャッシュし、連続入力は150msのデバウンス後に1回だけ反映します。日本語IME変換中の再描画を抑え、画面外カードは対応ブラウザで描画負荷を軽減します。表示件数 / 全体件数 / 未確認件数は常設の読み上げ領域へ通知します。
- **読みやすい差分カード**: 行見出しは日本語の要約を優先し、内部パスは「技術情報」に折りたたみます。長い値やJSONは行数・文字数付きのプレビューで表示し、必要な行だけ全文へ展開できます。
- **無視ルール候補**: 差分行の「パスを無視」から、大小文字・空白・`*`・区切り記号をリテラルとして扱う `path:` 形式の完全パスを次回比較条件へ追加（現在の結果は変更せず、再比較後に適用）。配列番号を含む位置依存パスは誤除外防止のため自動追加不可
- **不完全比較の明示**: 件数上限後に走査していないセクションは「未走査・件数不明」として、取得失敗や本文未検証と区別して表示

#### HTML レポートの機能

差分 HTML レポートは、単体で完結する自己完結型ページです（外部 CDN 依存なし）。

- **差分一覧タブ**: 完全性、比較方向、客観件数を先に示し、セクション別に差分カードを表示します。レビュー受信箱、セクション見出し、ジャンプナビには確認済み / 対象件数を表示し、追加 / 削除 / 内容変更 / 移動 / 同一、使用中フィルター、文字単位ハイライトで変更箇所を把握できます。
- **比較レーンと段階表示**: 比較元を BEFORE、比較先を AFTER として値の方向を常に明示します。日本語の意味を先に見せ、内部パスやコードは「技術情報」、長い値は展開可能なプレビューへ分離します。
- **モバイル表示**: 狭い画面では比較値を1列に積み、絞り込み・出力のサイドバーを開閉式にして、横スクロールせずレビューできます。
- **モバイルドロワー**: 絞り込み・出力は本文を押し下げない固定ドロワーで開きます。背景操作を抑止し、`Esc`・閉じるボタン・背景クリックで元の操作位置へ戻ります。
- **JSONで比較（フィールド単位）**: WinMerge のように設定 JSON 全体を左右に並べて行単位で比較するモード。フィールドごとにブロックを区切り、変更行のハイライト・行番号・文字単位差分を表示（「複数行差分は変更行だけ表示」をオフにすると全行を整列表示）
- **フィールド単位タブ**: フィールドコード単位で、比較元 / 比較先の設定を kintone の設定ダイアログ風スナップショットで左右に並べ、値が異なる項目に差分色を付与。関連レコード一覧設定・ルックアップ設定・テーブル内の項目は、日本語ラベル付きの key-value 表で差分行を赤（比較元のみ）/緑（比較先のみ）/黄（変更）に色分けし、変更値は文字単位でハイライト。差分一覧と同じ種別チップ（追加 / 削除 / 変更 / 同一）での絞り込みと詳細オプション（無視キー・正規化プリセット）が有効
- **反映JSON作成**: 差分行・フィールドの「選択」チェックから、比較元の設定値を比較先アプリへ反映するための API パラメータ JSON を作成（保存 / コピー）。画面の「比較元=変更前 / 比較先=変更後」で比較した場合は変更前へ戻す方向になるため、前進移行では完成状態を比較元、反映先の現状を比較先にして再比較します。フィールドは `form/fields` の PUT / POST / DELETE に分解し、全体置き換え型のセクションは対応 API の payload を生成します。プロセスの状態名変更がある場合は、別の変更へ改名が混入するのを防ぐためHTMLの反映JSON全体を無効にし、統合版でもプロセス管理のセクション単位反映と失敗セクション再実行をブロックします。外部パッチJSON内の確認専用行・予約済み改名パスも拒否します。状態名変更以外は行／ノード単位で選ぶか、管理画面で手動確認します。
- **作成時に利用した設定JSONの出力**: レポート作成に使った比較元 / 比較先アプリのセクションデータを、それぞれ JSON ファイルとして保存可能
- **確認済み管理**: 各差分行の「確認」チェックで確認済みをマークし、サイドバーの「確認済みを隠す」で残作業だけに絞り込み。確認済み・選択中件数はサマリーに表示
- **コピー / エクスポート**: 行ごとに設定パス・値（JSON）をワンクリックコピー。表示中の差分を CSV 保存 / Markdown 表としてクリップボードにコピー
- **キーボード操作**: `J` / `K`（または「前へ / 次へ」）で差分行を順に移動、`Ctrl/⌘+F` で検索フォーカス、`Esc` で検索クリア
- ライト / ダークテーマ切替、セクションへのジャンプナビ、印刷プレビュー対応

#### セクション別ビュー（旧統合版の参考実装・現行 `差分比較.js` では未公開）

非フィールドセクション向けに、カテゴリ別タブと各セクション専用の可視化を提供します。

- カテゴリタブ: フィールド / レイアウト / ビュー・グラフ / プロセス・アクション / 通知 / 権限 / JS・CSS・プラグイン / アプリ設定（数字キー 1〜8 で切替）
- **フィールド**: フィールドコード単位で集約し、ラベル・型バッジ付きで表示。フィールド定義の追加/削除はタイプ / ラベル / 必須 / 選択肢などの要約で表示
- **権限**: エンティティ × 操作のマトリクス（許可↑ / 縮小↓ を色分け）。フィールド権限は NONE / READ / READ_WRITE の昇降を矢印で表示
- **プロセス**: ステータス遷移を SVG フロー図で表示（追加=緑/破線、削除=赤/破線、不変=灰）。ステータス一覧・アクション一覧を別表で併記
- **通知**: ルールカード（条件・トリガー・タイミング・宛先エンティティ）
- **ビュー・グラフ**: 表示項目・絞込条件・ソートをカード表示。変更ビューは変更詳細を折りたたみで列挙
- **レイアウト**: 比較元 / 比較先の配置を並べたグリッドビュー（新規=緑、削除=赤、GROUP は紫枠）
- **JS/CSS・プラグイン**: ファイル一覧（desktop / mobile × JS / CSS）とプラグインのバージョン差分
- **アプリ設定**: 変更があるキーのみを抽出した key-value 表（appSettings / appInfo / formSettings / categories）
- ヘッダーに比較元/比較先アプリ名を表示
- Markdown コピー / ファイル保存 / 印刷プレビュー対応

#### 履歴・監視（旧統合版の参考実装・現行 `差分比較.js` では未公開）

- 比較スナップショット履歴の保存と復元
- 履歴の一括削除
- 複数比較先への一括差分比較

### 2. プレビュー反映

比較元の設定を比較先プレビューへ反映するタブです。

- 差分を元に反映対象セクションを選択
- セクション単位の反映
- 高重要度セクションの自動選択
- セクション別の差分件数 / 重要度確認
- ノード単位の反映
- ノード検索、絞り込み、全選択、表示中のみ選択 / 解除、Undo / Redo
- 反映対象と最新プランのサマリ表示
- バックアップ自動保存
- エラー時中断
- 反映後デプロイ
- 反映プラン確認（反映の方向〔比較元 → 比較先プレビュー〕とアプリ名を明示、削除を含む場合は赤帯で件数を警告）
- プラン確認キャンセル時も結果表示を維持（Esc・×・背景クリックでも安全にキャンセル）
- プラン確認モーダルから直接反映する場合は同内容の確認を重複表示しない（最終確認は必ず実施）
- 最終確認の重さはリスクに比例（注意点なし: チェックのみ / 注意点あり: キーワード入力 / 高リスク: 比較先アプリID入力）
- 比較先プレビューのバックアップ
- プレビューへの反映
- デプロイのみ実行
- パッチ JSON を直接読込 / 編集して反映

単機能版（`プレビュー反映.js`）では、上記に加えて次の操作補助があります。

- 実行結果をセクション単位で記録し、「失敗・未実行だけ選択」で再実行対象をワンクリックで選び直し（エラー中断時の未実行セクションも含む）
- 反映エラーのログに対処ヒントを併記（権限不足 / アプリID誤り / ルックアップ参照先 / フィールド未反映 / 通信エラーなどの典型パターン）
- 高リスク実行の追加確認（比較先アプリID入力）時に、高リスクと判定した理由を明示
- 実行後に「比較先の設定画面を開く」から運用環境への反映（デプロイ）操作へ直接移動

### 11. APIテスター

- kintone API の GET / POST / PUT / DELETE を直接実行
- パスまたは URL を指定
- リクエスト Body を JSON で入力
- レスポンスを画面表示
- プリセットはカテゴリ別（取得 / 更新 preview）に整理。アプリ情報・設定・フィールド・レイアウト・ビュー・プロセス管理・デプロイ状態・レコード・コメント等
- 「JSON整形」で Body を検証＋整形
- 実行メタ表示（経過時間 / レスポンス形状 / サイズ / ステータス）と、レスポンスのコピー / JSON 保存
- 実行履歴に時刻を表示、履歴の JSON エクスポート
- 画面内 Ctrl/Cmd + Enter で実行

## 推奨利用フロー

典型的な使い方は以下です。

1. 比較元 / 比較先を設定する
2. 必要なら環境プロファイルを適用する
3. 差分比較で設定差分を確認する
4. 反映プランを確認する
5. 比較先プレビューへ反映する
6. 必要に応じてデプロイする
7. 設計書や差分レポートを出力して記録を残す

## 注意事項

- 反映系処理は比較先プレビューまたは本番データへ影響します
- 全レコード削除、CSV インポート、アプリ間コピーは実データ変更を伴います
- 反映前にバックアップを取得する運用を推奨します
- ルックアップ、添付ファイル、プロセス関連の移送は環境差異の影響を受けやすいです
- プラグイン設定はプラグイン本体の配布や個別設定内容までは含まれない場合があります
