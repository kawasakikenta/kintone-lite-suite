# 次にやる作業（kintone-lite-suite）

更新: 2026-10-30。前提と検証方法は `CLAUDE.md` を先に確認してください。

## T1. Playwright 比較ハーネスの CI 分離（実装済み）

- 通常 PR と main 更新で複数比較先・ペア・フォルダペア・プレビュー反映・lite 操作の DOM ハーネスを実行する。
- 重い `test:diff-compare` と `test:er-compare` は対応する UI／出力ソース・生成物・共通依存・ハーネスの変更時、または `workflow_dispatch` で実行する。
- PR は比較元ブランチの SHA、main 更新は push 前の SHA を比較基準にする。詳細は `tools/test-harness/README.md` を参照。
- 比較 HTML、JSON、PNG などは 7 日間の Actions artifact とし、Git へ追加しない。

## T2. ER 図の外部依存固定

生成 HTML が実行時 CDN 応答へ依存しないよう、Cytoscape、Dagre などを固定版で同梱する。難しい場合は SRI と厳格な CSP を適用し、供給網リスクを明示する。

## T3. Excel 差分出力の安全共有

共有用マスキング、暗号学的な内容識別子、出力サイズ上限、レビュー結果の再取込を段階的に追加する。人向けレビュー表と技術明細の役割分離は維持する。

## T4. プレビュー反映の実環境確認

2026-10 の改善（一般設定、別アプリの JS/CSS 転送、未公開の変更の確認、バックアップから戻す、複数アプリへの順次反映）は、合成 API と画面ハーネスでのみ検証している。検証用アプリで次を確認する。

- 公開直後に、本番とプレビューの revision が一致するか。「変更を中止」した後の revision の扱い（未公開の変更の判定に使う）。
- 一般設定の PUT（タイトルを自動・手動にする、数値の桁数と丸め、年度の開始月）が受け付けられるか。
- ゲストスペースを含む JS/CSS ファイルのダウンロード・アップロード（`POST /file.json` と `__REQUEST_TOKEN__`）と、新しい fileKey での customize PUT。
- バックアップJSON（ファイル本体を埋め込み）を反映元にした復元で、JS/CSS と一覧が反映前に戻るか。
- 書き込みの再試行（5xx・通信失敗）で同じ revision を再送したとき、初回がサーバー側で確定していた場合に GAIA_CO02（競合）になるか。なる場合は「直前の書き込みが成功していた可能性」を案内に加える。
- 同名の一覧の種類（表形式→カレンダー形式など）を変える PUT と、フィールド権限・リマインダー通知・プロセス管理の作業者が存在しないフィールドを参照する PUT が受け付けられるか（受け付けられなければ事前検査が必要）。

### T4 の実環境での確認結果（2026-10-31）

Yu5 テナントのテスト専用アプリ（62・63）で確認した。書き込みはアプリ 63 のプレビューのみで、確認後に変更を中止した。

- 「変更を中止」した後のプレビューの revision は本番と同じ値に戻る（未公開の変更の判定に使える）。
- リマインダー通知が無いアプリの `timezone` は `null`。`timezone: null` の PUT は受け付けられ、kintone が既定値を入れる（空文字は拒否）。
- カテゴリーは名前をキーにしたオブジェクトで、階層は `children`（配列は `CB_IJ01`、キーと `name` の不一致は `GAIA_NM01`、`index` と `children` は必須）。カテゴリーが無いアプリは `categories: {}`。
- 反映元と反映先で先頭のステータスが違うと、プロセス管理の PUT は「先頭のステータスは、先頭以外の位置に変更できません」で拒否されることがある（差分確認で警告する）。
- 通知先の `FIELD_ENTITY` を含むリマインダー通知の PUT と、一度失敗した後の別の PUT の revision 引き継ぎは正常に動く。

未確認: 一般設定の PUT、ゲストスペースのファイル転送、バックアップからの復元、書き込み再試行時の revision、一覧の種類変更。

## T6. 環境内の全アプリを対象にする機能の実環境確認と残課題（2026-10 追加）

全 11 ツールに「環境内の全アプリ」（アプリ検索）と、複数アプリへの一括処理を追加した。合成 API・単体テスト・画面ハーネスでのみ検証している。数百〜数千アプリの環境で次を確認する。

- `/apps.json` の全ページ取得にかかる時間と、候補表（数千行）・対象アプリ表（数千行）の描画・入力の重さ。確認画面の署名（`installLiteWorkflow`）は第 1 段の入力をすべて走査するため、数千行の表での操作感を確認する。
- 差分比較の 1対多: 比較先ごとに比較先バンドルと差分行をメモリに保持する（比較元は 1 つを共有）。数千件では数 GB に達しうるため、実際の使用量を測り、必要なら差分 0 件の比較先は保持せず必要時に再取得する、一定件数ごとに分けて実行する、などを検討する。
- 設計書 ZIP・CSV出力・設定取得の ZIP は全件をメモリ上で作る。数千アプリでの上限（ZIP サイズ、ブラウザのメモリ）を確認する。
- レコード管理の添付ファイル保存・バックアップは、アプリごとに別の ZIP をダウンロードする。数百件の連続ダウンロードがブラウザに止められないかを確認する。
- フィールド追加・JS/CSS 設定の複数反映先: 1 件ずつ直列に書き込む。数百件での所要時間と、kintone の API 利用上限（1 日あたりのリクエスト数）への影響を確認する。
- ゲストスペースのアプリは `/k/v1/apps.json` に含まれないため、ゲストスペースIDごとの取得が必要。ゲストスペースの一覧を取得する API は無いため、利用者に入力してもらう方式のままとする。

## T5. 実ブラウザ検証で見つかった改善候補（2026-10-27、対応済み）

配布 bundle を模擬 kintone 画面に読み込み、全 11 ツールの全フロー（約 1,000 チェック）を検証して見つかった改善候補は、次のとおり対応した。

- プレビュー反映: レイアウトの組み替えを削除に数えない（本当に無くなる要素は「フィールド 3 個の行」などで示す）。高さ 560px 以下の画面で最終確認の本文を広げた。失敗表示から `[API] …` の内部情報を外した（実行ログには残す）。中止で途中停止した項目は「途中で停止」に統一した。差分取得のエラーに「反映元 #N / 反映先 #N」を付けた。外部更新の検出は内容が変わった項目だけを名前で示す。取得失敗があるときは警告色で示す。
- 差分比較: 比較条件以外の JSON は「比較条件のJSONではありません」と示す。一括 ZIP のファイル名に両側のアプリ ID を付けた。フォルダ読込はファイルの合間で中止できる。1対多の比較先一覧にスクロールの案内を出す。
- レコード管理: 完了メッセージにレコード件数を出す。一部成功は警告色にした。書き込みの応答待ちで中止したときの案内を出す。確認で全アプリ「いいえ」なら確認画面に戻る。
- 設計書: 取得失敗の項目名を日本語にした。ER 図: 起点アプリを取得できないときは保存・表示しない。プロセス図: 中止後に空のカードを出さない。Mermaid 読込失敗時は URL をログにだけ出す。
- 共通: 対象アプリ表の「×」のはみ出しを解消した。

残り:

- 差分比較で単体の設定 JSON を読み込む処理は、1 ファイルの読み込みの途中では止められない（読込後に中止が要求されていれば内容を採用しない）。
- プレビュー反映の最終確認は、320×420 程度の画面では書き込み先ブロックの下半分にスクロールが必要。
- レコード管理の書き込みリクエストが無応答のときは、設計上その場で中止できない（10 秒後に案内を表示する）。案内の表示は単体テストで確認しており、実ブラウザでは未確認。
