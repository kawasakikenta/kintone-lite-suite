# プレビュー反映

`tools/プレビュー反映.js` は、アプリまたは設定JSONを反映元にして、指定アプリのプレビュー設定を更新します。本番公開はアプリ設定画面で行います。画面では「反映元」（設定を読み取るアプリ）と「反映先」（プレビューへ書き込むアプリ）と呼びます。

## 操作の流れ

1. **対象を選ぶ**
   - 反映元・反映先のIDを指定します。アプリのURL（`/k/123/`、`/k/guest/5/123/`、`?app=123`）を貼り付けると、アプリIDとゲストスペースIDを読み取ります（通常スペースのURLではゲストスペースIDを空にします）。
   - IDを入力すると、その場でアプリ名を確認して欄の下に表示します（「✓ 営業テンプレート」「· 開いているアプリ」）。確認できない場合は、IDやゲストスペース、閲覧権限の確認を促します。
   - 「現在のアプリ」を選ぶと、開いている画面のゲストスペースも設定します。反映元の取得環境は「本番設定」「プレビュー設定」から選びます。
   - 反映する項目は3つのグループ（フォーム・表示／動作・カスタマイズ／権限・通知）から選びます。各項目の動作は、チップのツールチップと「各項目の反映方法」で確認できます。反映元の内容で置き換える項目（権限・通知・プロセス管理）には「置換」の目印が付きます。
   - レイアウト・一覧・グラフ・アクション・一般設定を選び、フィールド設定を選んでいない場合は、参照するフィールドが反映先に無いと停止することを注意表示します。
   - 初期選択はフィールド・レイアウト・一覧の3項目です。「差分を確認する」へ進めない場合は、画面下部に「次に進むには：…」として不足している入力を表示します。
2. **差分を確認**
   - APIで確認したアプリ名・ID・ゲストスペース・取得環境を表示します。先頭の要約表で、全項目の状態（差分あり／一致／確認が必要）、変更・削除・保持の件数、反映方法を一覧できます。項目名を押すと詳細へ移動します。
   - 各項目では「変更の要約」に、フィールドは「表示名（コード）」、一覧・グラフ・アクションは設定名、レイアウトは「3行目の2番目」などの位置で、削除・変更・追加・保持を示します（例「表示名: 取引先 → 顧客名」「必須: いいえ → はい」）。設定値そのものは「設定値の内訳」を開くと、反映先の現在と反映後を比較できます。
   - 反映先プレビューに以前からの未公開の変更があるかを確認して表示します（下記「未公開の変更と取り消し」）。
   - 参照するフィールドが反映先に無いために止まった場合、反映元にそのフィールドがあれば「フィールド設定も反映対象に含めて再取得」で、フィールド設定を加えて差分を取り直せます。
   - 不要な項目はチェックから外せます。
3. **最終確認**
   - 書き込み先と、反映する項目ごとの変更の要約を確認してチェックを入れます。削除される設定と、反映先へアップロードするJS/CSSファイルは別枠で示します。
   - 削除・置換、権限・通知・プロセス変更、同じアプリの本番からプレビューへの反映、反映先プレビューに以前からの未公開の変更がある場合は、反映先IDも入力します。ID入力中のEnterでは実行されません。
4. **反映結果**
   - 実行中は、項目ごとに「待機中・実行中…・成功・失敗・変更なし・未実行」を更新しながら表示します。
   - 完了後は項目ごとの結果と、失敗時の対処ヒントを表示します。「反映後の差分を再確認」で、反映した項目を同じ条件で再取得し、反映先が反映元と一致したか（差分が残っていないか）を確認できます。書き込みは行いません。
   - 利用者が「中止」して項目の途中で止まったときは、その項目を「失敗」ではなく「途中で停止」（書き込み済みの分は反映先に残る）、手を付けなかった項目を「未実行」と、カード・一覧・概要・記録で同じ言葉で示し、失敗の件数には数えません。失敗の理由は利用者向けの1行目から示し、内部の通信情報（`[API] PUT …`）は実行ログにだけ残します。
   - 失敗した場合は「失敗・未実行だけ選択」から対象を選び、差分を再取得してから再実行できます。項目の途中（フィールド追加の後の更新など）で止まったときは、書き込み済みの操作を失敗理由と一緒に表示します。
   - 取り消し方の案内と「バックアップから戻す（差分を確認）」を表示します（下記）。
   - 直近の結果は、反映先や反映元を変えている間は表示を外し（「直近の反映結果は現在の対象と異なるため表示していません」）、対象を戻すと再び表示します。書き込み前の検査で止まった場合は、直前の結果とバックアップの参照を残したまま差分確認へ戻ります。

高さ560px以下の低い画面では、見出し・案内・ステップ・固定フッターを詰めて、最終確認の書き込み先と変更内容に高さを回します。差分取得で取得できなかった項目があるときは、完了メッセージを警告色にして件数を示し、最終確認へ進むと「反映先と変更内容を確認してください」の案内に切り替えます。差分取得のエラーには、どちらのアプリかを「反映元 #N」「反映先 #N」で先頭に示します。

一覧検索にはフィールドコードや変更前後の値も使えます。画面の長文は省略表示し、要約は20件、内訳は50件ずつ追加表示します。

### 記録と共有

- **反映計画JSONを保存**：選択範囲の変更内訳と送信予定の設定を全件収録します（技術的な確認用）。
- **計画・記録のMarkdown**：差分確認画面では反映計画を、反映結果画面では実行結果を含む反映記録を、人が読めるMarkdownで保存・コピーできます。経路、概要表、項目ごとの変更の要約、注意、未公開の変更、実行結果を収録し、設定値の生JSONは含めません。承認依頼や作業記録に使えます。
- **実行結果JSONを保存**：実行時の対象、項目ごとの結果、ログ、未公開の変更の確認結果を監査用に保存します。

### 複数のアプリへ順番に反映する

対象選択画面の「詳細設定…」にある「続けて反映する反映先（複数アプリへ展開）」に、ほかの反映先をIDまたはアプリのURLで入力します（改行・カンマ・空白区切り。数字だけのIDは通常スペースのアプリ、ゲストスペースのアプリはURLで指定。最大1000件）。1件の反映が終わると、結果画面に「次の反映先 #203 の差分を確認」が表示され、反映元・項目・保持設定・参照先変換をそのままに、次の反映先の差分確認へ進めます。反映先ごとに差分確認と最終確認を行い、自動で書き込むことはありません。これまでの反映先と結果も一覧で確認できます（同じ反映先に再実行した場合は最新の結果に置き換えます）。参照先変換はすべての反映先に同じように使うため、反映先ごとに変換先が違う場合は、切り替えた後に参照先変換を直してください。項目が未選択の場合などは、次の反映先へ切り替えずに理由を表示します。

環境内の全アプリへ展開するときは、対象選択画面の「アプリを検索」で「環境内の全アプリ」を押し、「候補 N 件を続けて反映する反映先に追加」を使います（各候補行の「続けて反映へ」で1件ずつ追加することもできます）。入力済みの反映先と重複するもの、反映元にしているアプリ（同じアプリIDとゲストスペースID）は加えず、加えなかった件数と合計をステータスに表示します。ゲストスペースのアプリはゲストスペースIDを入れて取得し、`/k/guest/5/204/` の形で入ります。追加しただけでは書き込まず、反映先ごとの差分確認と最終確認は従来どおり必要です。1000件を超える場合は入力欄を変えずに警告を出すので、いくつかに分けて実行してください。これまでの反映先の記録は1001件まで残し、超えて古い記録を省いたときはその件数を表示します。

### 詳細設定とプリセット

- **参照先変換（ルックアップ・関連レコード一覧・アクションのコピー先）**：1行に「旧AppID → 新AppID」（区切りは `→` / `->` / `=` / `:` / カンマ / 空白）で入力します。従来の `{"旧AppID":"新AppID"}` 形式のJSONも使えます。入力欄の下に件数、または読み取れない行を表示します。ルックアップ（`lookup.relatedApp.app`）と関連レコード一覧（`referenceTable.relatedApp.app`）が変換対象で、変換した場合はアプリコード（`code`）指定を自動的に外します。変換先が反映先の現在の参照先と同じなら、反映先の設定をそのまま使い差分にしません。反映元の定義にルックアップ（関連レコード一覧）が無く反映先にある場合は外さず、注意として表示します。変換先の存在確認は、フィールド設定またはアクション設定を書き込むときに行います。
- **プリセット**：接続先・反映項目・参照先変換・保持設定・続けて反映する反映先に名前を付けて保存します。ブラウザには永続保存しないため、次回も使う場合は「JSONで書き出し」で保存し、「JSONを読み込み」で復元します。同名のプリセットは読み込んだ内容で置き換えます（最大30件。超えた分は保持されず、件数を表示します）。

## 何を保持し、何を置き換えるか

| 項目 | 反映する内容 |
| --- | --- |
| フィールド | 不足分を追加し、変更のある定義だけ更新。反映先だけのフィールド・テーブル内フィールドは保持。種類の変更、コードの改名、テーブル間の移動は事前に停止 |
| レイアウト | 反映元の配置を適用。反映先だけのフィールド配置はフォーム・グループ・テーブルの末尾に保持。装飾要素を含む配置の置換は内訳に表示 |
| 一般設定 | テーマ、レコードのタイトル、サムネイル表示、一括削除、コメント機能、レコードの再利用、一覧でのインライン編集、数値の桁数と丸め、年度の開始月を反映元に合わせる。アプリ名・説明・アイコンはアプリ固有の情報のため変更しない。レコードのタイトルに使うフィールドが反映先に無い場合は停止 |
| 一覧・グラフ・アクション | 標準では反映先だけの名前を持つ設定を保持し、表示順を反映元の後へ配置。「保持する」をOFFにした場合は反映元にない設定を削除。フィールドの保持はOFFにならない |
| プラグイン | まだ追加されていないIDだけ追加。反映先のプラグインは削除しない。プラグイン固有の設定値はコピーしない |
| JS/CSS | 適用範囲とPC・モバイルの一覧を反映元の内容に置き換える（反映先だけのファイル・URLは外れる）。FILEは、反映先プレビューの同じ枠（PC/モバイル × JS/CSS）ですでに使われているキーならそのまま使用。別アプリのFILEは本体を取得して内容で比較し、同じ枠に同名・同内容のファイルがあれば再利用、無ければ反映時に反映先へアップロードして新しいキーで設定（アップロードしたキーは1回しか使えないため、同じファイルをPCとモバイルで使う場合は枠ごとにアップロード。取得したキーを書き込みに流用しない）。反映先ファイルの本体を取得できず再利用できない場合は注意を表示。要約と内訳はファイル名で表示し、内容が同じなら変更なし |
| 権限・通知・プロセス・カテゴリー | 選択した設定を置換。通知先やルール、状態、カテゴリーなどの削除・変更を確認画面に表示。カテゴリーの有効状態、コメント通知、リマインダーのタイムゾーンも対象 |

「変更件数」は設定値・配列要素の差分件数です。レコードの削除件数ではありません。配列要素の入れ替えは削除と追加で示すことがあります。ただしレイアウトの行・グループの組み替えは、フィールドが反映後の配置に残る限り削除に数えず（最終確認で反映先IDの入力も求めません）、本当に無くなる要素だけを「フィールド 3 個の行（…）」「グループ「…」」のような言葉で示します。

## 実行前の検査とバックアップ

取得に失敗した項目は自動除外せず、選択されたままなら最終確認へ進めません。取得し直すか、利用者が対象から外します。一覧・グラフ・アクション・レイアウト・一般設定・フィールド権限・リマインダー通知・プロセス管理（作業者）が参照するフィールドの不足、設定形式の不足、revision欠落も検出します。参照先がレコード番号やステータスなどのシステムフィールドで、反映先に同じコードが無い場合は、フィールド設定の追加では解決しない旨を案内します。ルックアップ変換先が確認できない場合は書き込みを始めません。JS/CSSファイルの本体を反映元から取得できない場合も停止します。

実行直前に反映元と反映先を再取得し、確認時の内容・revisionと照合します。条件変更、外部更新、取得途中のrevision不一致があれば中断します。revisionはアプリ単位のため、選択した項目の内容が同じで別の設定だけが更新されたときは、項目名を挙げず「反映先アプリの設定が確認後に更新されました（revision N → M）」と示します。項目名は内容が実際に変わったものだけを挙げます。反映中は更新応答のrevisionを次の書き込みへ引き継ぎ、エラー時には残りの処理を止めます。JS/CSSのアップロードは、最初の書き込みより前にまとめて行い、1つでも失敗した場合は何も書き込みません（使われなかった一時ファイルは残るだけで、設定には影響しません）。

最初の書き込み前に、再取得して照合した反映先設定のJSONバックアップのダウンロードを開始します。ブラウザが端末への保存を完了したことまでは検証できません。

- JS/CSSを書き換える場合は、反映先のファイル本体もJSONに埋め込みます。書き込みで外れる（差し替わる）ファイルの本体を保存できない場合は、元に戻せなくなるため書き込みを始めません。JS/CSSの本文にはAPIトークンなどが含まれる場合があるため、バックアップJSONの保管と共有に注意してください。
- プラグイン固有設定は含みません。
- 複数APIへの更新は一括取消できず、追加したフィールドはバックアップJSONの再反映では削除されません。

確認画面から戻った場合や条件・対象を変更した場合は、最終確認のチェックとID入力を解除します。反映後も比較結果を使い回さず、再取得を要求します。

## 未公開の変更と取り消し

反映はプレビューへの書き込みなので、反映先プレビューに以前からの未公開の変更があると、後で公開したときにそれも一緒に本番へ反映されます。差分確認では、反映先の本番とプレビューのrevisionを比べ、異なる場合は選択した項目の内容も比べて、次のように表示します（書き込みは行わず、反映も止めません）。

| 表示 | 意味 |
| --- | --- |
| 未公開の変更なし | 本番とプレビューのrevisionが一致 |
| 未公開の変更はこのツールの反映分だけ | 直前にこの画面から同じ反映先へ反映し、その後プレビューが変わっていない（反映前は未公開の変更なし）。反映先IDの入力は求めない |
| 以前からの未公開の変更あり | revisionが異なる。内容が異なる項目があれば項目名も表示（JS/CSSのファイルは名前とサイズだけで比較）。最終確認で反映先IDの入力を求める |
| 確認できない | 取得失敗、取得中の更新などで判定できない |

反映結果画面の取り消し方の案内は、この結果で変わります。

- **未公開の変更が無かった場合（または、このツールの反映分だけだった場合）**：アプリの設定画面で「変更を中止」を押すと、今回の反映（と、このツールの直前の反映）をすべて取り消せます。「反映先の設定画面を開く」から移動できます。
- **未公開の変更があった場合**：「変更を中止」ではそれらも破棄されます。今回の反映だけを戻す場合は「バックアップから戻す」を使います。
- **バックアップから戻す（差分を確認）**：反映前のバックアップを反映元（設定JSON）にし、直前に反映した項目を選び、「保持する」をOFF（反映で追加された一覧・グラフ・アクションを外すため）、参照先変換を空（バックアップの値を二重に変換しないため）にして、差分確認へ進みます。内容を確認してから通常どおり反映します。JS/CSSは埋め込んだファイル本体から戻します。追加したフィールドは削除されません。復元中に反映元・反映先を変える、保持をONにする、参照先変換を入れる、バックアップに無い項目を加えると復元をやめ、復元用に取得した差分は使えなくなります。このとき、復元で自動設定した値のうち変更していないもの（保持・参照先変換・項目・反映元）を復元前の値に戻します。復元中は「フィールド設定も反映対象に含めて再取得」は使えません。復元中に画面を閉じて開き直した場合は、復元前の入力で通常の状態として開きます。

## 公式APIに基づく実装

- 一覧の省略項目は削除されるため、保持モードでは反映先の項目を送信設定に含めます。[一覧の設定を変更する](https://cybozu.dev/ja/kintone/docs/rest-api/apps/view/update-views/)
- アクションでも、送信しない名前の設定は削除されます。[アクション設定を変更する](https://cybozu.dev/ja/kintone/docs/rest-api/apps/settings/update-action-settings/)
- フィールドは追加と更新のAPIを分け、レイアウトには既存フィールドの配置を残します。[フィールド追加](https://cybozu.dev/ja/kintone/docs/rest-api/apps/form/add-form-fields/)、[フィールド更新](https://cybozu.dev/ja/kintone/docs/rest-api/apps/form/update-form-fields/)、[レイアウト更新](https://cybozu.dev/ja/kintone/docs/rest-api/apps/form/update-form-layout/)
- 一般設定は、反映元にある項目だけを送ります（アプリ名・説明・アイコンは送らない）。[アプリの一般設定を変更する](https://cybozu.dev/ja/kintone/docs/rest-api/apps/settings/update-general-settings/)
- プラグイン追加はPOSTと`ids`を使用します。[アプリにプラグインを追加する](https://cybozu.dev/ja/kintone/docs/rest-api/apps/settings/add-app-plugins/)
- JS/CSSの適用範囲と、同じプレビュー設定で使用中のFILEキーの扱いに従います。別アプリのファイルは、ファイルをダウンロードしてアップロードし直し、新しいfileKeyを使います。[カスタマイズ設定を変更する](https://cybozu.dev/ja/kintone/docs/rest-api/apps/settings/update-customization/)、[ファイルをアップロードする](https://cybozu.dev/ja/kintone/docs/rest-api/files/upload-file/)、[ファイルをダウンロードする](https://cybozu.dev/ja/kintone/docs/rest-api/files/download-file/)
- 通知の`notifyToCommenter`とカテゴリーの`enabled`を引き継ぎます。[一般通知](https://cybozu.dev/ja/kintone/docs/rest-api/apps/settings/update-general-notification-settings/)、[カテゴリー](https://cybozu.dev/ja/kintone/docs/api-lab/rest-api/apps/update-categories/)

書き込みは原則プレビューAPIだけに限定しています。例外として、別アプリのJS/CSSを渡すための一時ファイルのアップロード（通常のAPIの `POST /file.json`。アプリ設定やレコードは変更しない）だけを許可しています。
