# 次にやる作業（kintone-lite-suite）

更新: 2026-09-06。前提と検証方法は `CLAUDE.md` を先に確認してください。

## T1. Playwright 比較ハーネスの CI 分離（実装済み）

- 通常 PR と main 更新で複数比較先・ペア・フォルダペア・プレビュー反映・lite 操作の DOM ハーネスを実行する。
- 重い `test:diff-compare` と `test:er-compare` は対応する UI／出力ソース・生成物・共通依存・ハーネスの変更時、または `workflow_dispatch` で実行する。
- PR は比較元ブランチの SHA、main 更新は push 前の SHA を比較基準にする。詳細は `tools/test-harness/README.md` を参照。
- 比較 HTML、JSON、PNG などは 7 日間の Actions artifact とし、Git へ追加しない。

## T2. ER 図の外部依存固定

生成 HTML が実行時 CDN 応答へ依存しないよう、Cytoscape、Dagre などを固定版で同梱する。難しい場合は SRI と厳格な CSP を適用し、供給網リスクを明示する。

## T3. Excel 差分出力の安全共有

共有用マスキング、暗号学的な内容識別子、出力サイズ上限、レビュー結果の再取込を段階的に追加する。人向けレビュー表と技術明細の役割分離は維持する。

## T4. プレビュー反映の実環境確認

2026-10 の改善（一般設定、別アプリの JS/CSS 転送、未公開の変更の確認、バックアップから戻す、複数アプリへの順次反映）は、合成 API と画面ハーネスでのみ検証している。検証用アプリで次を確認する。

- 公開直後に、本番とプレビューの revision が一致するか。「変更を中止」した後の revision の扱い（未公開の変更の判定に使う）。
- 一般設定の PUT（タイトルを自動・手動にする、数値の桁数と丸め、年度の開始月）が受け付けられるか。
- ゲストスペースを含む JS/CSS ファイルのダウンロード・アップロード（`POST /file.json` と `__REQUEST_TOKEN__`）と、新しい fileKey での customize PUT。
- バックアップJSON（ファイル本体を埋め込み）を反映元にした復元で、JS/CSS と一覧が反映前に戻るか。
- 書き込みの再試行（5xx・通信失敗）で同じ revision を再送したとき、初回がサーバー側で確定していた場合に GAIA_CO02（競合）になるか。なる場合は「直前の書き込みが成功していた可能性」を案内に加える。
- 同名の一覧の種類（表形式→カレンダー形式など）を変える PUT と、フィールド権限・リマインダー通知・プロセス管理の作業者が存在しないフィールドを参照する PUT が受け付けられるか（受け付けられなければ事前検査が必要）。

## T5. アプリ名確認の実環境確認

2026-10-22 の入力中のアプリ名確認（`/app.json` の `appId` `name` `code` を表示）は、合成 API と画面ハーネスでのみ検証している。検証用アプリで次を確認する。

- 閲覧権限のないアプリで、「アプリを確認できません…」の警告が出ても操作を止めず、各処理の取得時に実際の権限エラーが表示されるか。
- ゲストスペースのアプリで、`/k/guest/{id}/v1/app.json` の問い合わせが成功し、通常スペースの同じ番号のアプリと取り違えないか。
- 対象アプリ表に大量の行を貼り付けたとき、同時 3 件の問い合わせで各行の「確認中…」から結果表示へ切り替わり、API 制限に当たらず、入力変更後に古い結果が残らないか。
