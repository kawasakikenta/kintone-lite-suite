# kintone-lite-suite

kintone の設定比較、プレビュー反映、設計書・ER図出力、レコード運用を、用途ごとの単機能 JavaScript として提供するリポジトリです。

## 収録ツール

`tools/` 直下の次のファイルが配布用 bundle です。

- `差分比較.js`
- `プレビュー反映.js`
- `本番反映.js`
- `フィールド追加.js`
- `kintoneJS取得.js`
- `設定取得.js`
- `設計書作成.js`
- `ER図.js`
- `プロセス実行.js`
- `kintoneレコード取得.js`
- `CSV出力.js`
- `データ品質チェック.js`

正規ソースは `tools/統合ツール/src/` にあります。配布用 bundle と `tools/単機能スクリプト棚卸し.md` はビルド生成物なので、直接編集しないでください。

## セットアップと検証

Node.js 20 以上、npm 10 以上を使用します。

```bash
npm ci
npm run setup
npm run check
```

`npm run check` はブラウザストレージ検査、通常・strict 型検査、Vitest、ビルドを実行します。ビルド後に Git 差分が残る場合は生成物の更新漏れです。

Playwright の比較・出力ハーネスは `tools/test-harness/README.md` を参照してください。

全12ツールの型検査・単体テスト・ビルド・画面／出力検証は `npm run test:all` でまとめて実行できます（Chrome が必要）。

設計書は人向けのExcelとAI向けの専用Markdownを選べます。Excelは項目一覧から詳細へ移動でき、取得状況と集計ルールを明示します。AI向けMarkdownはメタデータ・全セクションの取得状態・項目と参照の索引・JSON原文を収録します。通常のMarkdownも引き続き使えます。設計書差分レポートは比較方向とセクション別の追加・削除件数を先頭にまとめます。設定取得の ZIP と JS/CSS 一括取得の ZIP には、アプリごとのファイル対応と失敗内容を記録した manifest.json が入ります。設定取得の「設定とJS/CSSファイルをZIPで保存」では JS/CSS ファイルの本体も同じ ZIP に入れられ、フォルダの分け方（PC/モバイル・JS/CSS別／分けない）と、ファイル名の先頭に読み込み順を付けるか（既定は付けない）を「詳細設定…」で選べます。

各ツールのパネルは見出しをドラッグして移動でき、「－」で見出しだけに折りたたんで kintone 画面を確認できます。 Escキーは操作中のパネルだけを閉じ、日本語変換の取消やkintone側の操作を妨げません。実行中は経過時間と進捗ストリップを表示し、「中止」で次のリクエストの前に処理を止められます（送信済みの書き込みは待ってから止め、処理済み・未実行の件数を表示します）。読み取りの応答待ちには上限があり、通信が止まったまま処理中が続くことはありません。完了後は所要時間を「前回」として残します。結果ログは「コピー」でクリップボードへ写すか、「保存」でテキストファイルに残せます。パネルを開いたまま再起動したときは位置を引き継ぎます。文字は本文 14px を基準に補足文も 12.5px 以上とし、手順ナビは現在・済み・これからの段階を色で区別します。1 画面目には対象アプリと主要な操作だけを出し、ふだん変えない設定は「詳細設定…」、4 つ目以降の操作は「ほかの操作…」のポップアップ、補足説明はカードの「?」から開きます。詳細は [liteツール群の機能説明](tools/統合ツール_機能説明.md) の「パネルの共通操作」を参照してください。

アプリ名検索は100件ずつ追加取得でき、アプリURLからゲストスペースも判別します。複数アプリのIDはカンマ・空白区切りで貼り付けられ、選択中の文字列を置き換えます。設定取得で一部が失敗した場合は、保存後も失敗件数と再取得の案内を表示します。

全12ツールで環境内の全アプリを対象にできます。「アプリを検索」の「環境内の全アプリ」で閲覧できるアプリを最後のページまで候補に表示し、「候補 N 件をすべて追加」などで対象アプリ表・比較先・起点・続けて反映する反映先へまとめて入れます（ゲストスペースのアプリはゲストスペースIDごとに取得）。フィールド追加と JS/CSS 設定には複数の反映先プレビューへの反映、プロセス図には複数アプリの ZIP 保存を追加しました。JS/CSS 設定は、アップロード済みファイル（FILE 形式）を含む設定も別のアプリへ反映できます（取得元から本体を取得し、反映先に同名・同内容のファイルがあれば再利用、無ければ書き込みの直前にアップロードします）。フィールド追加は、選んだフィールドが参照するフィールドが反映後のフォームに無いとき、最終確認に足りないコードを示します。書き込みを伴う複数アプリの処理は、全対象を事前確認してから最終確認を 1 回行い、revision 競合は上書きせず、中止した残りは「未実行（中止）」として示します。確認画面の対象一覧は先頭 20 件と件数でまとめます。

差分比較の 1対1比較には「本番とプレビューを比較（未公開の変更を確認）」があり、同じアプリの本番を比較元、プレビューを比較先に設定できます。一覧・グラフ・ステータスなどの途中に 1 件追加しただけで後続の表示順がすべて差分になる、といったノイズを出さないようにしています。判定規則は [差分比較ロジック説明](docs/diff-comparison-logic.md) を参照してください。

ER 図は、描画ライブラリを同梱しているため、保存した HTML を含めて外部 CDN へ通信せずに表示できます。関連アプリの探索は数アプリずつ並行して読み取ります。線（関連）を選ぶと、ルックアップのコピー項目や関連レコード一覧の条件を確認できます。

ZIP の保存（設定取得・JS/CSS・設計書・レコード管理・データ検査・プロセス図）と設計書 Excel も、外部 CDN からスクリプトを読み込みません。プロセス図の描画ライブラリ（Mermaid）だけは固定版を CDN から読み込み、内容を検証できたときだけ実行します（読み込めない場合は状態と遷移の表で表示します）。レコード管理の添付ファイル保存・バックアップは、ZIP の上限（4GB 未満・65,535 件）を超える前に複数の ZIP に分けて保存します。

検索方法を「アプリコード」に切り替えると完全一致で検索でき、名前・コード検索はスペースIDでも絞れます。候補にはコード・所属スペース・更新日時・更新者を表示します。レコード管理では、一覧の絞り込みと並び順をクエリに反映し、添付フィールドを名前から選択できます。テーブル内の添付にも対応しています。詳しい使い方と根拠となる公式APIは [APIレスポンスを利用する補助機能](docs/api-response-improvements.md) を参照してください。

プレビュー反映では、入力中にアプリ名を確認し、差分を項目単位の「変更の要約」（例「表示名: 取引先 → 顧客名」）で示します。一般設定（テーマ・レコードのタイトルなど）と、別アプリのJS/CSSファイル（反映先へアップロードして設定）も反映できます。反映先プレビューの未公開の変更を事前に知らせ、反映後は「変更を中止」やバックアップからの復元で取り消せます。計画・記録はMarkdownで保存でき、同じ設定を複数のアプリへ順番に反映できます。複数の反映先を指定したときは「全反映先の事前確認」で、どの反映先に差分があるか・取得に失敗するかを、書き込まずに一覧で確認できます。反映元と反映先でルックアップなどの参照先アプリが食い違うときは、反映先の現在の設定を根拠に参照先変換の候補を示します。詳しくは [プレビュー反映](docs/preview-reflection.md) を参照してください。

本番反映は、プレビューの未公開の変更を本番へ公開（kintone の「アプリを更新」）、または破棄（「変更を中止」）するツールです。本番とプレビューの差分をアプリごとに確認し、削除されるフィールド（レコードの値も削除され、元に戻せません）を警告し、反映前の本番設定をバックアップJSONに保存してから実行します。複数アプリ（環境内の全アプリを含む）に対応し、1アプリずつ、またはまとめて反映できます。取得失敗や反映処理中のアプリを選んだままでは先へ進めません。別のアプリ（開発・検証用）の設定を本番へ反映するときは、パネル上部の「反映元アプリから本番へ」で、差分を設定値 1 つずつ選び（例：「必須」だけ反映し、表示名は反映しない）、主な値は入力欄・残りはJSONで直してから、反映先のプレビューへ書き込み、続けて本番へ反映します。どちらの結果画面にも「バックアップから戻す」があり、保存したバックアップを反映元に、差分を確認して反映前の状態へ戻せます（本番反映の中で完結します）。「反映元アプリから本番へ」で選んだ変更と修正は JSON で保存・読み込みでき（承認待ちの間や別の担当者への受け渡しに使えます。読み込んでも最終確認は必ず通ります）、反映後は「反映後の内容を確認する」で、選んだ変更が意図した値で入ったかを読み取りだけで確かめられます。削除されるフィールドがあるアプリには、レコード数も示します。

CSV取込には、全対象アプリのフィールド設定に照らした事前検査と先頭行のプレビューがあります。実行時にも全対象を再検査してから追加します。ステータス更新では、同名アクションを遷移元ごとに選択し、実行条件・次の作業者・実行者の設定を確認して対象クエリを入力できます。

「重複・未入力を検査」では、名前から1〜5項目を選び、組み合わせの重複と未入力を調べられます。該当レコードへのリンクと全結果CSVを出力します。「CSV取込ひな形を作成」では、取込可能な列と必須・選択肢などの入力ガイドをアプリごとのZIPフォルダに保存します。各フォルダの README.txt に対象アプリ・生成日時・列数と、使い方・同梱ファイル・注意点を記載しています。使い方は [データ検査とCSVひな形](docs/record-quality-and-template.md) を参照してください。

```bash
npm run test:output-layouts
npm run test:deploy-dom
npm run test:diff-multi-dom
npm run test:diff-compare
npm run test:er-compare
```

## 安全上の注意

反映・追加・更新を行うツールは kintone の設定やデータを変更します。対象環境、App ID、処理方向を確認し、必要なバックアップを取得してから実行してください。

独立した Excel、FreeBoard、スケジュール、データ加工ツールは、それぞれ別リポジトリで管理します。
