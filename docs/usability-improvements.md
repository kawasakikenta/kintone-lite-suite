# LiteSuite 全11ツールの使い勝手改善

2026-10-22。既存の操作と配布形式を維持し、入力ミスに早く気づき、長い結果を読みやすくし、途中で失敗しても復帰しやすくする改善です。

## 目的

- 入力ミスへの早期の気づき: アプリIDやゲストスペースIDの入力中に対象のアプリ名を示し、確認画面へ進む前に取り違えに気づけるようにする。
- 長い結果の読みやすさ: パネルを画面いっぱいに広げて結果を読めるようにし、実行にかかった時間を案内に残す。
- 途中失敗からの復帰: 対象アプリ表を空に戻す操作と、設定取得で失敗したアプリだけを対象に残して再実行する導線を設ける。

## ツール別の改善内容

共通の改善は次の「全ツール共通」にまとめ、表にはツール固有の点だけを書きます。

| ツール | 改善内容 |
| --- | --- |
| 差分比較 | 比較元・比較先（1対1・1対多）のアプリID・ゲストID欄でアプリ名を確認する。ペア一括比較は対象外 |
| プレビュー反映 | 入力中のアプリ名確認と反映の流れは従来どおり |
| フィールド追加 | 比較元・比較先のアプリID・ゲストID欄でアプリ名を確認する |
| JS/CSS設定 | 取得元・反映先のアプリID・ゲストID欄でアプリ名を確認する |
| 設計書作成 | 対象アプリ表の行ごとに「確認中…」「アプリ名: X」「アプリを確認できません（…）」を表示する |
| 設定取得 | 対象アプリ表の行ごとにアプリ名を確認する。一部のアプリの取得に失敗したあと、結果画面の「失敗したアプリだけを対象に残す」で表を失敗したアプリだけにして対象画面へ戻り、取得セクションを確認して再実行できる |
| ER図 | 起点のアプリID欄に複数のIDを入れたとき、先頭10件を「#101 顧客管理 / #102 案件」のように並べる |
| プロセス実行 | アプリID・ゲストID欄でアプリ名を確認する |
| kintoneレコード取得 | 複数のIDを入れる欄で、先頭10件のアプリ名を並べる |
| CSV出力 | 対象アプリ表の行ごとにアプリ名の確認結果を表示する |
| データ品質チェック | 複数のIDを入れる欄で、先頭10件のアプリ名を並べる |

## 全ツール共通

- 拡大表示: 見出し右の「⤢」でパネルを画面いっぱいに広げ、もう一度押す（⤡）と元の大きさへ戻す。拡大中はドラッグ移動しない。折りたたみ中は幅を変えない。実行中でも拡大・折りたたみは使える。
- 入力中のアプリ名確認: アプリID・ゲストスペースIDの入力が止まる（350ms）と、本番側の `/app.json` でアプリ名を確認し、欄の下に「✓ 顧客管理（コード: customer）」と表示する。入力途中の値は問い合わせず、同じ接続先はパネル内で1回だけ問い合わせる。開いているアプリには「開いているアプリ」と添える。
- 確認できない場合: 「アプリを確認できません。ID・ゲストスペース・閲覧権限を確認してください。」を警告色で示すが、操作は止めない。厳密な確認は各処理の取得時に行う。
- 対象アプリ表: アプリ検索や設定JSONから名前付きで追加した行は問い合わせない。「全行を消去」で表を空に戻せる。3件以上あるときは確認ダイアログを出す。
- 確認画面: 要約にもアプリ名を表示する（「#123 顧客管理（ゲスト 5）· 本番」）。確認が後から終わっても、入力が変わっていなければ確認画面をやり直す必要はない。
- 所要時間: 確認画面を経て実行する全ツールで、実行結果の案内に「所要時間: 1分12秒」を表示する。

## 仕様の照合

アプリ名の確認には、[アプリの情報を取得する（Get App）](https://cybozu.dev/ja/kintone/docs/rest-api/apps/get-app/)の応答の `appId`、`name`、`code` を使います。ゲストスペースのアプリは、`/k/guest/{id}/v1/` 配下の同じAPIで問い合わせます。

閲覧権限のないアプリ、ゲストスペースのアプリ、大量の対象行での表示は実環境では確認していません。[次にやる作業](next-tasks.md)の T5 で検証用アプリを使って確認します。
