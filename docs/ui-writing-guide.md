# lite ツール群の文言ガイド

全 11 ツールのパネルに表示する文言（タイトル・副題・ヒント・注記・操作の説明・ステータス）を書くときの基準です。利用者は kintone の管理者で、REST API の内部仕様は知らない前提で書きます。

## 1. 用語を統一する

| 場面 | 使う語 | 使わない語 |
| --- | --- | --- |
| 設定やレコードを読む側 | 反映元（書き込み系）、取得元（読み取り系）、比較元（差分比較だけ） | ソース、src |
| 設定を書き込む側 | 反映先（常にプレビュー） | 比較先（差分比較以外で）、ターゲット |
| レコードを書き込む側 | 対象アプリ（本番） | 反映先（レコード操作では使わない） |
| 本番 / プレビュー | 本番、プレビュー | 運用環境、preview |
| ゲストスペースの番号 | ゲストスペースID | ゲストID（入力欄の短い placeholder だけ可） |
| 設定の取得に失敗した項目 | 取得失敗 | _fetchError、エラー項目 |
| 一括処理で手を付けなかった件 | 未実行 | スキップ（「条件に合わず飛ばした」場合だけ） |
| 利用者が「中止」を押した | 中止 | キャンセル（確認ダイアログで「いいえ」を選んだ場合だけ） |

- 差分比較だけが「比較元 → 比較先」。フィールド追加・JS/CSS 設定・プレビュー反映は「反映元 → 反映先」。
- ボタン名は「何を・どこへ」の順で書く。例: 「反映先プレビューへ反映」「CSVを出力」「ER図をHTMLで保存」。

## 2. 影響範囲を最初に示す

各ツールの見出しのバッジは、次の 3 つのうち 1 つだけを必ず付ける（機能の宣伝は付けない）。

| バッジ | 意味 | 対象ツール |
| --- | --- | --- |
| 読み取り専用 | kintone に何も書き込まない | 差分比較、設定一括取得、設計書、ER 図、プロセス図、CSV出力、データ品質チェック |
| プレビューへ書き込み | 反映先アプリのプレビューだけを変更する。本番への公開は設定画面で行う | プレビュー反映、フィールド追加、JS/CSS 設定 |
| 本番データを変更 | 本番のレコードを追加・更新する。元に戻せない操作を含む | レコード管理（CSV取込・ステータス更新・コピー） |

ヒント（見出し下の 1 行）は「このツールで何ができて、何が起きないか」を 1〜2 文で書く。操作手順や形式の説明はカードの注記へ。

## 3. 注記は「結果 → 理由」の順に、短く

- 1 文目に利用者にとっての結果（何が保存されるか、何が変わるか、何が変わらないか）を書く。技術的な理由は 2 文目以降か括弧内に置くか、省く。
  - 良い例: 「10,000 件を超えても全件取得します（並び順の指定がある場合は cursor API を使います）。」
  - 悪い例: 「limit / offset は指定できません。order by を付けた場合は cursor API、無い場合はレコード ID 順で全件取得します。」
- 1 つの注記は 2 文以内。3 文以上になるときは、注記を分けるか「詳細設定」へ畳む。
- 同じ内容をヒント・注記・操作の説明に重ねて書かない。操作の説明（ラジオカードの 1 行）は「何を・どこへ・どの形式で」だけ。
- 内部識別子（fileKey、revision、PUT、_fetchError、customize.json、scope）は、利用者が入力や判断に使う場合だけ書き、かみ砕いた語を先に置く。例: 「取得後に別の更新が入っていた場合（revision 競合）は上書きせず中止します」。

## 4. 取り消せない操作は、その場で最初に言う

- 本番レコードを変更する操作の注記は、1 文目を「元に戻せません。」や「本番のレコードを直接更新します。」から始める。
- プレビューへの書き込みは「反映先のプレビューだけを変更します。本番への公開は kintone の設定画面で行います。」を各ツールで同じ言い回しにする。
- 取り消し方があるなら、同じ注記の 2 文目で示す（「変更を中止」、バックアップからの復元、など）。

## 5. ステータスと結果の言い回し

- 完了: 「〜を保存しました」「〜を反映しました」のように結果の動詞で終える。「完了」だけにしない。
- 部分成功: 「3 件中 2 件を保存しました。失敗 1 件（App 303: 権限がありません）」のように、成功数・失敗数・失敗理由の順。
- 中止: 「中止しました（2/5 件を処理、残り 3 件は未実行）」。途中まで書き込んだ内容が残ることを 2 文目で伝える。
- 次にすべきことがあるときは、文末に「〜してください」で 1 つだけ示す。

## 6. 検証

文言を変えたら、`tools/test-harness/*.cjs` と `tools/統合ツール/tests/` でその文字列を検索し、同じ文言に更新する。画面ハーネス（`npm run test:lite-workflows` など）で 320〜1440px のはみ出しがないことを確認する。
