# kintone-lite-suite

kintone の設定比較、プレビュー反映、設計書・ER図出力、レコード運用を、用途ごとの単機能 JavaScript として提供するリポジトリです。

## 収録ツール

`tools/` 直下の次のファイルが配布用 bundle です。

- `差分比較.js`
- `プレビュー反映.js`
- `フィールド追加.js`
- `kintoneJS取得.js`
- `設定取得.js`
- `設計書作成.js`
- `ER図.js`
- `プロセス実行.js`
- `kintoneレコード取得.js`
- `CSV出力.js`
- `データ品質チェック.js`

正規ソースは `tools/統合ツール/src/` にあります。配布用 bundle と `tools/単機能スクリプト棚卸し.md` はビルド生成物なので、直接編集しないでください。

## セットアップと検証

Node.js 20 以上、npm 10 以上を使用します。

```bash
npm ci
npm run setup
npm run check
```

`npm run check` はブラウザストレージ検査、通常・strict 型検査、Vitest、ビルドを実行します。ビルド後に Git 差分が残る場合は生成物の更新漏れです。

Playwright の比較・出力ハーネスは `tools/test-harness/README.md` を参照してください。

全11ツールの型検査・単体テスト・ビルド・画面／出力検証は `npm run test:all` でまとめて実行できます（Chrome が必要）。

設計書は人向けのExcelとAI向けの専用Markdownを選べます。Excelは項目一覧から詳細へ移動でき、取得状況と集計ルールを明示します。AI向けMarkdownはメタデータ・全セクションの取得状態・項目と参照の索引・JSON原文を収録します。通常のMarkdownも引き続き使えます。設計書差分レポートは比較方向とセクション別の追加・削除件数を先頭にまとめます。設定取得の ZIP と JS/CSS 一括取得の ZIP には、アプリごとのファイル対応と失敗内容を記録した manifest.json が入ります。

各ツールのパネルは見出しをドラッグして移動でき、「－」で見出しだけに折りたたんで kintone 画面を確認できます。 Escキーは操作中のパネルだけを閉じ、日本語変換の取消やkintone側の操作を妨げません。実行中は経過時間と進捗ストリップを表示し、「中止」で次のリクエストの前に処理を止められます（送信済みの書き込みは待ってから止め、処理済み・未実行の件数を表示します）。読み取りの応答待ちには上限があり、通信が止まったまま処理中が続くことはありません。完了後は所要時間を「前回」として残します。結果ログは「コピー」でクリップボードへ写すか、「保存」でテキストファイルに残せます。パネルを開いたまま再起動したときは位置を引き継ぎます。文字は本文 14px を基準に補足文も 12.5px 以上とし、手順ナビは現在・済み・これからの段階を色で区別します。1 画面目には対象アプリと主要な操作だけを出し、ふだん変えない設定は「詳細設定…」、4 つ目以降の操作は「ほかの操作…」のポップアップ、補足説明はカードの「?」から開きます。詳細は [liteツール群の機能説明](tools/統合ツール_機能説明.md) の「パネルの共通操作」を参照してください。

アプリ名検索は100件ずつ追加取得でき、アプリURLからゲストスペースも判別します。複数アプリのIDはカンマ・空白区切りで貼り付けられ、選択中の文字列を置き換えます。設定取得で一部が失敗した場合は、保存後も失敗件数と再取得の案内を表示します。

全11ツールで環境内の全アプリを対象にできます。「アプリを検索」の「環境内の全アプリ」で閲覧できるアプリを最後のページまで候補に表示し、「候補 N 件をすべて追加」などで対象アプリ表・比較先・起点・続けて反映する反映先へまとめて入れます（ゲストスペースのアプリはゲストスペースIDごとに取得）。フィールド追加と JS/CSS 設定には複数の反映先プレビューへの反映、プロセス図には複数アプリの ZIP 保存を追加しました。書き込みを伴う複数アプリの処理は、全対象を事前確認してから最終確認を 1 回行い、revision 競合は上書きせず、中止した残りは「未実行（中止）」として示します。確認画面の対象一覧は先頭 20 件と件数でまとめます。

検索方法を「アプリコード」に切り替えると完全一致で検索でき、名前・コード検索はスペースIDでも絞れます。候補にはコード・所属スペース・更新日時・更新者を表示します。レコード管理では、一覧の絞り込みと並び順をクエリに反映し、添付フィールドを名前から選択できます。テーブル内の添付にも対応しています。詳しい使い方と根拠となる公式APIは [APIレスポンスを利用する補助機能](docs/api-response-improvements.md) を参照してください。

プレビュー反映では、入力中にアプリ名を確認し、差分を項目単位の「変更の要約」（例「表示名: 取引先 → 顧客名」）で示します。一般設定（テーマ・レコードのタイトルなど）と、別アプリのJS/CSSファイル（反映先へアップロードして設定）も反映できます。反映先プレビューの未公開の変更を事前に知らせ、反映後は「変更を中止」やバックアップからの復元で取り消せます。計画・記録はMarkdownで保存でき、同じ設定を複数のアプリへ順番に反映できます。詳しくは [プレビュー反映](docs/preview-reflection.md) を参照してください。

CSV取込には、全対象アプリのフィールド設定に照らした事前検査と先頭行のプレビューがあります。実行時にも全対象を再検査してから追加します。ステータス更新では、同名アクションを遷移元ごとに選択し、実行条件・次の作業者・実行者の設定を確認して対象クエリを入力できます。

「重複・未入力を検査」では、名前から1〜5項目を選び、組み合わせの重複と未入力を調べられます。該当レコードへのリンクと全結果CSVを出力します。「CSV取込ひな形を作成」では、取込可能な列と必須・選択肢などの入力ガイドをアプリごとのZIPフォルダに保存します。各フォルダの README.txt に対象アプリ・生成日時・列数と、使い方・同梱ファイル・注意点を記載しています。使い方は [データ検査とCSVひな形](docs/record-quality-and-template.md) を参照してください。

```bash
npm run test:output-layouts
npm run test:diff-multi-dom
npm run test:diff-compare
npm run test:er-compare
```

## 安全上の注意

反映・追加・更新を行うツールは kintone の設定やデータを変更します。対象環境、App ID、処理方向を確認し、必要なバックアップを取得してから実行してください。

独立した Excel、FreeBoard、スケジュール、データ加工ツールは、それぞれ別リポジトリで管理します。
