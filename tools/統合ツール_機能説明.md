# kintone lite ツール群 機能説明

対象: `tools/*.js` の単機能liteバンドル

## 概要

このドキュメントは、共通ソースから生成するkintone向けliteツール群の機能仕様をまとめたものです。廃止済みの `tools/統合ツール.js` を読み込むのではなく、目的に応じて `tools/差分比較.js`、`tools/ER図.js` などの単機能バンドルを使用します。以下の「タブ」は機能分類または各liteパネル内の画面を指し、全機能を1つの画面から起動する構成ではありません。

> SQL 実行は共通ビルドに含まれません。別リポジトリ `kintone-data-utilities` の `kintoneSQL.js` を利用してください。

主な用途は以下です。

- 開発環境と本番環境の設定差分を確認する
- 反映元の設定を反映先のプレビューへ反映する
- プレビューの未公開の変更を確認し、バックアップを取ってから本番へ反映（または変更を中止）する
- フィールドや JS/CSS 設定を個別に移送する
- 設計書や差分レポートを出力する
- 複数アプリの設定をまとめて保存する
- アプリ同士の関連（ER図）とプロセス管理の流れ（プロセス図）を図で確かめる
- レコードの出力・取込・ステータス更新・データ検査をまとめて行う

## 外部ライブラリと通信

- ZIP の作成（設定取得・JS/CSS 取得・設計書・レコード管理・データ品質チェック・プロセス図の ZIP 保存）は、ツールに含めた自前の実装で行います。外部から読み込まないため、CDN が遮断された社内ネットワークでも使えます。ファイル名は UTF-8 で、Windows のエクスプローラー、macOS、`unzip`、Python で文字化けしません。ブラウザが対応していれば圧縮し、対応していなければ圧縮なしで保存します。
- ZIP は 1 つあたり 4GB 未満・65,535 件（フォルダを含む）までです。超える場合は壊れた ZIP を作らず、「対象を分けて、もう一度実行してください」とエラーを表示します。
- 設計書の Excel（`設計書作成.js`）も、書き出しに使うライブラリ（xlsx-js-style 1.2.0）を同梱しています。通信しません。
- プロセス図の Mermaid（約 3MB）だけは、固定版（10.6.1）を CDN（jsDelivr、だめなら unpkg）から読み込みます。管理者の kintone の画面で実行されるため、配布物のハッシュ（SRI）が一致しない内容は実行しません。読み込めない・検証できないときは、状態と遷移の表（簡易表示）に切り替えます。

## 基本概念

- 比較元 / 比較先: 差分比較で比べる 2 つのアプリ（比較元が変更前、比較先が変更後）
- 反映元 / 反映先: 設定を書き込むツール（プレビュー反映・本番反映の「反映元アプリから本番へ」・フィールド追加・JS/CSS 設定）で、設定を読み取るアプリと、プレビューへ書き込むアプリ
- 取得元: 読み取り専用のツールで設定を読むアプリ。レコードを扱うツールでは「対象アプリ」と呼びます
- プレビュー: アプリ設定の未デプロイ領域
- バンドル: 各種設定をまとめて取得した JSON データ
- セクション: アプリ設定の比較単位

比較対象セクションは主に以下です。

- アプリ設定
- フィールド設定
- レイアウト設定
- フォーム設定
- ビュー設定
- レポート設定
- プロセス管理
- プラグイン
- JS/CSS 設定
- アクション設定
- アプリ権限
- フィールド権限
- レコード権限
- 通知設定
- レコード条件通知
- リマインダー通知
- カテゴリ設定

## 共通設定

各 lite パネルは、そのツールで使うアプリ（比較元・比較先、反映元・反映先、取得元、対象アプリ）とゲストスペースIDを、パネルの中で指定します。ツールどうしで接続先や作業状態を共有しません（ブラウザストレージも使いません）。

### パネルの共通操作

全 lite パネルは `litePanelTheme.ts` の共通基盤で動作し、次の操作を共有します。

- 見出しのバッジは影響範囲を示します。「読み取り専用」（緑）は kintone に何も書き込まないツール、「プレビューへ書き込み」（橙）は反映先アプリのプレビューだけを変更するツール、「本番データを変更」（赤）は本番のレコードを追加・更新するツール、「本番の設定を変更」（赤）は本番のアプリ設定を公開または破棄する本番反映です。文言の基準は [文言ガイド](../docs/ui-writing-guide.md) にまとめています
- 見出し部分をドラッグしてパネルを移動できます。画面外へは出ず、ウィンドウ幅を変えたときも画面内へ戻します。見出しをダブルクリックすると右上の初期位置へ戻ります。パネルを開いたまま同じツールを再度起動したときは、動かした位置を引き継ぎます（「閉じる」で閉じた後やページの再読み込み後は初期位置に戻ります。ブラウザストレージは使いません）
- 見出し右の「－」で本文を折りたたみ、見出しだけを残して kintone 画面を確認できます。「＋」で展開します
- 実行中は見出し右に経過時間（例: 処理中 1分12秒）と見出し下端の進捗ストリップを表示します。閉じるボタンは完了まで無効です。完了後は「前回 1分12秒」として次の実行まで所要時間を残します
- 実行中は見出し右に「中止」ボタンが出ます。押すと「中止中…」になり、実行中のリクエストが終わり次第、次のリクエストの前で処理を止めます。進行中の読み取り（設定取得・ファイル本文）は打ち切りますが、書き込み（POST / PUT / DELETE）は送信済みのものを最後まで待ってから止めます。途中まで書き込んだ内容は取り消さないため、ステータスに「中止しました」と処理済み・未実行の件数を表示し、結果ログで内訳を確認できます。書き込みを 1 件も送っていなければ「書き込みは行っていません」と表示します。実行中に同じツールをもう一度起動した場合は、見えなくなった旧パネルが書き込みを続けないよう、実行中のパネルをそのまま残して案内を表示します（終わるのを待つか「中止」を押してください）
- 読み取りの応答待ちには上限があります（REST API の GET は 120 秒、JS/CSS 本文は 60 秒、ファイル本体は 120 秒）。超えた場合は通信失敗と同じ扱いで再試行し、それでも応答がなければ失敗として表示します。通信が止まったまま「処理中」が続くことはありません。例外として、並び順（`order by`）を指定したレコードの取得（cursor API）は、送り直すとレコードが抜けるため応答待ちに上限を設けません。止まったときは「中止」を押してください
- 書き込み（プレビューの設定・レコード・アプリの更新）は、応答が届かなかったとき（通信エラー・応答の無い 5xx・応答待ちの超過）に黙って送り直しません。kintone 側では反映されていることがあり、送り直すと二重に登録したり、成功したのに「revision 競合」と表示したりするためです。プレビューの設定（プレビュー反映・フィールド追加・JS/CSS 設定）は、設定を読み直して更新番号（revision）が送ったときのままなら反映されていないので、同じ revision で送り直します（二重には反映されません）。revision が進んでいる・読み取れないときは、成功とも失敗とも言わず「反映されたか分からない」と、kintone で何を確かめればよいかを警告の色で示して止めます。レコードの追加・ステータス更新・本番反映の依頼は送り直さず、「書き込まれたか確認できない」「完了を確認できない」と示します（kintone のエラー応答が無い失敗は、形が分からなくても同じ扱い）
- kintone が入力エラー（`CB_VA01` など）で書き込みを受け付けなかったときは、「入力内容が正しくありません。」だけでなく、受け付けなかった項目ごとに「どこの・何が」を示します。kintone が返すキーは言葉に言い換えます（例: `properties.customer.lookup.relatedApp.app` →「フィールド「customer」のルックアップ設定・参照するアプリID」、`records[3].amount.value` →「CSV 5行目・金額［amount］」、`states[未処理].index` →「ステータス「未処理」の並び順」。言い換えられない部分はキーのまま残します）。画面（ステータス・複数の反映先の結果の行・プレビュー反映の「項目ごとの結果」・本番反映の結果）には先頭 3 件と「ほか N 件」を、結果ログ（実行ログ）には全件を出します。文は kintone が返したもので、1 件 200 文字までにし、送った内容が入る通信情報の行（`[API] …`）は画面に出しません。フィールド追加・JS/CSS 設定・プレビュー反映・本番反映（「反映元アプリから本番へ」の書き込みと、プレビューの変更の公開の依頼）・レコード管理（CSV取込・ステータス更新・コピー）で同じ言い回しです
- 結果ログ右上の「コピー」でログ全文をクリップボードへコピーでき、「保存」で `ツール名_ログ_日時.txt` として保存できます
- 入力欄で Enter（テキストエリアは Ctrl/Cmd+Enter）を押すと主アクションを実行し、Esc でパネルを閉じます。キーボード操作中の現在位置は枠線で表示します
- OS の「視差効果を減らす」設定では、アニメーションを止めます
- 1 画面目に出すのは対象アプリ・主要な操作（3 つまで。JS/CSS 設定は 4 つ）・取り消せない操作の警告だけです。ふだん変えない設定は「詳細設定…」、4 つ目以降の操作は「ほかの操作…」のポップアップで開き、補足説明はカード見出しの「?」で読めます。ポップアップは Esc・背景クリック・「閉じる」で閉じ、パネル本体は閉じません
- 文字は本文 14px・補足 12.5〜13px を下限にし（操作の説明・影響範囲のバッジ・段階の説明・候補の補足・設定取得の結果表・設計書の Excel のシートを選ぶ画面と生成中の表示も含む。段階の番号や「置換」などの小さな印と、差分比較の表示密度「コンパクト」の明細・640px 以下の画面の比較元・比較先の固定見出しは、収まりを優先して小さくします）、補足文の灰色もコントラストを確保した色にしています。3 段階の手順ナビは、現在の段階を濃い青、済んだ段階を緑（左端に印）、これからの段階を灰色で示します
- 複数のアプリIDを入れる・貼り付ける欄（対象アプリ表、差分比較の比較先、設定取得のアプリID、kintoneレコード取得・CSV出力・データ品質チェックの対象アプリ、ER図の起点、プレビュー反映の「続けて反映する反映先」など）は、半角カンマ「,」・読点「、」・全角カンマ「，」・空白・改行のどれで区切っても分けて受け付けます（全ツールで同じ）。ペア一括比較の貼り付けは、タブまたは「,」「、」「，」で列を分けます
- アプリID・ゲストスペースID・スペースIDの欄は、日本語入力のまま入れた全角数字（「１０１」）と全角カンマ（「，」）を半角に直して受け付けます（入力・貼り付け・変換の確定のとき。全ツールで同じ）。プレビュー反映・本番反映の確認用のアプリID欄も同じように直しますが、反映先と同じ番号でなければ進めない点は変わりません。プレビュー反映の「続けて反映する反映先」と、参照先変換（旧AppID → 新AppID）の全角数字も受け付けます。アプリを検索の検索語に全角数字だけを入れたときも、アプリIDとして調べます。数字以外の文字が混じる値は、これまでどおり入力の誤りとして止めます
- ゲストスペースのアプリ画面で開くと、既定の対象（現在のアプリ）とアプリ表の「現在のアプリ」にゲストスペース ID も入ります。通常スペースの同じ番号のアプリを指すことはありません
- 「アプリを検索」の「環境内の全アプリ」で、閲覧できるアプリを最後のページまで取得して候補に表示します（検索語とスペースIDは使いません）。複数のアプリを受け付ける入力欄には、候補の上の「候補 N 件をすべて追加」（割り当て先が複数あるときは「…すべて比較先へ」など）でまとめて設定できます。同じアプリIDとゲストスペースIDの組み合わせは重複して追加しません。ゲストスペースのアプリは通常の一覧に含まれないため、ゲストスペースIDを入れてゲストスペースごとに取得します。全アプリを対象にしたときも、確認画面の対象一覧は先頭 20 件と「…ほか N 件（合計 M 件）」で示し、件数は省略しません

### 接続先の指定

- アプリIDとゲストスペースID（対象アプリ表ではアプリごとに指定）。アプリの URL（`/k/123/`・`/k/guest/5/123/`）を貼り付けると、アプリIDとゲストスペースIDを読み取ります（対象アプリ表・差分比較・プレビュー反映・本番反映）
- 本番／プレビューの選択（「プレビュー環境から取得」「プレビュー環境を参照」など）。設定を書き込むツールは、常に反映先のプレビューへ書き込みます（本番反映を除く。レコード管理は本番のレコードを変更します）
- 「現在のアプリ」で、開いている画面のアプリ（ゲストスペースIDを含む）を入れます
- 差分比較では「比較方向を入れ替え」（1対1比較）とペアごとの「入替」で比較元と比較先を入れ替えられます

### ルックアップ参照先アプリ ID 変換

- プレビュー反映・本番反映の「反映元アプリから本番へ」・フィールド追加で、参照先アプリ ID を置き換えて反映します（ルックアップ・関連レコード一覧。プレビュー反映と本番反映はアクションのコピー先も）
- 変換した場合はアプリコード（`code`）指定を自動的に外し、変換後の ID が有効になるようにします
- 環境ごとにアプリ ID が異なる場合の移送を補助

## タブ別機能

### 1. 差分比較

公開中の `差分比較.js` は単一パネルで比較条件、結果確認、ファイル出力までを完結します。以下は現行 lite 版と、そこから生成する自己完結 HTML レポートの機能です。判定規則と上限の正本は [差分比較ロジック説明](../docs/diff-comparison-logic.md) です。

#### 非フィールド差分の検出精度

フィールド以外のセクションも、エンティティ単位で安定して差分を検出します。

- **ドメイン識別子マッチング**: アプリ権限はエンティティ（type:code）、フィールド権限・レコード権限のエンティティ配列も対象エンティティ、一般通知は宛先エンティティ、レコード条件通知・リマインダー通知はタイトル、遷移アクションは name|from|to の組み合わせで左右をマッチング。並び替えは added/removed の組ではなく moved 行へ集約され、個別の変更は「どのエンティティの何が変わったか」単位で出力されます
- **純粋並び替え検出**: 中身が同一で並びだけ違う配列（レイアウト行など）は moved 行のみで報告
- **moved 統合（LCS）**: 並び替えと追加/削除が混在する配列でも、同一内容が別位置に現れた added/removed ペアを moved 1 行（移動位置「N番目 → M番目」付き）に統合
- **表記ゆれ・空値ゆれの注記**: `"100"` ⇄ `100`、`"true"` ⇄ `true` などの差分は「表記のみ」、空文字 / null / 空配列 / 空オブジェクト同士の差分は「空値の差のみ」と注記。差分行自体は残します
- **改名検出**: フィールドコード変更やビュー / ステータス / 通知などのエンティティ改名を added/removed のペアから推定し「改名候補」として表示。プロセス管理のステータス改名は遷移アクションの from/to 参照カスケードを自動吸収し、改名 1 行に集約
- **客観分類**: 変更種別（追加 / 削除 / 内容変更 / 移動 / 同一）と存在状況（比較元のみ / 比較先のみ / 両方）を分離して表示。重要度や対応優先度は自動判定しません
- **関連設定の表示**: フィールド削除・改名時はフィールド権限・レコード権限等で見つかった参照を、ステータス削除・改名時は参照している遷移アクションを「関連している設定」として表示。業務影響や因果関係の断定ではありません
- **プラグイン取得結果**: プラグインセクション直下の `fetched` / `skipped` / `failed` は設定差分へ数えません。`failed` または `skipped` が1件以上なら、通常の差分ではなく取得不完全の警告として扱い、そのセクションを比較不能にします。現在の設定取得でも、ID欠落や不正な応答で設定を取得できなかった項目は同じ扱いです

#### 比較条件

- 比較対象セクションの選択
- 無視キーの設定
- **よく使う除外**: 「環境固有ID（アプリ・一覧・グラフ・アクション）を比較から除外」を折りたたまずに表示し、比較対象・参照先のApp IDと、一覧・グラフ・アクション自身の内部IDだけを除外。既定はオフで、フィールドコード、一覧条件、アクションの対応付け、プラグインID、独自設定内の一般的な `app` / `id` は比較対象に残します。変更後は再比較が必要で、差分件数・画面結果・Excelへ同じ条件を反映します
- セクション別の順序、監査情報、文言、外観、有効フラグ等を対象にした正規化プリセットの適用
- **比較条件プロファイル**: セクション、無視ルール、正規化、同一行、文字差分、表示密度、左右／上下の比較レイアウト、差分の表示方法（一覧／詳細）、行単位の差分をJSONで保存・読込（表示方法と行単位の差分を持たない古い比較条件は既定値で読み込む）。アプリID、設定本文、認証情報は含めない
- 無視キーの保存 / 読込（比較条件プロファイルに含めて保存します）
- 比較元 / 比較先の設定JSONの読込・解除（保存は HTML レポートの「作成時に利用した設定JSON」、または設定取得で行います）
- **3つの比較方法**: 1件ずつ比較する「1対1比較」、1つの比較元を複数の比較先へ照合する「1対多比較」、複数の比較元と比較先を各行で1対1に対応付ける「ペア一括比較」を切り替えられます。
- **ペア一括比較**: 比較元App ID / Guest ID / 運用・プレビューと、比較先App ID / Guest ID / 運用・プレビューを最大50ペア登録し、登録順に1件ずつ比較します。2列または4列の表をまとめて貼り付けできます。片側欠落、同じペア、比較元または比較先の重複は行番号付きで実行前に表示します。API取得時は同一接続先同士も止めます。途中失敗後も後続を続け、結果表には両側のアプリと環境を残します。成功行ごとにExcelまたはHTMLを保存できます。
- **複数対複数のフォルダ取込**: ペア一括比較で「比較元（変更前）フォルダ・ZIP」と「比較先（変更後）フォルダ・ZIP」のそれぞれで「フォルダを選択」または「ZIPを選択」を押し、配下の設定JSONを再帰的に読み込めます。「ZIPを選択」は設定取得の「設定をZIPで保存」で保存したZIP（manifest.json つき・無しのどちらも）を展開せずに読み、展開したフォルダを選んだときと同じ対応・同じ比較結果になります（片側をZIP、反対側をフォルダにしてもよい）。両側に同じZIP（名前・大きさ・更新日時が同じ）を選ぶと、止めずに取り違えの注意を出します。ZIPの読み取りはブラウザの中だけで行い、展開するのはJSONだけです（JS/CSSファイル本体は読まない）。一意なアプリ名、次に一意なApp IDだけを自動対応し、曖昧な組み合わせは対応確認表で手動選択します。App ID一致・フォルダ順候補は行ごとの確認チェック、対象外にする行や未使用の比較先も明示チェックで確定し、確認済みペアで現在の表を置き換えます。フォルダ由来の行は設定JSONと接続情報を固定し、同一App IDの旧／新スナップショットを比較できます。不足分をAPIで補わず、左右のキャッシュも共有しません。再読込を始めた時点で旧結果と保存導線を無効化し、読込中の比較も止めます。1回の選択上限は全ファイル2,000件、JSON 500件、JSON合計128MB、1フォルダ（1つのZIP）50アプリで、ZIPファイル自体は256MBまでです。ZIPは、壊れたZIP、記録された大きさと中身が合わないZIP、展開すると別の場所を指すパスや同じ名前になるファイルを含むZIPも読まずに止めます（止めたときは前の選択のまま）。
- **環境内の全アプリを比較先にする**: 「アプリを検索」の「環境内の全アプリ」から「候補 N 件をすべて比較先に追加（1対多）」を押すと、1対多比較に切り替えて全アプリを比較先に入れます。既にある比較先と、比較元と同じ接続先（アプリID・ゲストスペースID・環境が同じ）のアプリは除き、件数を表示します。比較先が 100 件を超える場合は、時間とメモリの注意を表示します
- **差分比較の実行 → HTML レポート出力**: 「差分比較を実行」を押すと、比較完了と同時に差分 HTML レポートをダウンロードします（出力ボタンを別途押す必要はありません）。「1対多比較」でも比較先ごとに HTML を自動保存します（比較先が 10 件を超える場合は自動保存せず、結果行または Excel の一括保存から保存します）。「ペア一括比較」はブラウザの複数ダウンロード確認を避けるため、結果行から必要なHTMLを保存します。
- **差分一覧 Excel 出力**: Lite版から保存する `.xlsx` は「比較概要」「変更対象一覧」「変更一覧」を常設し、「比較概要」（取得状態の注意があるときは「確認できなかった範囲」）の直後に利用者向けの説明シート「このファイルの見方」（シートの構成、確認の手順、各シートの列の読み方、値の表記）を置き、実差分がある機能だけを `01_アプリ一般設定` から `20_カテゴリー設定` の機能別シートへ分けます。どの機能か特定できない差分は `99_その他の設定` にまとめ、差分がない機能の空シートは作りません。プラグイン個別設定は `10_プラグイン個別設定`、カスタマイズファイル本文は `12_カスタマイズ本文` へ分け、プロセスのアクションは `08_プロセス管理`、アプリアクションは `13_アプリアクション` として混在させません。値は変更一覧と機能別シートの「変更前」「変更後」へそのまま収録し、変更一覧の「分類」から機能別シートの同じNo.の明細へ内部リンクで移動できます。取得失敗・一部未検証・件数上限がある場合は「確認できなかった範囲」を概要の直後に追加します。同一行は収録せず、表示専用行はテーブル全体の追加・削除を内包フィールドへ展開する子行だけに限定します。権限・通知・プラグイン・JS/CSS設定を含む実差分は1差分1行で収録します。並び順変更とkintoneの `index` は、意味が確定する設定だけ比較元・比較先を1始まりの「N番目」「M番目」で示します。独自設定の `index`、`no`、`size` は変換しません。状態・型の専用列は設けず、対象がない側は「存在しません」、値が入っていない状態は「（未設定）」「（値なし）」「（空文字）」と値列へ直接表示します。差分0件でも「変更一覧」に罫線付きの「差分はありません」行を出して保存できます。
- **Excel構成**: 「出力」の「Excel構成」で、上記の「レビュー用（標準）」と「社内・技術明細込み」（フィールド差分の要約・詳細、差分一覧、セクション別の技術明細と差分ID を加えた構成）を選べます。既定はレビュー用です
- **フォームフィールドの専用表示**: `03_フォームフィールド` では「配置 / フィールド名 / フィールドコード / フィールドの種類 / 差分プロパティ / フィールド存在 / 設定値存在」を別列にします。フィールド自体の追加・削除は変更前後を「存在」「存在しません」で示し、個別プロパティだけが片側にない場合とは存在列で区別します。テーブルと内包フィールドは親子表示し、配置列に親テーブルの名称とコードを示します。子行はExcelのアウトラインで折りたたみ・展開できます。
- **Excel のレビュー向けレイアウト**: 変更一覧は「No. / 変更区分 / 分類 / 設定対象 / 差分プロパティ / 変更前 / 変更後」の7列です。人が読める名称を優先し、ログインユーザーなどの条件関数、対象種別、`WRITE / READ / NONE`、プロセス作業者方式、フィールド・一覧・グラフ・カスタマイズの列挙値をセクションとパスの文脈に合わせて日本語化します。条件式の引用符内と自由入力は置換しません。変更前は淡い赤、変更後は淡い緑、存在しない側は無彩色で表示します。空欄や比較対象が存在しない側を含め、すべての表の全行・全列へ同じ細い淡色の四辺罫線を適用し、強調は背景色と文字色で行います。シート・行・列を非表示にせず、セル数式と外部リンクも生成しません。概要には完全性、「変更対象一覧」と同じ対象単位の変更対象件数、機能別の差分明細件数、比較条件、掲載範囲を表示します。重要度・影響度や対応要否は自動判定しません。
- **Excel の一括保存**: 1対多比較とペア一括比較では、「Excelをまとめて保存（N件・ZIP）」からExcelを1つのZIPで保存します。先頭の `000_一括比較結果.xlsx` でExcel生成対象の結果、差分内訳、アプリ名の不一致、個別Excel名を確認でき、個別Excelは登録順の番号と短い業務名で命名します。差分0件と取得不完全の結果も含み、比較失敗とExcel生成失敗は個別Excelから除外します。Excel生成失敗は、少なくとも1件を保存できる場合には集計へ状態を残します。ZIPには `.xlsx` 以外を入れず、上限は200MiBです。
- HTML レポートは「差分一覧」「フィールド単位」の 2 タブ構成（サマリー / 比較対象設定タブは廃止）。レポート内の「詳細オプション」で、出力前と同じ無視キー・順序無視などの条件を後から選択して表示を絞り込み可能
- HTML レポートには CSP を付けています（外部への通信・読み込み・フォーム送信を禁止し、スクリプトは埋め込んだ 1 つだけを内容のハッシュで許可）。設定の文字列から HTML が差し込まれても、スクリプトは動きません。
- 「範囲」で全件 / 表示中を選び、Excel保存または HTML の再出力が可能
- **HTML内容モード**: 「出力」の「HTML内容」の既定「レビュー用（変更箇所のみ）」（レポート内の表記は「差分行のみ（全設定は未収録）」）は比較元/先の全設定スナップショットを埋め込まず、元設定JSON・フィールド詳細・反映JSONを収録しません。「社内用（比較設定を含む・取扱注意）」（レポート内の表記は「比較設定込み（取扱注意）」）を明示選択した場合だけ詳細機能を有効化します。選び直したあとは「HTML を再出力」で保存します。どちらのHTMLにも差分行の比較元/先の値は残り、Excelにも同じ差分値を加工せず収録します。プラグインの設定値やJS/CSS本文の差分を含むExcel（どちらの構成も）とAI向けMarkdownには「🔒 取扱注意」を表示します。共有前に内容を確認してください。
- **画面内レビュー**: 変更種別・セクション・キーワード等で絞り込み、`J` / `K` と前後ボタンで実差分を先頭・末尾の範囲内で移動。固定ヘッダーは BEFORE / 現在位置 / AFTER の3レーンで比較方向を保ち、有効な絞り込み条件は個別解除できるチップで表示します。表示密度、差分の表示方法（一覧／詳細）、セクションの閉じる / 開く、左右／上下の比較レイアウトも切り替え可能です。
- **連続レビュー**: HTMLレポートでは全体とセクション別の確認済み件数・進捗率を表示し、「確認して次へ」または `R` キーで現在行を確認済みにして次の未確認差分へ移動できます。集中表示でも比較元 / 比較先のアプリ名と App ID、現在位置、未確認数を残します。コンパクト密度ではカード余白を縮めて大量差分を高速に読み進められます。
- **レビュー状態の持ち運び**: 「レビュー状態JSON保存 / 読込」で確認済み状態を明示的に保存し、後から同じ比較結果へ復元できます。別レポート用のJSON、未知・重複した行、2MBを超えるファイルは現在状態を変えずに拒否します。ブラウザ内へ状態を自動保存しません。
- **大量差分向けの軽量表示**: 検索文字列を行単位でキャッシュし、連続入力は150msのデバウンス後に1回だけ反映します。日本語IME変換中の再描画を抑え、画面外カードは対応ブラウザで描画負荷を軽減します。表示件数 / 全体件数 / 未確認件数は常設の読み上げ領域へ通知します。
- **読みやすい差分カード**: 行見出しは日本語の要約を優先し、フィールド設定の行には対象の表示名とコード（例: `顧客名（customer_name） · 必須設定変更`）を付けて同じ種類の変更を見分けられるようにします。内部パスは「技術情報」に折りたたみます。ステータス改名は旧名と新名で示します。長い値やJSONは行数・文字数付きのプレビューで表示し、必要な行だけ全文へ展開できます。HTMLレポートの差分行は、見出し、その下の 1 行（違いの種類・存在状況・理由・「技術情報」・「関連している設定」）、値の順に並べ、1 行に収まる値は「比較元 値 → 比較先 値」の 1 行で示します。片側だけにある行は存在状況、両方にある行は差分内容を色付きで先に示します。文字単位ハイライトは連続する文字を 1 つの印にまとめ、共通部分が半分に満たない値（`false` → `true` など）は値全体の置き換えとして印を付けません。並び順だけが異なる行は「内容は同じです。並び順だけが異なります。」と示し、内容は「内容を表示」で開きます。追従する絞り込みバーは、広い画面では種別と移動の 2 段にまとめ、絞り込みが無いときは「適用中」の行を出しません。
- **一覧と詳細（パネルの結果明細）**: 既定の「一覧」は、各行を「種類・項目名」と変更の要点（「比較元の値 → 比較先の値」を色付きの短いチップで 1 行。複数行の値は削除・追加の行数と最初の違う行）だけにして値を閉じ、差分のある項目を見渡せます。行ごとの「値を表示」、行の見出し・要点の押下、確認バーの「一覧」「詳細」ボタン（「表示」の表示方法と同じ設定）で値を開閉します。値は開いた行だけ描画するため、件数が多くても軽く動きます。
- **行単位の差分**: 複数行の値（JS/CSS の本文、長い設定値）の内容変更は、開いた行で比較元・比較先を行ごとにそろえ、違う行とその前後 2 行だけを行番号と「−」「+」の印つきで示します（変更のない行は「変更のない N 行を省略」、「すべての行を表示」で全行）。内容が近い置き換えの行は文字単位でも強調し、改行コード（CRLF / LF）だけの違いは注記だけで示します。「上下に比較」と狭い画面では 1 列に積みます。「表示」の「行単位の差分」をオフにするか、違う行が多すぎるときは、従来どおり比較元・比較先の値を左右に並べます。HTML・Excel・Markdown の内容は変わりません。
- **無視ルール候補**: 差分行の「次回から除外」から、大小文字・空白・`*`・区切り記号をリテラルとして扱う `path:` 形式の完全パスを次回比較条件へ追加（現在の結果は変更せず、再比較後に適用）。配列番号を含む位置依存パスは誤除外防止のため自動追加不可
- **不完全比較の明示**: 件数上限後に走査していないセクションは「未走査・件数不明」として、取得失敗や本文未検証と区別して表示
- **対応付けの注意**: 要素数が多く並び替えの検出を省略した配列や、タイトル等の識別子が空・重複で別の方式に切り替えた配列を、完了メッセージと結果の概要へ表示。差分の取りこぼしではないため、完全性や「要確認」には含めません
- **同じアプリの本番とプレビューを比較**: 1対1比較の「本番とプレビューを比較（未公開の変更を確認）」で、比較元を本番、比較先を同じアプリ（同じゲストスペース）のプレビューに設定します。比較元の入力（URLの貼り付け可）を使い、空なら開いているアプリを使います。設定だけを行い、比較は「差分比較を実行」で行います（実行後の概要に「本番 → プレビュー」と示されます）。比較元の設定JSONを読み込んでいる間は設定できず、1対多・ペア一括では表示しません。
- **表示順の繰り下がり**: 一覧・グラフ・ステータス・カテゴリ・アプリアクションの途中へ1件追加（削除）して、後続の表示順が1つずつずれただけの違いは、差にしません。両側にある項目どうしの並び順が変わったものだけを「表示順」の差として示します。
- **並び順を無視する正規化**: 選んだ並び順だけを差分から外します。並べ替えで位置がずれた「並び順が異なる」行や、新しい差は出しません。
- **結果の要約をコピー**: 結果の概要の下の「結果の要約をコピー」で、比較元・比較先（アプリ名・App ID・環境）、結果（差分の件数と追加・削除・内容変更・移動の内訳）、取得の状態、差分のあるセクションごとの件数、取得失敗などの注意、比較条件を数行の文でクリップボードにコピーします。チャットや課題の記録にそのまま貼れます。件数と文は画面の概要と同じで、設定の値は含めません。
- **件数の一致**: 完了メッセージの内訳（追加・削除・内容変更・移動）は概要・HTML・Markdownと同じ数です。旧フォーム設定（フィールド設定・レイアウト設定の再掲）は、Excelでは変更一覧の件数に含めず別シートに載せるため、画面・HTML・Markdownの件数は、Excelの変更一覧の行数にフォーム設定の件数を足した数になります（画面の概要にも、再掲であることを示します）。
- **1対多比較の保持量**: 結果をメモリに保持するとき、保存に使わないJS/CSSの本文・プラグイン設定の取得結果は取り除きます（比較先200件・業務アプリ規模で約99MB → 約22MB）。結果の行からのHTML・Excel・Markdown・ZIP保存は変わりません。
- **1対多比較の実行前検査**: すべての比較先のアプリID・ゲストIDと重複を行番号付きで検査し、問題があれば直前の比較結果を残したまま実行を止めます。1対1比較を含め、比較元・比較先のゲストIDも半角数字以外は取得前に止めます

#### HTML レポートの機能

差分 HTML レポートは、単体で完結する自己完結型ページです（外部 CDN 依存なし）。

- **差分一覧タブ**: 完全性、比較方向、客観件数を先に示し、セクション別に差分カードを表示します。レビュー受信箱、セクション見出し、ジャンプナビには確認済み / 対象件数を表示し、追加 / 削除 / 内容変更 / 移動 / 同一、使用中フィルター、文字単位ハイライトで変更箇所を把握できます。
- **比較レーンと段階表示**: 比較元を BEFORE、比較先を AFTER として値の方向を常に明示します。日本語の意味を先に見せ、内部パスやコードは「技術情報」、長い値は展開可能なプレビューへ分離します。
- **モバイル表示**: 狭い画面では比較値を1列に積み、絞り込み・出力のサイドバーを開閉式にして、横スクロールせずレビューできます。
- **モバイルドロワー**: 絞り込み・出力は本文を押し下げない固定ドロワーで開きます。背景操作を抑止し、`Esc`・閉じるボタン・背景クリックで元の操作位置へ戻ります。
- **JSONで比較（フィールド単位）**: WinMerge のように設定 JSON 全体を左右に並べて行単位で比較するモード。フィールドごとにブロックを区切り、変更行のハイライト・行番号・文字単位差分を表示（「複数行差分は変更行だけ表示」をオフにすると全行を整列表示）
- **フィールド単位タブ**: フィールドコード単位で、比較元 / 比較先の設定を kintone の設定ダイアログ風スナップショットで左右に並べ、値が異なる項目に差分色を付与。関連レコード一覧設定・ルックアップ設定・テーブル内の項目は、日本語ラベル付きの key-value 表で差分行を赤（比較元のみ）/緑（比較先のみ）/黄（変更）に色分けし、変更値は文字単位でハイライト。差分一覧と同じ種別チップ（追加 / 削除 / 変更 / 同一）での絞り込みと詳細オプション（無視キー・正規化プリセット）が有効
- **反映JSON作成**: 差分行・フィールドの「選択」チェックから、比較元の設定値を比較先アプリへ反映するための API パラメータ JSON を作成（保存 / コピー）。画面の「比較元=変更前 / 比較先=変更後」で比較した場合は変更前へ戻す方向になるため、前進移行では完成状態を比較元、反映先の現状を比較先にして再比較します。フィールドは `form/fields` の PUT / POST / DELETE に分解し、全体置き換え型のセクションは対応 API の payload を生成します。プロセスの状態名変更がある場合は、別の変更へ改名が混入するのを防ぐためHTMLの反映JSON全体を無効にし、統合版でもプロセス管理のセクション単位反映と失敗セクション再実行をブロックします。外部パッチJSON内の確認専用行・予約済み改名パスも拒否します。状態名変更以外は行／ノード単位で選ぶか、管理画面で手動確認します。
- **作成時に利用した設定JSONの出力**: レポート作成に使った比較元 / 比較先アプリのセクションデータを、それぞれ JSON ファイルとして保存可能
- **確認済み管理**: 各差分行の「確認」チェックで確認済みをマークし、サイドバーの「確認済みを隠す」で残作業だけに絞り込み。確認済み・選択中件数はサマリーに表示
- **コピー / エクスポート**: 行ごとに設定パス・値（JSON）をワンクリックコピー。表示中の差分を CSV 保存 / Markdown 表としてクリップボードにコピー
- **キーボード操作**: `J` / `K`（または「前へ / 次へ」）で差分行を順に移動、`Ctrl/⌘+F` で検索フォーカス、`Esc` で検索クリア
- ライト / ダークテーマ切替、セクションへのジャンプナビ、印刷プレビュー対応

### 2. プレビュー反映

アプリまたは設定JSONから、指定アプリのプレビュー設定を更新します。

- 対象選択・差分確認・最終確認・結果の4段階。進めない理由を画面下部に表示。画面の用語は「反映元／反映先」
- アプリURLの貼り付けからアプリID・ゲストスペースIDを読み取り。入力中にアプリ名を確認して表示
- 反映元の本番／プレビューを明示選択し、APIで確認したアプリ名・ID・ゲストスペースを表示
- 反映項目ごとの動作説明と「置換」の目印。フィールド設定を含めない場合の注意
- 差分確認の要約表と、項目単位の「変更の要約」（フィールドは表示名（コード）、レイアウトは位置）。設定値の内訳で反映先の現在と反映後を比較
- 反映先だけのフィールド・配置を保持。一覧・グラフ・アクションも標準で保持し、全置換は明示選択
- 一般設定（テーマ・レコードのタイトル・コメントなど。アプリ名・説明・アイコンは対象外）の反映
- 別アプリのJS/CSSファイルを内容で比較し、必要なものだけ反映先へアップロードして設定
- 取得失敗や参照先フィールド不足、種類の衝突を実行前に検出。不足時はフィールド設定を加えて再取得
- 反映先プレビューの以前からの未公開の変更を表示し、ある場合は反映先IDの入力を要求
- 反映計画JSONの保存、計画・記録のMarkdown保存とコピー、項目と値の検索、セクション選択
- ルックアップ・関連レコード一覧・アクションの参照先AppIDを「旧ID → 新ID」の行形式またはJSONで指定。変換時はアプリコード（code）指定を自動削除
- 参照先変換の入れ忘れを防ぐ「参照先変換の候補」。反映元と反映先の同じコードのルックアップ・関連レコード一覧（と同じ名前のアクション）で参照先アプリが違うとき、差分確認に「401 → 301」の形で候補を示し（分かる範囲でアプリ名も）、「候補を参照先変換に追加して差分を取り直す」で入力欄へ加える。根拠は反映先の現在の設定だけ（名前の類似などから推測しない）。同じ旧IDに複数の参照先がある食い違いは自動では入れず、入力済みの変換は上書きしない。入れないまま反映するときは、最終確認で反映先IDの入力を求め、計画のMarkdownにも注意として載せる
- 接続先・項目・オプション・続けて反映する反映先のプリセットを保存し、JSONで書き出し・読み込み
- 最終確認のチェック。削除・権限等の変更・同じアプリへの反映・未公開の変更がある場合は反映先IDも入力
- 実行直前の設定・revision照合、自動バックアップ（JS/CSSのファイル本体を含む）、エラー時中断
- 実行中の項目ごとの進捗、結果の項目別一覧と対処ヒント（kintone の入力エラーは、受け付けなかった項目を「フィールド「X」の計算式」のような言葉で先頭 3 件と「ほか N 件」まで示し、全件は実行ログに残す。ルックアップ・関連レコード一覧の設定のエラーには「参照先変換」を案内する）
- 書き込みの応答が届かなかった項目は、設定を読み直して反映されていないと確かめたときだけ同じ revision で送り直す。分からないときは「反映されたか不明」（失敗には数えない）として以降の項目を書き込まずに止め、差分を取得し直して確かめるよう示す
- 失敗・未実行の選択と再比較。反映後に同じ条件で差分を再確認
- 「変更を中止」による取り消しの案内と、バックアップを反映元にした復元
- 同じ反映元・項目で複数の反映先へ順番に反映（反映先ごとに確認。最大 1000 件）。アプリ検索の「環境内の全アプリ」から全アプリをまとめて「続けて反映する反映先」に追加できる（反映元と入力済みのアプリは除き、件数を表示）
- 続けて反映する反映先があるとき、「全反映先の事前確認」で、全反映先の差分を書き込まずに先に一覧にする（反映元は 1 回だけ取得）。反映先ごとにアプリ名・状態（差分あり／差分なし（一致）／確認が必要／取得失敗／未実行（中止））・差分のある項目・変更と削除の件数・以前からの未公開の変更の有無を示し、取得失敗を「差分なし」と表示しない。「差分のない反映先を外す」「取得失敗だけ確認し直す」、行から差分確認へ進む操作、結果のMarkdown保存・コピー（承認依頼用。設定値の生JSONは含まない）。反映元・項目・保持・参照先変換を変えると古い結果として扱い、中止では残りを「未実行（中止）」にする。1000 件でも行は要約だけで、一覧は 50 件ずつ描画する。反映先ごとの差分確認と最終確認は従来どおり必要で、自動では書き込まない
- 閉じて開き直したとき（同じページが開いている間）は、入力・直前の結果とバックアップ・展開の記録・プリセットを引き継ぐ（ページを読み込み直すと消える）
- 本番公開は反映先の設定画面で実施

使い方・API仕様・バックアップの制約は [プレビュー反映](../docs/preview-reflection.md) を参照してください。

### 2-2. 本番反映

プレビューの未公開の変更を、本番へ公開（kintone の「アプリを更新」）または破棄（「変更を中止」）します。見出しのバッジは「本番の設定を変更」です。

- 対象を選ぶ・変更を確認・最終確認・結果の4段階。段階1・2では書き込みません。進めない理由は「次に進むには：…」で表示
- 対象アプリは表で入力（アプリごとにゲストスペース。URL・カンマ区切りの貼り付け、現在のアプリ、環境内の全アプリから一括追加。最大 1000 件）
- 操作は「本番へ反映（アプリを更新）」（既定）と「変更を中止（プレビューを本番に戻す）」。詳細設定で反映の方法（1アプリずつ／まとめて。まとめては最大 300 件・同じゲストスペース）と失敗したときの動作（残りを実行しない／続ける）を選択
- 差分確認はアプリごとに「変更あり」「未公開の変更なし」「取得失敗」「反映処理中」を表示。変更のある項目名・削除の件数・revision（本番 → プレビュー）と、開いたときに描画する項目別の「変更の要約」。取得失敗・反映処理中のアプリは選択している間は先へ進めず、「取得失敗・処理中だけ確認し直す」と「対象から外す」を用意
- 削除されるフィールドは警告色で「レコードの値も削除され、元に戻せません」と示し、コードだけを変えた可能性があるときは「プレビューの『X』」を添える。あわせて本番のレコード数を読み取り（読み取りだけ）、「このアプリのレコード: N 件（閲覧できるレコードの数）。削除するフィールドの値は、これらのレコードから削除されます。」と影響の大きさを示す（閲覧できない・取得に失敗したときは「確認できませんでした」と示して止めない）
- 計画のMarkdownを保存・コピー
- 最終確認は、方向・対象・反映の方法・削除される設定・削除されるフィールド・バックアップ・取り消し方を表面に示し、チェックと確認入力（1 件なら対象アプリのID、複数なら対象のアプリ数）を求める。確認は、前の段階へ戻る・選択や条件を変えると解除
- 実行前に各アプリの revision を再確認し、反映前の本番設定（変更を中止ではプレビューの設定）をバックアップJSONに保存してから依頼。バックアップはプレビュー反映の反映元（設定JSON）に読み込める
- 結果はアプリごとに待機中・確認中…・反映中…・成功・失敗・取り消し・確認後に更新・完了を確認できない・未実行を表示。数百件を超えるときは要約と問題のある行を優先表示。結果JSON・記録のMarkdownの保存とコピー、失敗・未実行だけ選び直す、1 件なら設定画面を開く

#### 反映元アプリから本番へ

別のアプリ（開発・検証用）の設定を、差分を設定値 1 つずつ選び、直してから、反映先のプレビューへ書き込み、続けて本番へ反映します（「操作」の既定）。対象を選ぶ → 差分を選ぶ → 内容を修正 → 最終確認 → 結果の 5 段階で、最初の 3 段階では書き込みません。

- 選んだ変更と、入力欄・JSON での修正を、段階 2・3 の「選択と修正を保存」で JSON ファイルに保存し、差分を抽出し直したあとに「選択と修正を読み込む」で戻せる（承認を待つ間や別の担当者への受け渡し）。反映元・反映先が保存時と違うファイルは違いを示して読み込まない。現在の差分に無い選択・修正は「当てはまらなかったもの」として件数を示す。JSON での修正は、反映先の設定が保存時と同じ項目だけ当てはめる。読み込んでも最終確認は必要
- 反映元と反映先で参照先アプリが違うルックアップ・関連レコード一覧・アクションがあり、参照先変換に入れていないときは、段階 2 に「参照先変換の候補があります」と警告し、「候補を参照先変換に追加して差分を取り直す」で追加して抽出し直せる（選択と入力欄の修正は引き継ぐ。食い違いは自動では入れない）。入れないまま進むと最終確認にも警告し、記録の Markdown・結果 JSON に残す
- プレビューへの書き込みで「反映されたか不明」の項目が出たら、本番へは反映しない（プレビュー反映と同じ規則）。依頼の応答が届かなかった本番反映は送り直さず「完了を確認できない」と示す
- 結果の「反映後の内容を確認する」で、本番（プレビューまでならプレビュー）の設定を読み取り、選んだ変更が選んだ値（修正した値を含む）で入っているかを確かめる。「すべて反映されています」または「反映されていない変更 N 件」（場所・期待した値・現在の値）を示し、取得できなかった項目は「確認できません」とする。確認した日時と結果は記録の Markdown・結果 JSON に残る。読み取りだけで、書き込まない

使い方・バックアップと戻し方・制約は [本番反映](../docs/production-deploy.md) を参照してください。

### 3. フィールド追加

フィールド追加（`フィールド追加.js`）は、JSON 編集・反映元から選んで追加・一括整備の機能で構成されます。書き込むのは反映先のプレビューだけで、デプロイ（本番公開）は行いません。

#### JSON編集

- `properties` 形式のフィールド JSON を直接編集
- 反映先プレビューへ反映
- 既存フィールドを上書き更新（オフなら同じコードの既存フィールドはスキップ）
- 反映後にフィールドコードが重複する組み合わせ（既存コードへの追加・コード変更の衝突）は、書き込み前に中止
- 反映前の確認に追加・更新対象のコード（コード変更は「旧 → 新」）と削除 0 件を表示。追加後の更新が失敗した場合は、追加が反映済みであることをエラーに含めて表示
- 追加・更新の応答が届かなかったときは、反映先のフィールド設定を読み直して反映されていないと確かめたときだけ送り直す。分からないときは「反映されたか分かりません」と、フォームの設定で何を確かめるかを警告の色で示して止める（「revision 競合」とは言わない）
- 反映後のフォームに無いフィールドを参照する定義（計算式の参照先（計算フィールドと文字列（1行）の自動計算）、ルックアップのコピー先、関連レコード一覧の条件。テーブルの中を含む。「・」や全角の「＄」「￥」を含むコードも 1 つのコードとして読む。反映先に既にあるフィールドと、同じ JSON で追加するフィールドは「ある」とみなす）は、最終確認に足りないコードを警告として示す（複数の反映先では反映先ごと）。書き込みは止めず、利用者が続けるかを決める（kintone は拒否することがあり、その場合は何も追加されない）。反映しない既存のフィールドが、コードを変更するフィールドを参照している場合も示す
- 「反映先から読込」で反映先プレビューの現在のフィールド、「反映元から読込」で反映元のプレビューのフィールドを JSON に読み込む
- 「検証」で件数（書込可・システム・テーブル・ルックアップ・計算）と構造上の問題を結果ログに示す
- JSON 整形・クリア
- JSON ファイル読込 / 保存（保存名は反映先、なければ反映元のアプリID）
- 反映先のアプリID・ゲストIDは数値のみ。ID・フィールド JSON（type 必須）・参照先変換 JSON は確認画面へ進む前に検査。検索結果から選ぶとゲストIDも検索した接続先に合わせる
- 参照先変換 JSON（`{"旧アプリID":"新アプリID"}`）は、全角の数字・カンマを半角にしてから読む（`{"３０１":"３０２"}` も `{"301":"302"}` と同じに変換する）。旧・新のアプリIDが正の整数でないもの（数字でない・空・0・小数など）や、同じ旧アプリIDに違う変換先があるものは、確認画面へ進む前に「「301」→「abc」」のように該当の組を示して止める（黙って捨てたり、変換しないまま反映したりしない）

#### 複数の反映先へ反映

- 操作「複数の反映先プレビューへ反映」で、同じフィールド JSON を複数アプリのプレビューへ反映する。反映先は「まとめて反映する反映先」の表（行ごとにゲストスペースID）で指定し、アプリ検索の「環境内の全アプリ」→「候補 N 件をすべてまとめて反映先に追加」で全アプリを入れられる
- 先に全反映先の現在のフィールド設定と revision を取得して計画を作り、最終確認を 1 回だけ表示する（対象数、反映する件数・変更なし・事前確認に失敗の内訳、追加 / 更新 / スキップの合計、削除 0 件、アプリごとの一覧は先頭 20 件と件数）
- 1 件ずつプレビューだけへ反映し、事前確認の revision を送る。その後に別の更新が入った反映先は「競合」として上書きしない。失敗・競合があっても残りを続け、「中止」で残りを「未実行（中止）」にする（反映済みの分は取り消さない）
- 結果は反映先ごとに 成功 / スキップ（変更なし） / 失敗 / 競合 / 反映されたか不明（応答が届かず、読み直しても分からない） / 未実行（中止） を表示し、一部成功は警告色

#### 反映元から選んで追加

- 反映元アプリ（プレビューの設定）のフィールド一覧を取得（「詳細設定…」の「反映元からフィールドを選んでマージ」）
- コード・ラベル・タイプで候補を絞り込み、表示中の候補を全選択／全解除。選択件数を常時表示
- 選択したフィールドを JSON にマージ（同じコードの既存定義は候補の内容で置き換え）。計算式の参照先・ルックアップのコピー先・テーブルの中のフィールドは自動では加えないため、足りなければ最終確認で示す
- 反映元のアプリID・ゲストIDを変更すると、前の反映元の候補は閉じる

#### 一括整備

- 反映先プレビューのフィールドコードへのプレフィックス一括付与 / 除去（「詳細設定…」の「プレフィックス一括リネーム」。計算式（文字列（1行）の自動計算を含む）・ルックアップのコピー先・関連レコード一覧の条件が参照するコードも、新しいコードに合わせて書き換える。コードを変えない定義でも参照先が変わるなら JSON に含める。重複するコードは生成前に中止）。出力形式は「コード変更用」（既存フィールドのコード変更として扱うため、上書き更新を自動でオン）と「新規追加用」（新しいコードのフィールドとして追加）から選ぶ。生成した JSON は入力欄に入るだけで、反映は別に実行する。書き換えるフィールドが無いとき（除去するプレフィックスで始まるコードが無い、すべて付いている）は、入力済みの JSON を変えずに理由を示す

### 4. JS/CSS 設定

JS/CSS 設定パネル（`kintoneJS取得.js`）は「JS/CSS設定を取得」「カスタマイズJSONを保存」「反映先プレビューへ反映」「複数の反映先プレビューへ反映」「全アプリのJS/CSSをZIP保存」から操作を選び、確認画面を経て実行します。

#### 設定編集

- 取得元アプリ（本番 / プレビュー、ゲストスペース指定可）の JS/CSS 設定取得
- JSON 表示 / 編集（手入力・貼り付けも可）。「JSONの読込・整形・保存」でファイル読込・反映先から読込・整形・クリア
- JSON 出力（ファイル名は取得時のアプリIDを使用。確認画面に JSON の取得元と取得後の編集有無を表示。編集中の JSON を取得で上書きする前に確認）
- 反映先プレビューへ反映（revision を送り、取得後に別の更新が入っていれば中止。反映先のプレビューから取得した JSON は取得時の revision を基準にし、それ以外は反映直前の revision を基準にする。最終確認に反映先の現在件数と、全置換で外れる件数を表示。js / css が配列でない JSON は反映前に止める。応答が届かなかったときは読み直して反映されていないと確かめたときだけ送り直し、分からなければ「反映されたか分かりません」と確かめ方を示す）
- 反映先は常にプレビュー環境で、デプロイは行わない（管理画面から手動）

#### FILE 形式（アップロード済みファイル）の別アプリへの反映

fileKey は取得元のアプリでしか使えないため、プレビュー反映と同じ規則（`reflect/customizeFiles.ts`）で、反映先ごとに扱いを決める。

- JSON を取得したアプリ（アプリ・本番 / プレビュー・ゲストスペース）を、取得時に覚えておく。取得した JSON に含まれていた fileKey だけが取得元のものと分かる
- 反映先プレビューの同じ枠（PC / モバイル × JS / CSS）ですでに使われている fileKey はそのまま使う（同じアプリへ戻すときは、ダウンロードもアップロードもしない）
- それ以外は取得元からファイル本体を取得し、反映先の同じ枠に同名・同内容のファイルがあればそのキーを再利用、無ければ反映先へアップロードして新しいキーで設定する（アップロードしたキーは 1 回しか使えないため、同じファイルを PC とモバイルで使う場合は枠ごとにアップロードする。取得元のキーを書き込みに流用しない）
- 最終確認に、アップロードするファイル（枠・ファイル名・サイズ）、再利用するファイル、そのまま使うファイルと、全置換で外れる件数を示す。複数の反映先では、アップロードするファイルの一覧と反映先ごとの件数を示す。取得元の本体は反映先ごとに取得し直さない
- アップロードは確認後、設定を書き込む直前に行う（複数の反映先では、反映先ごとの書き込みの直前）。本体の取得・アップロードが 1 つでも失敗した反映先には、設定を書き込まない（複数の反映先では、その反映先だけ「失敗」にして残りを続ける）。アップロードの途中で中止したときも書き込まず、「書き込みは行っていません」と示す。使われなかった一時ファイルが残ることがあるが、設定には影響しない
- 取得元が分からない JSON（手入力・ファイルから読み込んだだけ）や、取得後に追加して取得元の JSON に無い fileKey は、推測でアクセスせず「取得元アプリで『取得』してから反映してください」と示して止める（反映先がすでに同じ枠で使っているキーは使える）。バックアップ JSON のようにファイル本体を埋め込んだ JSON は、取得元が分からなくても反映できる
- 操作の確認画面に、FILE の件数と、取得元が分からないファイルの警告を表示する

#### 複数の反映先へ反映

- 操作「複数の反映先プレビューへ反映」で、同じ JS/CSS 設定 JSON を複数アプリのプレビューへ反映する（デプロイはしない）。反映先は表（行ごとにゲストスペースID）で指定し、アプリ検索の「環境内の全アプリ」→「候補 N 件をすべてまとめて反映先に追加」で全アプリを入れられる
- FILE 形式の JS/CSS を含む JSON も、上の規則で反映先ごとに再利用かアップロードかを決めて反映する。取得元が分からないファイルでどの反映先にも渡せないときは、事前確認の段階で 1 回だけ理由を示して止める
- 先に全反映先のプレビュー設定と revision を取得し（FILE があれば、反映先ごとのファイルの扱いも決める。読み取りのみ）、最終確認を 1 回だけ表示する（対象数、枠ごとの件数、適用範囲、外れる件数、アップロードするファイル、事前確認の失敗、反映先一覧は先頭 20 件と件数）。事前確認の後に別の更新が入った反映先は「競合」として上書きしない。失敗・競合があっても残りを続け、「中止」で残りを「未実行（中止）」にする
- 結果は反映先ごとに 成功 / 失敗 / 競合 / 反映されたか不明（応答が届かず、読み直しても分からない） / 未実行（中止） を表示し、一部成功は警告色

#### 一括ダウンロード

- アクセスできる全アプリ（ゲストスペースIDを入れたときはそのゲストスペースの全アプリ）の JS/CSS 添付（FILE 形式）を本番設定から一括 ZIP 化（ゲストスペースIDは一括ダウンロード欄の指定のみを使用し、数値のみ受け付ける）
- ZIP の manifest.json に、アプリごとのフォルダ名・適用範囲（scope）と、各ファイルの ZIP 内パス（ファイル名は使えない文字・`..`・Windows 予約名・大文字小文字だけの重複を避けて安全化し、元ファイル名は name に残す）・読み込み枠（desktop / mobile × js / css）・元ファイル名・fileKey・サイズ、取得に失敗したアプリ／ファイルを記録。URL 形式は、ZIP にファイルを入れず、manifest.json の urlEntries（読み込み枠・URL・読み込み順）と INDEX.md の一覧に記録する
- 一部の取得に失敗した場合は ZIP に download_errors.txt を含めて警告表示。取得できたファイルが 0 件で失敗がある場合は ZIP を作らず、失敗の内訳をログに表示

### 5. ER図

`ER図.js` は、起点アプリから関連アプリを辿って ER 図を作ります。

#### ER図

- 起点アプリ（既定は開いているアプリ。カンマ区切りで複数、「詳細設定…」の追加起点も可）から関連アプリを探索
- ルックアップ / 関連レコード一覧 / アプリアクションを辿って ER 図生成
- プリセット（直接の関連（深さ1）・周辺（深さ2）・逆引きあり・すべて辿る・スペース全体）で、探索の深さ・表示密度・レイアウト・逆引きをまとめて設定
- スペース ID 指定でスペース内全アプリを起点に追加（スペース所属アプリは二重枠で表示）
- 「スペース内アプリを読込」で一覧を取得し、アプリ名・ID で絞り込んで起点にするアプリだけを選択。選択件数は確認画面にも表示し、スペース ID や接続先を変えると古い一覧は破棄
- レイアウト指定
- 表示密度指定
- 探索深さ指定
- アプリ検索の「環境内の全アプリ」→「候補 N 件をすべて起点にする」で、全アプリを起点にした ER 図を作れる（起点の入力欄を置き換え、ゲストスペースIDも候補に合わせる）。確認画面の起点は件数と先頭 20 件、状態表示は先頭 5 件と件数で示す。50 起点以上では時間と図の大きさの注意を表示
- 設定の読み取りは、同時に 4 アプリまで並行して行う（1 アプリあたり項目・アプリ情報・アクションの 3 リクエストを並べて送る）。結果の並び・深さ・関連は 1 アプリずつ読んだときと同じ。「中止」すると、読み取りを終えたアプリの数と、中断した・読んでいないアプリの数を示す（図は生成しない）。1 リクエストが 60 ms かかる合成 API で 300 アプリを走査すると、約 43 秒が約 12 秒になる
- 逆引き探索（全アプリを走査して、起点を参照するアプリも辿る）。走査中に設定を読み取れなかった（取得失敗・一部取得の）アプリがある場合は、完了メッセージを警告表示にし、図の上部の「逆引き走査」表示とエクスポートの注意書きで、それらを参照する関連が含まれない可能性を示す
- サブテーブル項目の含有切替
- 設定JSON・ZIP から作る（任意。「詳細設定…」の「設定JSON・ZIP から作る」）: 「設定取得」で保存した設定JSON（「設定をZIPで保存」の ZIP も可。ZIP の読み取りはブラウザの中だけで行う）を読み込むと、kintone に問い合わせず、ファイルにあるアプリの設定（フィールド設定・アプリ情報・アクション設定）から図・HTML・仕様書 Markdown・Mermaid・関連一覧 CSV を作る。読み込むと起点を読み込んだすべてのアプリにする（起点・探索の深さ・逆引きはあとから変えられる。逆引きは読み込んだアプリの中から探し、スペースIDは読み込んだアプリ情報のスペースで探す）。読み込んだ中に無い参照先は「未取得の参照先」になる（取得失敗にはしない）。フィールド設定の無いアプリは取得失敗、アプリ情報・アクション設定の無いアプリは一部取得として理由を示し、読み込んだときにも注意を出す。接続先と本番／プレビューは読み込んだ設定のとおりで、「プレビュー環境を参照」は使わない。生成した HTML の見出しには「設定JSONから作成（取得日時 取得）」と接続先を出し、いま開いている kintone のホストは出さない（取得・関連サマリーの「取得元」にファイル名を、印刷・Markdown にも取得元を出す）。設定JSONはキーを並べ替えて保存されているため、カードの項目の並びはフィールドコードの順になる。読み込んでいる間は 1 画面目に「設定JSON「…」の N アプリから作ります（kintone に問い合わせません）」と出し、確認画面の「取得元」にも示す。「読込解除」で kintone から読む動作に戻る（既定は今までどおり kintone から読む）
- 生成する HTML は、描画ライブラリ（Cytoscape.js・Dagre・cytoscape-dagre の固定版）を中に埋め込んだ自己完結のファイルで、ネットワークに接続できない環境でも開ける（CDN は使わない。同梱するライブラリの著作権・ライセンス表記は残している）。「ER図を開く」の画面、保存した HTML、図の画面の「出力 → 編集済みHTMLを保存」で保存して開き直したファイルのすべてで同じ。ブラウザの制限などで描画ライブラリを初期化できないときだけ、取得済みアプリの一覧の表を出す。同梱により HTML は約 0.67 MB 大きくなる
- 安全: 図の HTML は kintone の画面から開くと kintone と同じオリジンで動くため、CSP で通信・外部の読み込み・フォーム送信・`<base>`・frame を禁じ、スクリプトは HTML に埋め込んだもの（描画ライブラリ・起動・図の本体）だけを内容のハッシュで許可する（`'unsafe-inline'` を使わない）。ボタンなどの操作はイベント属性（`onclick` など）を使わないため、アプリ名などの文字列が HTML として差し込まれても、イベント属性・`javascript:` の URL・script は動かない。編集済みHTMLを保存・開き直し・保存し直ししても、同じ CSP のまま動く（編集の状態は実行しない JSON として入れる。以前の版で保存した編集済みHTMLも、そのファイルのまま開け、「編集 → 編集済みHTMLから取り込む」で今の図へ取り込める）
- 関連（線）の詳細として、ルックアップは「参照先のどのフィールドをどのフィールドへコピーするか」と取得時の絞り込み条件、関連レコード一覧は表示するフィールドと絞り込み条件、アプリアクションは「どのフィールドを起動先のどのフィールドへコピーするか」と実行条件を持つ。図の詳細パネル・線へのマウスオーバー、出力の Markdown（関連の表の「コピー・表示するフィールド」「絞り込み条件」の列）・関連の CSV（同名の 2 列）・JSON（`copyFields`・`displayFields`・`filterCond`）、パネルの「仕様書をMarkdownで保存」「関連一覧をCSVで保存」に出る
- 検索は、アプリ名・ID と、取得済みの全項目の名前・コードを対象にする。図の強調・左のアプリ一覧・表のビューに共通で効く。現在の表示密度でカードに出ていない項目で一致したアプリは、一致件数の吹き出しに「うち N 件は図に出ていない項目」と示す（表示密度を「詳細」にすると項目を確認できる）。表示範囲の外で一致したアプリは、検索欄で Enter を押すと、そのアプリのまわりを表示して移る
- 取得に失敗した（一部取得を含む）アプリの理由は、kintone の応答の文だけを、構造チェック・アプリの詳細・出力の「取得上の注意」に示す（内部の通信情報の行 `[API] GET …` は出さず、実行ログ（console）にだけ残す）
- 保存形式は HTML、仕様書 Markdown、Mermaid、関連一覧 CSV。ファイル名には起点アプリ・環境・日時が入る（Mermaid は日本語のフィールドコードでも描画できるよう、項目名を `field_1` などにして実コードと表示名を注釈に入れる）
- 図の画面（生成した HTML）の構成: 上部はタイトル（対象の起点アプリ・取得日時・接続先・取得と関連の要約）、検索、表示の切り替え（図 / アプリ一覧 / 関連一覧。Alt+1〜3）、「表示設定」（表示範囲・配置 6 種・関連のないアプリを下にまとめる・カードの項目の量・シンプル・関連線の種類・線のまとめ・線のラベル・選んだアプリの強調・経路探索・ミニマップ・フルスクリーン）、「編集」（アプリ・項目・関連線・メモの追加、名前と枠の色の編集、固定、図からの削除、そろえる・色分け、戻す、元に戻す）、「出力」、配色の切り替え、ヘルプ（コマンドパレット Ctrl+K もここから開ける）。左はアプリ一覧（構造チェックの要約、状態・参照する／される数、表示範囲の内外。押すと図でそのアプリへ移る）、右は選んだアプリまたは関連線の詳細。幅 1023px 以下では左の一覧を引き出しに、640px 以下では詳細を全画面にし、操作は「⋯」にまとめる
- 開いた直後の表示範囲: 起点アプリがあり、アプリが 15 を超え、起点とその直接の関連先に絞ると 4 分の 3 未満に減るときは「起点まわり」で開く（全アプリを起点にした図などは全体で開く）。図の左上の帯で「全体を表示」「起点まわり」と深さ（1: 直接の関連先 / 2: 関連先の関連先）を切り替えられる。アプリをダブルクリックするか、詳細の「このアプリのまわりを表示」で、そのアプリのまわりだけを表示する。図の外のアプリを左の一覧・表・検索・コマンドパレットで選ぶと、そのアプリのまわりへ移る。一度表示した範囲は位置を覚えていて、戻ると同じ配置に戻る（配置の種類を変えると配置し直す）。「〇〇のまわり」は、配置が「階層」のとき、中心のアプリを真ん中に、それを参照するアプリを左、それが参照するアプリを右に並べる
- 関連線: 同じアプリの組・同じ種類の線は 1 本にまとめ、本数を太さと吹き出しで示す（表示設定でやめられる）。まとめた線を押すと、まとめた関連線をすべて詳細に並べ、そこから個別に編集・削除できる。線の名前は、選んだ線・マウスを乗せた線・選んだアプリの線にだけ出す（「線のラベルを常に表示」で全部に出す）
- 表のビュー: 「アプリ一覧」は App ID・アプリ名・スペース・項目数・参照する数・参照される数・状態（取得失敗・一部取得は理由も）を表にし、見出しで並べ替え、表示するアプリ（表示中・起点・手動追加・図から削除）と構造チェック（取得に注意・循環候補・自己参照・関連なし・未取得の参照先あり）で絞り込める。「関連一覧」は種類・参照元アプリと項目・参照先アプリと項目・コピーまたは表示する項目・絞り込み条件を表にし、種類（ルックアップ / 関連レコード一覧 / アプリアクション）と状態（参照先が未取得・自己参照・絞り込み条件あり・手動追加・図から削除）で絞り込める。行の「図で見る」で、図のそのアプリ・その線（まとめた線なら代表の線）へ移る。640px 以下では 1 行を 1 枚のカードにして、列名を各値の前に出す
- 配色は明るい配色が基本で、開いたときは OS の設定（prefers-color-scheme）に従う。切り替えボタンはこの画面を開いている間だけ有効で、編集済みHTML・共有 URL には保存しない
- アプリは見出しと項目行を分けたカードで表示する。項目には PK・FK・関連・一意・必須のバッジが付く。縮小時（65% 未満）は、詳細カードと同じ大きさの枠にアプリ名を大きく描いた概要カードに切り替わる（縮小してもアプリ名が読め、倍率を変えても配置が重ならない）。起点アプリには「起点」の印を付ける（起点がアプリの半分以上の図では付けない）。取得失敗（⚠）・一部取得（△）・未取得の参照先（？）・関連なしは、色だけでなく文字でも示す。階層配置で1階層のアプリが多い場合は複数列に、階層が多く横に長い場合は複数段に折り返す。フォース・同心円・グリッドなどで配置後にカードが重なったときは、重ならなくなるまで押し広げる（縮小時の概要カードの大きさも含めて重ならないようにする。固定したアプリは動かさない。800 アプリを超える図では行わない）。アプリを選ぶと周辺が強調されるが、PNG・印刷には強調や選んだ線を残さない
- 図の画面の「出力」からは PNG（白背景で起点・接続先・日時・表示範囲・凡例を含み、表示倍率によらず項目入りのカードで、表示中の範囲を描く）、印刷、Mermaid、draw.io、PlantUML、SQL DDL（MySQL 形式。テーブル内のルックアップや外部キーにできない関連は理由をコメントで示す）。Markdown 仕様書には Mermaid の ER 図を埋め込む（4万字を超える図は省略）、JSON、Markdown、CSV を保存できる
- 印刷（「出力 → 印刷」・Ctrl+P・ブラウザの印刷）は、画面のスクリーンショットではなく資料にする: 見出し（対象の起点・取得日時・印刷日時・接続先・取得状態・アプリと関連の数・図の表示範囲）、図（表示中の範囲の画像）、アプリ一覧、関連一覧（A4 横）。図の画像は印刷するときだけ作り、印刷のあとに消す
- 編集済みHTML: 手動の追加・名前や色の変更・メモ・位置・図からの削除・固定・隠した項目・関連線の種類の表示・表示範囲（とそれぞれの位置）を保存し、開き直すと戻す。以前の版で保存した編集状態（表示範囲を持たない形式）も読み、全体の表示で保存時の位置に戻す（以前の版で既定だった「線のラベルを常に表示」は引き継がない）
- 編集済みHTMLから取り込む（図の画面の「編集 → 編集済みHTMLから取り込む」・コマンドパレット）: 以前に保存した編集済みHTML（以前の版・今の版のどちらも）を選ぶと、その中の編集（手動で追加したアプリ・項目・関連線、アプリの名前と枠の色、項目と関連線の編集、メモ、位置、図からの削除、固定、隠した項目）を今の図へ当てはめる。新しく作り直した図へ、前に作り込んだ編集を移すときに使う。今の版のファイルは保存したときの表示範囲で、以前の版のファイルは全体で、保存した位置に置く（ファイルに位置の無いアプリは、取り込んだ位置の下に並べる）。関連線は、関連の種類・項目・参照先で今の図の関連と対応させるため、設定が変わって関連の並びが変わった図や、設定JSONから作った図にも取り込める。今の図に無いアプリ・項目・関連線の編集は「対象外」として、件数と図に無いアプリを結果に示す。同じ内容が今の図にあるもの（同じファイルを 2 回取り込んだときなど）は重ねない。表示設定（配置・カードの項目・線の種類・線のまとめなど）は今の図のまま。結果はコピー・ファイル保存でき、「元に戻す」（Ctrl+Z）で取り込む前に戻せる。ファイルの中のスクリプトは実行しない（編集の状態の部分を文字列として読み、形と値を確かめて、知っている項目だけを使う。色は「#」で始まる 16 進の形だけ、名前などは文字として扱う）。64MB を超えるファイルは読まない

### 6. プロセス図

- プロセス管理設定から Mermaid フロー図を生成
- Mermaid ソースの表示／コピー／.mmd ファイル保存（lite 版は結果画面の「図のソースを確認する」から操作）。保存した .mmd はアプリID・生成日時のコメント行付きで、Mermaid Live Editor や Markdown に貼り付けて表示できる
- 現在状態はピル表示で、シミュレーション中の遷移を読み上げ対応で通知
- フロー図プレビュー（Mermaid.js を読み込めない・内容を検証できない・描画に失敗した場合は、その理由を示した簡易表示（状態と遷移の表）に切り替え）。コピー・.mmd 保存するソースにはシミュレーション中の現在状態の強調を含めない
- 完了メッセージにステータス数・アクション数を表示し、from/to 未設定のアクションは除外して警告表示
- 操作「複数アプリのプロセス図をZIPで保存」で、表に入れた複数アプリ（アプリ検索の「環境内の全アプリ」で全アプリも可）のプロセス図をまとめて保存する。ZIP には `manifest.json`、一覧の `overview.md`（アプリごとの有効 / 無効 / 取得失敗、状態・アクション数、構造上の注意、Mermaid ブロック）、プロセス管理が有効なアプリの `diagrams/*.mmd` を入れる（SVG は含めない）。「プレビュー環境を参照」も適用する
- プロセス管理が無効なアプリは失敗ではなく「無効」として一覧に残す。取得失敗は理由つきで一覧とログに残し、完了メッセージを警告色にする。「中止」では取得済みの分だけを保存し、残りを「未実行（中止）」と記録する（何も取得できていない・全件失敗のときは ZIP を作らない）
- 通し検証（`npm run test:record-explore`）で、状態 40・アクション 90、分岐・差し戻し・終端が複数、記号や HTML に見える長い名前、同名アクション、プロセス無効、複数アプリ ZIP を確認済み（Mermaid を読み込めない環境の簡易表示では HTML を実行しない）。簡易表示は表のままで、図（SVG）にはしていない
- 状態遷移シミュレーション（最初から開始 → 現在状態から実行できるアクションを選んで実行。「1手戻す」「履歴をコピー」も可）。開始前や終端のステータスで実行を押した場合は理由を表示。プロセス管理が無効なアプリではソースを出力しない
- 「図のソースを確認する」から、プロセス管理仕様書（Markdown）のコピー・保存（状態数・アクション数・始点と終端・分岐などの構造診断、ステータスと作業者、アクションの一覧）と、描画した図の SVG 保存（Mermaid で描画できたときだけ。簡易表示では保存できない理由を示す）
- シミュレーションの作業者設定と仕様書 Markdown の「作業者種別」は、作業者の選び方を kintone の意味で示す（候補から作業者を1人選ぶ・候補のうち誰か1人が作業する・候補の全員が作業する。ほかのツールと同じ言葉）

### 7. 設計書

`設計書作成.js` は 1 つのパネルで、出力の種類（Excel・Markdown・AI向けMarkdown・JSON・コピー・ZIP・設計差分）を操作として選びます。出力の対象は対象アプリ表の 1 行目です（ZIP は全行、設計差分は 1 行目と 2 行目）。

#### 設計書出力

- 設計書 JSON 出力
- 設計書 Markdown 出力
- Markdown コピー
- 設計書 Excel 出力: 「プレビュー環境から取得」に合わせて本番／プレビューの設定を取得する（複数アプリ ZIP も同じ。ZIP の名前と manifest に環境を記録する）。項目定義シートのグループ名はフィールド設定の表示名（コードではない）。グラフの集計 `AVERAGE`（平均）・作業者の選び方 `ANY` も日本語で表示する。取得に失敗した項目は完了メッセージとサマリーシートの「API取得失敗レポート」に残す。出力中の「中止」で取得を止められる
- アプリ検索の「環境内の全アプリ」→「候補 N 件をすべて追加」で全アプリを対象アプリ表に入れ、「全対象をExcel ZIPで保存」で全アプリの設計書をまとめて保存できる（単一出力は表の 1 行目のまま）。50 アプリ以上では時間とメモリの注意を確認画面に表示
- 設計書 HTML 出力（「ほかの操作…」の「HTML設計書を保存」「全対象をHTML ZIPで保存」）: 1 つの HTML ファイルで、ブラウザだけで読める設計書を保存する。中身は Markdown の設計書と同じ組み立て・同じ言葉（下の「HTML 設計書の構成」）。kintone から取得するときも、設定JSON・ZIP を読み込んだときも使える（読み込んだときは kintone に問い合わせず、見出しの「取得元」に「読み込んだ設定JSON」と出す）。複数アプリの ZIP には、アプリごとの HTML と、各設計書へのリンクと取得の結果をまとめた `overview.html`、`_manifest.json`（`htmlFile`）を入れる（ZIP を展開してから `overview.html` を開く）
- 機微な値: 設計書の Markdown・AI向けMarkdown・HTML には、設定JSON由来のプラグインの設定値（`_config`）と JS/CSS ファイルの本文（`_bodyText`）を、原文 JSON にも載せない（kintone から直接取得した場合と同じ）。AI向けMarkdown には「除外した補助情報」として件数を書く。設計書 JSON は設定の写しなので従来どおり含める。Markdown・HTML の設計書は JS/CSS 本文・プラグインの設定値を kintone から取得しない（本文の取得失敗でセクションが取得失敗にならない）
- 設定JSON読込（任意）: 「設定一括取得」で保存したJSON、または「設定をZIPで保存」で保存したZIP（`manifest.json` にあるアプリごとの設定JSONをその順に読む。JS/CSSファイル本体は読まない。ZIPの読み取りはブラウザの中だけで行い、通信しない）（複数アプリの `apps` 配列にも対応）を読み込むと、kintoneへ接続せずそのJSONの内容だけから設計書（JSON / Markdown / Excel / HTML いずれも）を生成できる。読み込んだアプリは対象アプリ表に入る（「読込解除」で、読み込んだ設定を使わず kintone から取得する状態に戻す）。複数アプリ一括Excel出力（ZIP）でも、対応する設定JSONが読み込まれているアプリはAPI取得をスキップする。比較元・比較先を持つ差分用の JSON（`source`・`target`）は、設計差分で比べる対象アプリ表の1・2行目に入れる（開いたアプリなど、それまでの行は後ろに残す）。設定JSONに含まれないセクションは「取得失敗」として設計書に記載し、完了メッセージにも残す。アプリIDの無い設定や同じアプリIDの重複は読込時に警告する。ZIP は一部のアプリが失敗しても残りを保存し、成功／失敗件数を完了メッセージと manifest に記録する。

#### Markdown 設計書の構成

- 先頭にアプリID・アプリ名・ゲストスペース・取得環境（本番／プレビュー）・取得日時（ISO 形式には日本時間を併記）・取得できなかったセクションをまとめた表
- 目次、件数サマリー、確認ポイント、セクション一覧のあとに各セクションの表を出力
- フィールド表は「参照先/制約」列でルックアップの参照先アプリ（「顧客マスタ（App 302）」のように名前とID。名前は kintone から読み取るか、設定JSONから作るときは読み込んだJSONから引く。読めなければIDだけ）とキー、関連レコード一覧の参照先アプリと条件、単位・桁区切り・文字数や値の範囲、初期値（現在日時）などを表示。テーブル内フィールドも同じ列を持つ
- 取得に失敗したセクションは「0件」と読み違えないよう、本文に「取得できませんでした」と理由を書き、件数欄も「取得失敗」にする（理由は kintone の応答の文だけ。内部の通信情報の行 `[API] GET …` は本文・取得状態の表に出さず、生データにだけ残す。Excel・HTML も同じ）
- 「出力セクション」の件数は「取得状態」の件数と同じ数え方（件数の定義が無いアプリ設定などは「-」）。サマリー・確認ポイントのルックアップ数・必須フィールド数・関連レコード一覧数は、テーブル内のフィールドも含めて Excel の設計書と一致させる
- ルックアップは転記（コピー先 ← コピー元）の一覧、関連レコード一覧は表示フィールド、アクションは連携先アプリ（名前とID）、コピー項目（コピー元 → コピー先。レコードのURLを含む）と実行条件を表に出す。プラグイン表は有効状態、カレンダー一覧は日付・タイトルのフィールドと PC 版のみの表示、グラフは分類の期間（月など）と、フィールドを持たない集計（件数）を出す。作業者の選び方 `ANY`（候補の誰でも）も日本語にする。レイアウトのグループ名はフィールド設定の表示名から出し、名前が無い見出しには「 — 」を付けない
- フィールド名・選択肢・計算式などに含まれる `|`・`<`・`*`・改行は Markdown が崩れたり HTML として解釈されたりしないようエスケープする
- 各セクション末尾の API レスポンス（生データ）は折りたたみで付属

#### HTML 設計書の構成

- 見出し: アプリ名、アプリID、ゲストスペースID、取得環境、取得日時、取得状態（「基本設定18種：完了」、または「未完了」と取得失敗・部分取得・未取得の件数）、取得元、作成日時、取得できなかったセクション。取得できていないセクションがあるときは、理由（1 行目。内部の通信情報の行 `[API] GET …` は出さない）と「取得できていない設定の値は、0件や無効を意味しません」を示す
- 取得状態（全セクションの状態・件数・詳細）、サマリー（件数）、確認ポイントのあとに、Markdown と同じ順・同じ見出しで各セクションを出す。表の列・値・言葉は Markdown と同じ（フィールドの種別・必須・重複禁止・初期値・選択肢/式・参照先/制約、ルックアップ・関連レコード一覧の参照先アプリ名とコピー項目、テーブル内のフィールド、一覧・グラフ・プロセス管理・権限・通知・アクション・プラグイン・JS/CSS・カテゴリー）。レイアウトは、Excel の「フォームレイアウト」と同じくフィールド名・種類・幅・必須も並べ、行・グループ・テーブルを枠で示す。フィールド権限の見出しにはフィールド名も添える
- 取得に失敗したセクションは「⚠ 取得できませんでした: 理由」、部分取得・空・整形表示の無いセクションも Markdown と同じ文で示す。各セクションの末尾に「APIレスポンス（生データ）」を折りたたみで付ける（印刷には出さない）
- 目次: 左に固定（基本・プロセス・カスタマイズ・連携・権限・通知・その他に分け、件数と取得失敗などを示す）。読んでいるセクションを強調する。幅 1023px 以下では「目次」ボタンで開く引き出しにし（`Esc`・×・背景で閉じて、開いたボタンへ戻る）、640px 以下では表を 1 行 1 枚のカードにする
- 絞り込み: 上部の「フィールド名・コードで絞り込み」で、フィールドの表（テーブル内を含む）を絞り込む。全角・半角、大文字・小文字を区別しない。空白で区切ると、すべてを含む行だけを出す。件数（一致 N / 全 M 件）を示し、`Enter` で最初の行へ移り、`Esc` で解く
- 印刷（「印刷」ボタン・ブラウザの印刷）: 目次と操作の部品・原文を出さず、見出し（印刷日時を含む）と各セクションの資料にする（A4 横。表の見出しはページごとに繰り返す。対応するブラウザでは各ページの上にアプリ名、下にページ番号を出す）。絞り込み中でも全件を印刷する
- 配色: 明るい配色が基本で、開いたときは OS の設定に従う。「暗い配色／明るい配色」ボタンの切り替えは開いている間だけ（保存しない）
- 安全: kintone の設定の文字列はすべて文字として出す（HTML・スクリプトとしては動かない）。CSP で通信・外部の読み込み・フォーム送信を禁じ、埋め込んだスクリプトとスタイルを 1 つずつ内容のハッシュで許可する。ブラウザストレージは使わない。プラグインの設定値と JS/CSS ファイルの本文は、Markdown と同じく原文にも載せない（kintone から作るときは取得もしない）。スクリプトが動かない環境でも本文・目次は読める（絞り込み・配色の切り替え・目次の引き出しだけが使えない）

#### 差分レポート

- 比較元と比較先の設計書差分を Markdown レポートとして出力
- 先頭に比較方向（比較元＝追加・更新後の姿、比較先＝現在の設定）、アプリ名・環境、追加／削除の行数を表で示し、「見方」とセクション別の追加・削除件数の表を付ける
- 差分は生データ JSON と取得日時を除いた設計書の表・要約で比較するため、変更点を読み取りやすい。本文は変更行の前後 3 行だけを残し、離れた変更の前に `@@ セクション名（省略 N 行）@@` を入れる（業務アプリ規模でも変更が埋もれない）。追加・削除の件数は全体から数える。生成日時は読める形（`2026-11-09 22:00:00`）厳密な差分は差分比較ツールの HTML / Excel を使う

### 8. 設定一括取得

`設定取得.js` は、対象アプリ表のアプリの設定をまとめて JSON・ZIP に保存します。

#### 一括取得

- 複数アプリ ID をまとめて指定（各行の「↑コピー」「複製」で行を作れる）
- アプリ名検索から追加。「環境内の全アプリ」→「候補 N 件をすべて追加」で全アプリを対象アプリ表に追加（追加済みは重複させない）
- 「スペースから追加」でスペース ID を入れ、スペース内の全アプリを一括追加（アプリが無いスペースは理由を表示）
- 「現在のアプリ」の追加
- 取得対象セクションの選択（プリセット「すべて」「基本のみ」「権限のみ」「通知のみ」「カスタマイズのみ」。1 項目ずつは「詳細設定…」）
- JSON 出力
- 機微な値: 確認画面に「プラグインの設定値: 含める（API キーなどの機微な値を含む場合があります）」と「JS/CSSファイルの本文: JSON に含める」を示す。詳細設定の「機微な値の扱い」で「プラグインの設定値を含めない」を選ぶと、プラグインの一覧（ID・名前・有効状態）だけを保存し、設定値は取得しない。含めなかったことは、プラグインのセクションの `_partial`（種類 `pluginConfigOmitted`）、JSON の `pluginConfig`、ZIP の manifest.json の `pluginConfig`・アプリごとの `omittedPluginConfigs`、INDEX.md、結果表に記録する（取得失敗には数えない。既定は従来どおり含める）。この JSON を差分比較に読み込むと、プラグインは一覧だけを比べ、設定値は「一部未検証」として示す。プレビュー反映・本番反映の反映元にした場合は、従来どおりプラグインの追加だけを行う（固有の設定値はもともとコピーしない）
- ZIP 出力の manifest.json には取得環境・セクション一覧に加え、アプリごとのファイル名・アプリ名・ゲストスペース・取得日時・成功／失敗セクション（失敗理由つき）を記録
- ZIP 出力
- 結果表にアプリごとのアプリ名と取得 OK / NG のセクション数を、完了メッセージに全体の件数（保存したアプリ数、取得に失敗したアプリ数とセクション数）を表示
- 結果表の各アプリの下の「内容:」の行、ZIP の INDEX.md の「内容」列、manifest.json と JSON の `summary` の `counts` に、アプリごとの設定の中身の件数（フィールド（テーブル内）・一覧・グラフ・プロセス管理の有効/無効とステータス数・アクション・プラグイン・JS/CSS・通知）を出す。開かずにどのアプリか・規模を確かめられる。数え方は設計書の「取得状態」と同じで（フィールドはシステム項目を含む）、取得に失敗した・取得しなかったセクションは数えない
- 一部のアプリを取得できなかったとき（取得に失敗したセクション・JS/CSSファイルがある、または中止で未実行）は、結果画面の「取得できなかったアプリだけを対象に残す」で、対象アプリ表をそのアプリだけ（ゲストスペースIDと表のアプリ名も残す）にして最初の段階へ戻り、取得する設定を確かめて取り直せる。本文がサイズ上限などで省略されただけのファイルは、取り直しても同じなので対象にしない。全アプリを取得できたときは表示しない
- 単機能版の結果表のメモには、失敗したセクション名（アプリ全体が失敗した場合は最初の失敗理由）と、サイズ上限などで本文を取得できず fileKey のみ記録した JS/CSS ファイル数を表示
- 単機能版の「設定とJS/CSSファイルをZIPで保存」は、設定の ZIP に JS/CSS 設定のファイル本体（FILE 形式。URL 形式は含まない）を、アプリごとの `アプリ名(appID)_本番_JS_CSS/` フォルダに入れて保存する。取得する設定に「JS/CSS設定」が必要
- フォルダの分け方と読み込み順は「詳細設定…」で別々に選ぶ。フォルダ分け: PC/モバイル・JS/CSS別のフォルダ（`desktop/js/main.js`、既定）／フォルダを分けない（`main.js`）。読み込み順: 付けない（既定）／ファイル名の先頭に付ける（`desktop/js/01_main.js`。フォルダを分けない場合は枠も付けて `desktop_js_01_main.js`）。同じフォルダの同名ファイル（大文字小文字の違いを含む）は `_2` などを付けて上書きしない
- 取得できなかったファイルは理由を結果表のメモと manifest.json（`customizeFiles`。ZIP 内のパス・枠・読み込み順・fileKey・失敗理由）に記録し、残りのファイルと設定は保存する。ファイルの取得中に中止したアプリは保存せず「未実行（中止）」にする

### 9. レコード管理

`kintoneレコード取得.js` のレコード管理は、タブで操作を選びます（CSV出力・CSV取込・CSVひな形・データ検査・ステータス・添付DL・コピー・バックアップ）。CSVひな形とデータ検査は [データ検査とCSVひな形](../docs/record-quality-and-template.md) を参照してください。CSV 出力だけの `CSV出力.js` と、データ検査だけの `データ品質チェック.js` もあります（どちらも読み取り専用）。

対象アプリ欄には、アプリ検索の「環境内の全アプリ」→「候補 N 件をすべて対象アプリにする」で全アプリを入れられます（入力欄を置き換え、ゲストスペースIDも候補に合わせます）。確認画面の対象アプリは件数と先頭 20 件で示し、CSV取込の最終確認も先頭 20 アプリと件数にまとめます。「7」と「07」のように先頭の 0 だけが違うアプリIDは同じアプリとして 1 つにまとめます（同じアプリへ 2 回書き込まないため）。添付ファイル保存とバックアップは、アプリごとに別の ZIP を保存します。データ品質チェック（`データ品質チェック.js`）の対象アプリ欄も同じ操作で全アプリにできます（検査項目は先頭の対象アプリから読み込むため、その項目が無いアプリは検査失敗として表示します）。

#### ステータス更新

- 一覧条件に一致するレコードのプロセス管理を一括実行
- 複数アプリで確認画面をキャンセルしたアプリは、完了扱いにせず「実行していません」と最終メッセージに表示します（ステータス更新・コピー）。
- ステータス更新とアプリ間コピーはアプリごとに確認ダイアログを表示するため、一度に指定できるのは 50 アプリまでです（超える場合は確認画面へ進まずに理由を表示します）
- 追加・更新が100件単位の途中で拒否された場合は、確定済み・未処理の件数に加え、kintone が返したレコード（CSV取込は行番号、ステータス更新・コピーはレコードID）とフィールド名［コード］別の理由を表示します（テーブル内のフィールドは「明細［items］2行目・数量［qty］」）。ステータスには先頭 3 件と「ほか N 件」を、結果ログには全件を出します（塊の中の位置で数えた「50件目」のような行は出しません）。
- CSV取込・コピーのレコード追加は、応答が届かなかった（通信エラー・タイムアウト）ときに自動で再送しません（サーバー側で確定していると二重に登録されるため）。その塊が書き込まれたかどうか確認できない旨と、再実行する前に kintone で件数を確認する案内を表示します。kintone のエラー応答（エラーコード）が無い失敗（中継装置のエラーページや JSON のエラーなど形の分からない失敗。要求ID（id）や errors だけでは kintone の拒否と見なしません）も、書き込まれていないとは言い切らず同じ案内を出します。
- ステータス更新も、応答が届かなかった塊（通信エラー・タイムアウト・5xx）を自動では送り直しません（確定していた場合、送り直すと進んだ revision と食い違い、実際は更新済みなのに「revision 競合」と表示していたため）。その塊が書き込まれたかどうか確認できない旨と、再実行する前に kintone でその塊のレコードのステータスを確認する案内を表示します。条件にステータスを含めて再実行すると、進んだレコードは対象に入りません。
- 応答が届かなかった塊は、位置（「101～200件目」）に加えて、その塊の最初と最後の行・レコード（例「この塊の 100件: CSV 102行目 〜 CSV 201行目」「レコードID 101 〜 レコードID 200」）を示し、kintone で何を確かめればよいかが分かるようにします。

#### 添付DL

- 一覧条件に一致する添付ファイルを ZIP で一括ダウンロード
- ZIP が約 2GB（またはファイルとフォルダの合計が約 65,000 件）を超えるときは、取得を始める前にレコード単位で分け、`…_part1.zip`・`…_part2.zip` のように 1 つ分を取得するたびに保存します（1 レコードの添付は同じ ZIP に入ります。10 個以上のときは `_part01` と 0 埋め）。各 ZIP の `manifest.json` の `split` に、分割したこと・ZIP ごとのレコード範囲・保存数・失敗数・未保存数を書きます。
- 1 ファイルで ZIP の上限（4GB 未満）を超える添付は取得せず、その 1 件だけを「ZIP の上限で保存できなかった添付」として理由つきで `download_errors.txt`・`manifest.json`（`unsaved`）・完了メッセージ（警告色）に残して続けます。保存できた添付がまだ 1 件も無い間の ZIP は作らず、記録を次の ZIP へ持ち越します。「中止」では、保存済みの ZIP を示し、中断した ZIP 以降は保存しません。
- ZIP を複数ダウンロードしたとき（分割・複数アプリ）は、完了メッセージに依頼した ZIP の数と名前を示します。ブラウザの許可確認が出たら許可し、ダウンロード一覧の数と照らし合わせてください。

#### CSV

- 一覧条件に一致するレコードの CSV エクスポート（ヘッダーはフィールドコード・フィールド名・「フィールド名 [コード]」、改行は LF・CRLF から選択）
- CSV ファイルからの一括インポート。「CSVを事前検査」で、書き込む前に全対象アプリについて列・必須・選択肢・数値の形式と範囲・文字数・日付／時刻／日時の形式（存在しない日付 2026-02-30 や 13 月・25 時も）・CSV 内の重複を調べる
- 作成者・更新者・作業者はユーザーコード、分類は「,」区切りで出力します。ラベル・スペース・罫線・グループ・関連レコード一覧は値がないため列を作りません。
- 複数アプリで一部が失敗した場合や、閲覧権限などで取得できなかったテーブルがある場合は、成功分を保存したうえで、失敗したアプリと未取得のテーブルの内訳を CSV出力パネルの結果欄にも表示します（ZIP 内の manifest にも記録）。
- エクスポート CSV のうち = + - @（全角を含む）で始まる文字列セルは Excel の数式実行を防ぐため先頭に ' を付けます（数値は対象外）。ZIP 出力の manifest.json notes にも記載します。

#### バックアップ

- 一覧条件に合致するレコードを CSV・添付ファイル・コメント込みで ZIP バックアップ
- 必要に応じてアプリ設定 JSON も同梱（「アプリ設定も保存」を選んだ場合は保存範囲を1つ以上選ぶ必要があります）
- 添付が ZIP の上限に近づくときは、添付だけの ZIP（`…_part1.zip` …）に分け、レコードの CSV/JSON・コメント・設定と全体の `manifest.json`（`split`・全体の保存数・取得失敗・保存できなかった添付）は最後の ZIP に入れます。最後の ZIP が保存されていれば、バックアップは最後まで終わっています。「中止」したときは、保存済みの ZIP は添付の一部で完全なバックアップではないことを示します。

#### アプリ間コピー

- コピー元アプリの条件に合うレコードを、対象アプリへ新規レコードとして一括コピー
- コピー先に必須のフィールドがあり、コピー元から値が入らず初期値も無いとき（すべてのレコードが kintone に拒否される）は、確認の前に対象フィールドを示して止めます（事前確認にも表示）。
- コピー先に一致するフィールドが1つも無い場合は空レコードを作らないよう実行を止めます。コピー先のテーブル内でも、型が違うセルは除外して一覧に表示します。
- 実行確認画面に添付フィールドのコード一覧と添付ありレコード件数を表示します（添付はコピーされないため、必要な場合は手動で再アップロードしてください）。

## 推奨利用フロー

典型的な使い方は以下です。

1. 差分比較で、比較元（開発・検証）と比較先（本番）の設定差分を確認する
2. プレビュー反映で反映元・反映先を選び、差分確認（反映計画）を確かめる
3. 反映先のプレビューへ反映する
4. 本番反映で、プレビューの未公開の変更を確認してバックアップを取り、本番へ反映する（アプリの設定画面で「アプリを更新」してもよい。別アプリの設定を選んで本番まで反映するときは、本番反映の「反映元アプリから本番へ」）
5. 設計書や差分レポートを出力して記録を残す

## 注意事項

- 反映系処理は反映先のプレビュー、本番の設定（本番反映）、または本番のレコード（レコード管理）へ影響します
- CSV 取込、ステータス更新、アプリ間コピーは実データ変更を伴います
- 反映前にバックアップを取得する運用を推奨します
- ルックアップ、添付ファイル、プロセス関連の移送は環境差異の影響を受けやすいです
- プラグイン設定はプラグイン本体の配布や個別設定内容までは含まれない場合があります
