# kintone lite ツール群 機能説明

対象: `tools/*.js` の単機能liteバンドル

## 概要

このドキュメントは、共通ソースから生成するkintone向けliteツール群の機能仕様をまとめたものです。廃止済みの `tools/統合ツール.js` を読み込むのではなく、目的に応じて `tools/差分比較.js`、`tools/ER図.js` などの単機能バンドルを使用します。以下の「タブ」は機能分類または各liteパネル内の画面を指し、全機能を1つの画面から起動する構成ではありません。

> SQL 実行は共通ビルドに含まれません。別リポジトリ `kintone-data-utilities` の `kintoneSQL.js` を利用してください。

主な用途は以下です。

- 開発環境と本番環境の設定差分を確認する
- 比較元の設定を比較先のプレビュー環境へ反映する
- プレビューの未公開の変更を確認し、バックアップを取ってから本番へ反映（または変更を中止）する
- フィールドや JS/CSS 設定を個別に移送する
- 設計書や差分レポートを出力する
- 複数アプリの設定をまとめて保存する
- フィールド参照・通知・権限・レイアウトを横断的に分析する
- レコード運用や可視化作業をまとめて行う

## 外部ライブラリと通信

- ZIP の作成（設定取得・JS/CSS 取得・設計書・レコード管理・データ品質チェック・プロセス図の ZIP 保存）は、ツールに含めた自前の実装で行います。外部から読み込まないため、CDN が遮断された社内ネットワークでも使えます。ファイル名は UTF-8 で、Windows のエクスプローラー、macOS、`unzip`、Python で文字化けしません。ブラウザが対応していれば圧縮し、対応していなければ圧縮なしで保存します。
- ZIP は 1 つあたり 4GB 未満・65,535 件（フォルダを含む）までです。超える場合は壊れた ZIP を作らず、「対象を分けて、もう一度実行してください」とエラーを表示します。
- 設計書の Excel（`設計書作成.js`）も、書き出しに使うライブラリ（xlsx-js-style 1.2.0）を同梱しています。通信しません。
- プロセス図の Mermaid（約 3MB）だけは、固定版（10.6.1）を CDN（jsDelivr、だめなら unpkg）から読み込みます。管理者の kintone の画面で実行されるため、配布物のハッシュ（SRI）が一致しない内容は実行しません。読み込めない・検証できないときは、状態と遷移の表（簡易表示）に切り替えます。

## 基本概念

- 比較元: コピー元、参照元となるアプリ
- 比較先: 差分確認先、反映先となるアプリ
- プレビュー: アプリ設定の未デプロイ領域
- バンドル: 各種設定をまとめて取得した JSON データ
- セクション: アプリ設定の比較単位

比較対象セクションは主に以下です。

- アプリ設定
- フィールド設定
- レイアウト設定
- フォーム設定
- ビュー設定
- レポート設定
- プロセス管理
- プラグイン
- JS/CSS 設定
- アクション設定
- アプリ権限
- フィールド権限
- レコード権限
- 通知設定
- レコード条件通知
- リマインダー通知
- カテゴリ設定

## 共通設定

各liteパネル上部の接続設定は、その機能で利用する比較元・比較先・ゲストスペースを指定します。

### パネルの共通操作

全 lite パネルは `litePanelTheme.ts` の共通基盤で動作し、次の操作を共有します。

- 見出しのバッジは影響範囲を示します。「読み取り専用」（緑）は kintone に何も書き込まないツール、「プレビューへ書き込み」（橙）は反映先アプリのプレビューだけを変更するツール、「本番データを変更」（赤）は本番のレコードを追加・更新するツール、「本番の設定を変更」（赤）は本番のアプリ設定を公開または破棄する本番反映です。文言の基準は [文言ガイド](../docs/ui-writing-guide.md) にまとめています
- 見出し部分をドラッグしてパネルを移動できます。画面外へは出ず、ウィンドウ幅を変えたときも画面内へ戻します。見出しをダブルクリックすると右上の初期位置へ戻ります。パネルを開いたまま同じツールを再度起動したときは、動かした位置を引き継ぎます（「閉じる」で閉じた後やページの再読み込み後は初期位置に戻ります。ブラウザストレージは使いません）
- 見出し右の「－」で本文を折りたたみ、見出しだけを残して kintone 画面を確認できます。「＋」で展開します
- 実行中は見出し右に経過時間（例: 処理中 1分12秒）と見出し下端の進捗ストリップを表示します。閉じるボタンは完了まで無効です。完了後は「前回 1分12秒」として次の実行まで所要時間を残します
- 実行中は見出し右に「中止」ボタンが出ます。押すと「中止中…」になり、実行中のリクエストが終わり次第、次のリクエストの前で処理を止めます。進行中の読み取り（設定取得・ファイル本文）は打ち切りますが、書き込み（POST / PUT / DELETE）は送信済みのものを最後まで待ってから止めます。途中まで書き込んだ内容は取り消さないため、ステータスに「中止しました」と処理済み・未実行の件数を表示し、結果ログで内訳を確認できます。書き込みを 1 件も送っていなければ「書き込みは行っていません」と表示します。実行中に同じツールをもう一度起動した場合は、見えなくなった旧パネルが書き込みを続けないよう、実行中のパネルをそのまま残して案内を表示します（終わるのを待つか「中止」を押してください）
- 読み取りの応答待ちには上限があります（REST API の GET は 120 秒、JS/CSS 本文は 60 秒、ファイル本体は 120 秒）。超えた場合は通信失敗と同じ扱いで再試行し、それでも応答がなければ失敗として表示します。通信が止まったまま「処理中」が続くことはありません
- 結果ログ右上の「コピー」でログ全文をクリップボードへコピーでき、「保存」で `ツール名_ログ_日時.txt` として保存できます
- 入力欄で Enter（テキストエリアは Ctrl/Cmd+Enter）を押すと主アクションを実行し、Esc でパネルを閉じます。キーボード操作中の現在位置は枠線で表示します
- OS の「視差効果を減らす」設定では、アニメーションを止めます
- 1 画面目に出すのは対象アプリ・主要な操作（3 つまで）・取り消せない操作の警告だけです。ふだん変えない設定は「詳細設定…」、4 つ目以降の操作は「ほかの操作…」のポップアップで開き、補足説明はカード見出しの「?」で読めます。ポップアップは Esc・背景クリック・「閉じる」で閉じ、パネル本体は閉じません
- 文字は本文 14px・補足 12.5〜13px を下限にし、補足文の灰色もコントラストを確保した色にしています。3 段階の手順ナビは、現在の段階を濃い青、済んだ段階を緑（左端に印）、これからの段階を灰色で示します
- ゲストスペースのアプリ画面で開くと、既定の対象（現在のアプリ）とアプリ表の「現在のアプリ」にゲストスペース ID も入ります。通常スペースの同じ番号のアプリを指すことはありません
- 「アプリを検索」の「環境内の全アプリ」で、閲覧できるアプリを最後のページまで取得して候補に表示します（検索語とスペースIDは使いません）。複数のアプリを受け付ける入力欄には、候補の上の「候補 N 件をすべて追加」（割り当て先が複数あるときは「…すべて比較先へ」など）でまとめて設定できます。同じアプリIDとゲストスペースIDの組み合わせは重複して追加しません。ゲストスペースのアプリは通常の一覧に含まれないため、ゲストスペースIDを入れてゲストスペースごとに取得します。全アプリを対象にしたときも、確認画面の対象一覧は先頭 20 件と「…ほか N 件（合計 M 件）」で示し、件数は省略しません

### 接続先設定

- 比較元アプリ ID / ゲスト ID / プレビュー指定
- 比較先アプリ ID / ゲスト ID / プレビュー指定
- 比較元を現在アプリに設定
- 比較元の内容を比較先へコピー
- 比較元と比較先の入れ替え

### 環境プロファイル

- 比較元 / 比較先の組み合わせを名前付きで保存
- 開発、検証、本番などの環境切替を簡略化

### ルックアップ参照先アプリ ID 変換

- フィールド反映時に参照先アプリ ID を置換（ルックアップ・関連レコード一覧の両方が対象）
- 変換した場合はアプリコード（`code`）指定を自動的に外し、変換後の ID が有効になるようにします
- 環境ごとにアプリ ID が異なる場合の移送を補助

### 作業履歴

- 作業状態（接続先・選択状態など）をセッション内メモリへ手動保存・復元
- 履歴の個別削除 / 全削除
- ブラウザ再読み込みで消去されます（ブラウザストレージは使用しません）

### 共通データ取得 / クイック実行

- 比較元 / 比較先の共通データを先読み
- 差分比較から反映プラン確認までを連続実行

## タブ別機能

### 1. 差分比較

公開中の `差分比較.js` は単一パネルで比較条件、結果確認、ファイル出力までを完結します。以下は現行 lite 版と、そこから生成する自己完結 HTML レポートの機能です。判定規則と上限の正本は [差分比較ロジック説明](../docs/diff-comparison-logic.md) です。

#### 非フィールド差分の検出精度

フィールド以外のセクションも、エンティティ単位で安定して差分を検出します。

- **ドメイン識別子マッチング**: アプリ権限はエンティティ（type:code）、フィールド権限・レコード権限のエンティティ配列も対象エンティティ、一般通知は宛先エンティティ、レコード条件通知・リマインダー通知はタイトル、遷移アクションは name|from|to の組み合わせで左右をマッチング。並び替えは added/removed の組ではなく moved 行へ集約され、個別の変更は「どのエンティティの何が変わったか」単位で出力されます
- **純粋並び替え検出**: 中身が同一で並びだけ違う配列（レイアウト行など）は moved 行のみで報告
- **moved 統合（LCS）**: 並び替えと追加/削除が混在する配列でも、同一内容が別位置に現れた added/removed ペアを moved 1 行（移動位置「N番目 → M番目」付き）に統合
- **表記ゆれ・空値ゆれの注記**: `"100"` ⇄ `100`、`"true"` ⇄ `true` などの差分は「表記のみ」、空文字 / null / 空配列 / 空オブジェクト同士の差分は「空値の差のみ」と注記。差分行自体は残します
- **改名検出**: フィールドコード変更やビュー / ステータス / 通知などのエンティティ改名を added/removed のペアから推定し「改名候補」として表示。プロセス管理のステータス改名は遷移アクションの from/to 参照カスケードを自動吸収し、改名 1 行に集約
- **客観分類**: 変更種別（追加 / 削除 / 内容変更 / 移動 / 同一）と存在状況（比較元のみ / 比較先のみ / 両方）を分離して表示。重要度や対応優先度は自動判定しません
- **関連設定の表示**: フィールド削除・改名時はフィールド権限・レコード権限等で見つかった参照を、ステータス削除・改名時は参照している遷移アクションを「関連している設定」として表示。業務影響や因果関係の断定ではありません
- **プラグイン取得結果**: プラグインセクション直下の `fetched` / `skipped` / `failed` は設定差分へ数えません。`failed` または `skipped` が1件以上なら、通常の差分ではなく取得不完全の警告として扱い、そのセクションを比較不能にします。現在の設定取得でも、ID欠落や不正な応答で設定を取得できなかった項目は同じ扱いです

#### 比較条件

- 比較対象セクションの選択
- 無視キーの設定
- **よく使う除外**: 「環境固有ID（アプリ・一覧・グラフ・アクション）を比較から除外」を折りたたまずに表示し、比較対象・参照先のApp IDと、一覧・グラフ・アクション自身の内部IDだけを除外。既定はオフで、フィールドコード、一覧条件、アクションの対応付け、プラグインID、独自設定内の一般的な `app` / `id` は比較対象に残します。変更後は再比較が必要で、差分件数・画面結果・Excelへ同じ条件を反映します
- セクション別の順序、監査情報、文言、外観、有効フラグ等を対象にした正規化プリセットの適用
- **比較条件プロファイル**: セクション、無視ルール、正規化、同一行、文字差分、表示密度、左右／上下の比較レイアウトをJSONで保存・読込。アプリID、設定本文、認証情報は含めない
- 無視キーの保存 / 読込
- 比較元 / 比較先バンドルの読込、解除、保存
- **3つの比較方法**: 1件ずつ比較する「1対1比較」、1つの比較元を複数の比較先へ照合する「1対多比較」、複数の比較元と比較先を各行で1対1に対応付ける「ペア一括比較」を切り替えられます。
- **ペア一括比較**: 比較元App ID / Guest ID / 運用・プレビューと、比較先App ID / Guest ID / 運用・プレビューを最大50ペア登録し、登録順に1件ずつ比較します。2列または4列の表をまとめて貼り付けできます。片側欠落、同じペア、比較元または比較先の重複は行番号付きで実行前に表示します。API取得時は同一接続先同士も止めます。途中失敗後も後続を続け、結果表には両側のアプリと環境を残します。成功行ごとにExcelまたはHTMLを保存できます。
- **複数対複数のフォルダ取込**: ペア一括比較で「比較元（変更前）フォルダ」と「比較先（変更後）フォルダ」を選択し、配下の設定JSONを再帰的に読み込めます。一意なアプリ名、次に一意なApp IDだけを自動対応し、曖昧な組み合わせは対応確認表で手動選択します。App ID一致・フォルダ順候補は行ごとの確認チェック、対象外にする行や未使用の比較先も明示チェックで確定し、確認済みペアで現在の表を置き換えます。フォルダ由来の行は設定JSONと接続情報を固定し、同一App IDの旧／新スナップショットを比較できます。不足分をAPIで補わず、左右のキャッシュも共有しません。再読込を始めた時点で旧結果と保存導線を無効化し、読込中の比較も止めます。1回の選択上限は全ファイル2,000件、JSON 500件、JSON合計128MB、1フォルダ50アプリです。
- **環境内の全アプリを比較先にする**: 「アプリを検索」の「環境内の全アプリ」から「候補 N 件をすべて比較先に追加（1対多）」を押すと、1対多比較に切り替えて全アプリを比較先に入れます。既にある比較先と、比較元と同じ接続先（アプリID・ゲストスペースID・環境が同じ）のアプリは除き、件数を表示します。比較先が 100 件を超える場合は、時間とメモリの注意を表示します
- **差分比較の実行 → HTML レポート出力**: 「差分比較を実行」を押すと、比較完了と同時に差分 HTML レポートをダウンロードします（出力ボタンを別途押す必要はありません）。「1対多比較」でも比較先ごとに HTML を自動保存します（比較先が 10 件を超える場合は自動保存せず、結果行または Excel の一括保存から保存します）。「ペア一括比較」はブラウザの複数ダウンロード確認を避けるため、結果行から必要なHTMLを保存します。
- **差分一覧 Excel 出力**: Lite版から保存する `.xlsx` は「比較概要」と「変更一覧」を索引として常設し、「比較概要」（取得状態の注意があるときは「確認できなかった範囲」）の直後に利用者向けの説明シート「このファイルの見方」（シートの構成、確認の手順、各シートの列の読み方、値の表記）を置き、実差分があるAPIだけを `API_01_アプリ一般設定` から `API_20_カテゴリー設定` のAPI別シートへ分けます。対応APIを特定できない差分は `API_99_API未特定` にまとめ、差分がないAPIの空シートは作りません。プラグイン個別設定は `API_10_プラグイン個別設定`、カスタマイズファイル本文は `API_12_カスタマイズ本文` へ分け、プロセスのアクションは `API_08_プロセス管理`、アプリアクションは `API_13_アプリアクション` として混在させません。「設定値詳細」には全実差分の比較元・比較先のAPI原文を同じNo.で収録し、各API別シートから内部リンクで移動できます。取得失敗・一部未検証・件数上限がある場合は「確認できなかった範囲」を概要の直後に追加します。同一行は収録せず、表示専用行はテーブル全体の追加・削除を内包フィールドへ展開する子行だけに限定します。権限・通知・プラグイン・JS/CSS設定を含む実差分は1差分1行で収録します。並び順変更とkintoneの `index` は、意味が確定する設定だけ比較元・比較先を1始まりの「N番目」「M番目」で示します。独自設定の `index`、`no`、`size` は変換しません。設定値詳細は状態・型の専用列を設けず、不存在・undefined・null・空文字を値列へ直接表示します。長文は必要時だけ「長文原文」へ分割します。差分0件でも「変更一覧」に罫線付きの「差分はありません」行を出して保存できます。
- **フォームフィールドの専用表示**: `API_03_フォームフィールド` では「配置 / フィールド名 / フィールドコード / フィールド種別 / 差分プロパティ / フィールド存在 / 設定値存在」を別列にします。フィールド自体の追加・削除は変更前後を「存在」「存在しません」で示し、個別プロパティだけが片側にない場合とは存在列で区別します。テーブルと内包フィールドは親子表示し、配置列に親テーブルの名称とコードを示します。子行はExcelのアウトラインで折りたたみ・展開できます。
- **Excel のレビュー向けレイアウト**: 変更一覧は「No. / 変更区分 / 分類 / 設定対象 / 差分プロパティ / 変更前 / 変更後」の7列です。人が読める名称を優先し、ログインユーザーなどの条件関数、対象種別、`WRITE / READ / NONE`、プロセス作業者方式、フィールド・一覧・グラフ・カスタマイズの列挙値をセクションとパスの文脈に合わせて日本語化します。条件式の引用符内と自由入力は置換しません。変更前は淡い赤、変更後は淡い緑、存在しない側は無彩色で表示します。空欄や比較対象が存在しない側を含め、すべての表の全行・全列へ同じ細い淡色の四辺罫線を適用し、強調は背景色と文字色で行います。シート・行・列を非表示にせず、セル数式と外部リンクも生成しません。概要には完全性、「変更対象一覧」と同じ対象単位の変更対象件数、機能別の差分明細件数、比較条件、掲載範囲を表示します。重要度・影響度や対応要否は自動判定しません。
- **Excel の一括保存**: 1対多比較とペア一括比較では、「Excelをまとめて保存（N件・ZIP）」からExcelを1つのZIPで保存します。先頭の `000_一括比較結果.xlsx` でExcel生成対象の結果、差分内訳、アプリ名の不一致、個別Excel名を確認でき、個別Excelは登録順の番号と短い業務名で命名します。差分0件と取得不完全の結果も含み、比較失敗とExcel生成失敗は個別Excelから除外します。Excel生成失敗は、少なくとも1件を保存できる場合には集計へ状態を残します。ZIPには `.xlsx` 以外を入れず、上限は200MiBです。
- HTML レポートは「差分一覧」「フィールド単位」の 2 タブ構成（サマリー / 比較対象設定タブは廃止）。レポート内の「詳細オプション」で、出力前と同じ無視キー・順序無視などの条件を後から選択して表示を絞り込み可能
- 「範囲」で全件 / 表示中を選び、Excel保存または HTML の再出力が可能
- **HTML内容モード**: 既定の「差分行のみ（全設定は未収録）」は比較元/先の全設定スナップショットを埋め込まず、元設定JSON・フィールド詳細・反映JSONを収録しません。「比較設定込み（取扱注意）」を明示選択した場合だけ詳細機能を有効化します。どちらのHTMLにも差分行の比較元/先の値は残り、Excelにも同じ差分値を加工せず収録します。共有前に内容を確認してください。
- **画面内レビュー**: 変更種別・セクション・キーワード等で絞り込み、`J` / `K` と前後ボタンで実差分を先頭・末尾の範囲内で移動。固定ヘッダーは BEFORE / 現在位置 / AFTER の3レーンで比較方向を保ち、有効な絞り込み条件は個別解除できるチップで表示します。表示密度、全折りたたみ / 展開、左右／上下の比較レイアウトも切り替え可能です。
- **連続レビュー**: HTMLレポートでは全体とセクション別の確認済み件数・進捗率を表示し、「確認して次へ」または `R` キーで現在行を確認済みにして次の未確認差分へ移動できます。集中表示でも比較元 / 比較先のアプリ名と App ID、現在位置、未確認数を残します。コンパクト密度ではカード余白を縮めて大量差分を高速に読み進められます。
- **レビュー状態の持ち運び**: 「レビュー状態JSON保存 / 読込」で確認済み状態を明示的に保存し、後から同じ比較結果へ復元できます。別レポート用のJSON、未知・重複した行、2MBを超えるファイルは現在状態を変えずに拒否します。ブラウザ内へ状態を自動保存しません。
- **大量差分向けの軽量表示**: 検索文字列を行単位でキャッシュし、連続入力は150msのデバウンス後に1回だけ反映します。日本語IME変換中の再描画を抑え、画面外カードは対応ブラウザで描画負荷を軽減します。表示件数 / 全体件数 / 未確認件数は常設の読み上げ領域へ通知します。
- **読みやすい差分カード**: 行見出しは日本語の要約を優先し、フィールド設定の行には対象の表示名とコード（例: `顧客名（customer_name） · 必須設定変更`）を付けて同じ種類の変更を見分けられるようにします。内部パスは「技術情報」に折りたたみます。ステータス改名は旧名と新名で示します。長い値やJSONは行数・文字数付きのプレビューで表示し、必要な行だけ全文へ展開できます。
- **無視ルール候補**: 差分行の「パスを無視」から、大小文字・空白・`*`・区切り記号をリテラルとして扱う `path:` 形式の完全パスを次回比較条件へ追加（現在の結果は変更せず、再比較後に適用）。配列番号を含む位置依存パスは誤除外防止のため自動追加不可
- **不完全比較の明示**: 件数上限後に走査していないセクションは「未走査・件数不明」として、取得失敗や本文未検証と区別して表示
- **対応付けの注意**: 要素数が多く並び替えの検出を省略した配列や、タイトル等の識別子が空・重複で別の方式に切り替えた配列を、完了メッセージと結果の概要へ表示。差分の取りこぼしではないため、完全性や「要確認」には含めません
- **同じアプリの本番とプレビューを比較**: 1対1比較の「本番とプレビューを比較（未公開の変更を確認）」で、比較元を本番、比較先を同じアプリ（同じゲストスペース）のプレビューに設定します。比較元の入力（URLの貼り付け可）を使い、空なら開いているアプリを使います。設定だけを行い、比較は「差分比較を実行」で行います（実行後の概要に「本番 → プレビュー」と示されます）。比較元の設定JSONを読み込んでいる間は設定できず、1対多・ペア一括では表示しません。
- **表示順の繰り下がり**: 一覧・グラフ・ステータス・カテゴリ・アプリアクションの途中へ1件追加（削除）して、後続の表示順が1つずつずれただけの違いは、差にしません。両側にある項目どうしの並び順が変わったものだけを「表示順」の差として示します。
- **並び順を無視する正規化**: 選んだ並び順だけを差分から外します。並べ替えで位置がずれた「並び順が異なる」行や、新しい差は出しません。
- **件数の一致**: 完了メッセージの内訳（追加・削除・内容変更・移動）は概要・HTML・Markdownと同じ数です。旧フォーム設定（フィールド設定・レイアウト設定の再掲）は、Excelでは変更一覧の件数に含めず別シートに載せるため、画面・HTML・Markdownの件数は、Excelの変更一覧の行数にフォーム設定の件数を足した数になります（画面の概要にも、再掲であることを示します）。
- **1対多比較の保持量**: 結果をメモリに保持するとき、保存に使わないJS/CSSの本文・プラグイン設定の取得結果は取り除きます（比較先200件・業務アプリ規模で約99MB → 約22MB）。結果の行からのHTML・Excel・Markdown・ZIP保存は変わりません。
- **1対多比較の実行前検査**: すべての比較先のアプリID・ゲストIDと重複を行番号付きで検査し、問題があれば直前の比較結果を残したまま実行を止めます。1対1比較を含め、比較元・比較先のゲストIDも半角数字以外は取得前に止めます

#### HTML レポートの機能

差分 HTML レポートは、単体で完結する自己完結型ページです（外部 CDN 依存なし）。

- **差分一覧タブ**: 完全性、比較方向、客観件数を先に示し、セクション別に差分カードを表示します。レビュー受信箱、セクション見出し、ジャンプナビには確認済み / 対象件数を表示し、追加 / 削除 / 内容変更 / 移動 / 同一、使用中フィルター、文字単位ハイライトで変更箇所を把握できます。
- **比較レーンと段階表示**: 比較元を BEFORE、比較先を AFTER として値の方向を常に明示します。日本語の意味を先に見せ、内部パスやコードは「技術情報」、長い値は展開可能なプレビューへ分離します。
- **モバイル表示**: 狭い画面では比較値を1列に積み、絞り込み・出力のサイドバーを開閉式にして、横スクロールせずレビューできます。
- **モバイルドロワー**: 絞り込み・出力は本文を押し下げない固定ドロワーで開きます。背景操作を抑止し、`Esc`・閉じるボタン・背景クリックで元の操作位置へ戻ります。
- **JSONで比較（フィールド単位）**: WinMerge のように設定 JSON 全体を左右に並べて行単位で比較するモード。フィールドごとにブロックを区切り、変更行のハイライト・行番号・文字単位差分を表示（「複数行差分は変更行だけ表示」をオフにすると全行を整列表示）
- **フィールド単位タブ**: フィールドコード単位で、比較元 / 比較先の設定を kintone の設定ダイアログ風スナップショットで左右に並べ、値が異なる項目に差分色を付与。関連レコード一覧設定・ルックアップ設定・テーブル内の項目は、日本語ラベル付きの key-value 表で差分行を赤（比較元のみ）/緑（比較先のみ）/黄（変更）に色分けし、変更値は文字単位でハイライト。差分一覧と同じ種別チップ（追加 / 削除 / 変更 / 同一）での絞り込みと詳細オプション（無視キー・正規化プリセット）が有効
- **反映JSON作成**: 差分行・フィールドの「選択」チェックから、比較元の設定値を比較先アプリへ反映するための API パラメータ JSON を作成（保存 / コピー）。画面の「比較元=変更前 / 比較先=変更後」で比較した場合は変更前へ戻す方向になるため、前進移行では完成状態を比較元、反映先の現状を比較先にして再比較します。フィールドは `form/fields` の PUT / POST / DELETE に分解し、全体置き換え型のセクションは対応 API の payload を生成します。プロセスの状態名変更がある場合は、別の変更へ改名が混入するのを防ぐためHTMLの反映JSON全体を無効にし、統合版でもプロセス管理のセクション単位反映と失敗セクション再実行をブロックします。外部パッチJSON内の確認専用行・予約済み改名パスも拒否します。状態名変更以外は行／ノード単位で選ぶか、管理画面で手動確認します。
- **作成時に利用した設定JSONの出力**: レポート作成に使った比較元 / 比較先アプリのセクションデータを、それぞれ JSON ファイルとして保存可能
- **確認済み管理**: 各差分行の「確認」チェックで確認済みをマークし、サイドバーの「確認済みを隠す」で残作業だけに絞り込み。確認済み・選択中件数はサマリーに表示
- **コピー / エクスポート**: 行ごとに設定パス・値（JSON）をワンクリックコピー。表示中の差分を CSV 保存 / Markdown 表としてクリップボードにコピー
- **キーボード操作**: `J` / `K`（または「前へ / 次へ」）で差分行を順に移動、`Ctrl/⌘+F` で検索フォーカス、`Esc` で検索クリア
- ライト / ダークテーマ切替、セクションへのジャンプナビ、印刷プレビュー対応

### 2. プレビュー反映

アプリまたは設定JSONから、指定アプリのプレビュー設定を更新します。

- 対象選択・差分確認・最終確認・結果の4段階。進めない理由を画面下部に表示。画面の用語は「反映元／反映先」
- アプリURLの貼り付けからアプリID・ゲストスペースIDを読み取り。入力中にアプリ名を確認して表示
- 反映元の本番／プレビューを明示選択し、APIで確認したアプリ名・ID・ゲストスペースを表示
- 反映項目ごとの動作説明と「置換」の目印。フィールド設定を含めない場合の注意
- 差分確認の要約表と、項目単位の「変更の要約」（フィールドは表示名（コード）、レイアウトは位置）。設定値の内訳で反映先の現在と反映後を比較
- 反映先だけのフィールド・配置を保持。一覧・グラフ・アクションも標準で保持し、全置換は明示選択
- 一般設定（テーマ・レコードのタイトル・コメントなど。アプリ名・説明・アイコンは対象外）の反映
- 別アプリのJS/CSSファイルを内容で比較し、必要なものだけ反映先へアップロードして設定
- 取得失敗や参照先フィールド不足、種類の衝突を実行前に検出。不足時はフィールド設定を加えて再取得
- 反映先プレビューの以前からの未公開の変更を表示し、ある場合は反映先IDの入力を要求
- 反映計画JSONの保存、計画・記録のMarkdown保存とコピー、項目と値の検索、セクション選択
- ルックアップ・関連レコード一覧・アクションの参照先AppIDを「旧ID → 新ID」の行形式またはJSONで指定。変換時はアプリコード（code）指定を自動削除
- 参照先変換の入れ忘れを防ぐ「参照先変換の候補」。反映元と反映先の同じコードのルックアップ・関連レコード一覧（と同じ名前のアクション）で参照先アプリが違うとき、差分確認に「401 → 301」の形で候補を示し（分かる範囲でアプリ名も）、「候補を参照先変換に追加して差分を取り直す」で入力欄へ加える。根拠は反映先の現在の設定だけ（名前の類似などから推測しない）。同じ旧IDに複数の参照先がある食い違いは自動では入れず、入力済みの変換は上書きしない。入れないまま反映するときは、最終確認で反映先IDの入力を求め、計画のMarkdownにも注意として載せる
- 接続先・項目・オプション・続けて反映する反映先のプリセットを保存し、JSONで書き出し・読み込み
- 最終確認のチェック。削除・権限等の変更・同じアプリへの反映・未公開の変更がある場合は反映先IDも入力
- 実行直前の設定・revision照合、自動バックアップ（JS/CSSのファイル本体を含む）、エラー時中断
- 実行中の項目ごとの進捗、結果の項目別一覧と対処ヒント
- 失敗・未実行の選択と再比較。反映後に同じ条件で差分を再確認
- 「変更を中止」による取り消しの案内と、バックアップを反映元にした復元
- 同じ反映元・項目で複数の反映先へ順番に反映（反映先ごとに確認。最大 1000 件）。アプリ検索の「環境内の全アプリ」から全アプリをまとめて「続けて反映する反映先」に追加できる（反映元と入力済みのアプリは除き、件数を表示）
- 続けて反映する反映先があるとき、「全反映先の事前確認」で、全反映先の差分を書き込まずに先に一覧にする（反映元は 1 回だけ取得）。反映先ごとにアプリ名・状態（差分あり／差分なし（一致）／確認が必要／取得失敗／未実行（中止））・差分のある項目・変更と削除の件数・以前からの未公開の変更の有無を示し、取得失敗を「差分なし」と表示しない。「差分のない反映先を外す」「取得失敗だけ確認し直す」、行から差分確認へ進む操作、結果のMarkdown保存・コピー（承認依頼用。設定値の生JSONは含まない）。反映元・項目・保持・参照先変換を変えると古い結果として扱い、中止では残りを「未実行（中止）」にする。1000 件でも行は要約だけで、一覧は 50 件ずつ描画する。反映先ごとの差分確認と最終確認は従来どおり必要で、自動では書き込まない
- 閉じて開き直したとき（同じページが開いている間）は、入力・直前の結果とバックアップ・展開の記録・プリセットを引き継ぐ（ページを読み込み直すと消える）
- 本番公開は反映先の設定画面で実施

使い方・API仕様・バックアップの制約は [プレビュー反映](../docs/preview-reflection.md) を参照してください。

### 2-2. 本番反映

プレビューの未公開の変更を、本番へ公開（kintone の「アプリを更新」）または破棄（「変更を中止」）します。見出しのバッジは「本番の設定を変更」です。

- 対象を選ぶ・変更を確認・最終確認・結果の4段階。段階1・2では書き込みません。進めない理由は「次に進むには：…」で表示
- 対象アプリは表で入力（アプリごとにゲストスペース。URL・カンマ区切りの貼り付け、現在のアプリ、環境内の全アプリから一括追加。最大 1000 件）
- 操作は「本番へ反映（アプリを更新）」（既定）と「変更を中止（プレビューを本番に戻す）」。詳細設定で反映の方法（1アプリずつ／まとめて。まとめては最大 300 件・同じゲストスペース）と失敗したときの動作（残りを実行しない／続ける）を選択
- 差分確認はアプリごとに「変更あり」「未公開の変更なし」「取得失敗」「反映処理中」を表示。変更のある項目名・削除の件数・revision（本番 → プレビュー）と、開いたときに描画する項目別の「変更の要約」。取得失敗・反映処理中のアプリは選択している間は先へ進めず、「取得失敗・処理中だけ確認し直す」と「対象から外す」を用意
- 削除されるフィールドは警告色で「レコードの値も削除され、元に戻せません」と示し、コードだけを変えた可能性があるときは「プレビューの『X』」を添える。あわせて本番のレコード数を読み取り（読み取りだけ）、「このアプリのレコード: N 件（閲覧できるレコードの数）。削除するフィールドの値は、これらのレコードから削除されます。」と影響の大きさを示す（閲覧できない・取得に失敗したときは「確認できませんでした」と示して止めない）
- 計画のMarkdownを保存・コピー
- 最終確認は、方向・対象・反映の方法・削除される設定・削除されるフィールド・バックアップ・取り消し方を表面に示し、チェックと確認入力（1 件なら対象アプリのID、複数なら対象のアプリ数）を求める。確認は、前の段階へ戻る・選択や条件を変えると解除
- 実行前に各アプリの revision を再確認し、反映前の本番設定（変更を中止ではプレビューの設定）をバックアップJSONに保存してから依頼。バックアップはプレビュー反映の反映元（設定JSON）に読み込める
- 結果はアプリごとに待機中・確認中…・反映中…・成功・失敗・取り消し・確認後に更新・完了を確認できない・未実行を表示。数百件を超えるときは要約と問題のある行を優先表示。結果JSON・記録のMarkdownの保存とコピー、失敗・未実行だけ選び直す、1 件なら設定画面を開く

#### 反映元アプリから本番へ

別のアプリ（開発・検証用）の設定を、差分を設定値 1 つずつ選び、直してから、反映先のプレビューへ書き込み、続けて本番へ反映します（「操作」の既定）。対象を選ぶ → 差分を選ぶ → 内容を修正 → 最終確認 → 結果の 5 段階で、最初の 3 段階では書き込みません。

- 選んだ変更と、入力欄・JSON での修正を、段階 2・3 の「選択と修正を保存」で JSON ファイルに保存し、差分を抽出し直したあとに「選択と修正を読み込む」で戻せる（承認を待つ間や別の担当者への受け渡し）。反映元・反映先が保存時と違うファイルは違いを示して読み込まない。現在の差分に無い選択・修正は「当てはまらなかったもの」として件数を示す。JSON での修正は、反映先の設定が保存時と同じ項目だけ当てはめる。読み込んでも最終確認は必要
- 反映元と反映先で参照先アプリが違うルックアップ・関連レコード一覧・アクションがあり、参照先変換に入れていないときは、段階 2 に「参照先変換の候補があります」と警告し、「候補を参照先変換に追加して差分を取り直す」で追加して抽出し直せる（選択と入力欄の修正は引き継ぐ。食い違いは自動では入れない）。入れないまま進むと最終確認にも警告し、記録の Markdown・結果 JSON に残す
- 結果の「反映後の内容を確認する」で、本番（プレビューまでならプレビュー）の設定を読み取り、選んだ変更が選んだ値（修正した値を含む）で入っているかを確かめる。「すべて反映されています」または「反映されていない変更 N 件」（場所・期待した値・現在の値）を示し、取得できなかった項目は「確認できません」とする。確認した日時と結果は記録の Markdown・結果 JSON に残る。読み取りだけで、書き込まない

使い方・バックアップと戻し方・制約は [本番反映](../docs/production-deploy.md) を参照してください。

### 3. フィールド追加

フィールド追加は、JSON 編集・比較元から追加・一括整備の機能で構成されます。反映先は比較先プレビューのみで、デプロイ（本番公開）は行いません。

#### JSON編集

- `properties` 形式のフィールド JSON を直接編集
- 比較先プレビューへ反映
- 同一コード上書き
- 反映後にフィールドコードが重複する組み合わせ（既存コードへの追加・コード変更の衝突）は、書き込み前に中止
- 反映前の確認に追加・更新対象のコード（コード変更は「旧 → 新」）と削除 0 件を表示。追加後の更新が失敗した場合は、追加が反映済みであることをエラーに含めて表示
- 反映後のフォームに無いフィールドを参照する定義（計算式の参照先、ルックアップのコピー先、関連レコード一覧の条件。テーブルの中を含む。反映先に既にあるフィールドと、同じ JSON で追加するフィールドは「ある」とみなす）は、最終確認に足りないコードを警告として示す（複数の反映先では反映先ごと）。書き込みは止めず、利用者が続けるかを決める（kintone は拒否することがあり、その場合は何も追加されない）。反映しない既存のフィールドが、コードを変更するフィールドを参照している場合も示す
- 比較先の現在フィールド読み込み
- JSON 整形
- JSON ファイル読込 / 保存
- 比較先のアプリID・ゲストIDは数値のみ。ID・フィールド JSON（type 必須）・参照先変換 JSON は確認画面へ進む前に検査。検索結果から選ぶとゲストIDも検索した接続先に合わせる

#### 複数の反映先へ反映

- 操作「複数の反映先プレビューへ反映」で、同じフィールド JSON を複数アプリのプレビューへ反映する。反映先は「まとめて反映する反映先」の表（行ごとにゲストスペースID）で指定し、アプリ検索の「環境内の全アプリ」→「候補 N 件をすべてまとめて反映先に追加」で全アプリを入れられる
- 先に全反映先の現在のフィールド設定と revision を取得して計画を作り、最終確認を 1 回だけ表示する（対象数、反映する件数・変更なし・事前確認に失敗の内訳、追加 / 更新 / スキップの合計、削除 0 件、アプリごとの一覧は先頭 20 件と件数）
- 1 件ずつプレビューだけへ反映し、事前確認の revision を送る。その後に別の更新が入った反映先は「競合」として上書きしない。失敗・競合があっても残りを続け、「中止」で残りを「未実行（中止）」にする（反映済みの分は取り消さない）
- 結果は反映先ごとに 成功 / スキップ（変更なし） / 失敗 / 競合 / 未実行（中止） を表示し、一部成功は警告色

#### 比較元から追加

- 比較元アプリのフィールド一覧を取得
- コード・ラベル・タイプで候補を絞り込み、表示中の候補を全選択／全解除。選択件数を常時表示
- 選択したフィールドを JSON にマージ（同じコードの既存定義は候補の内容で置き換え）。計算式の参照先・ルックアップのコピー先・テーブルの中のフィールドは自動では加えないため、足りなければ最終確認で示す
- 比較元のアプリID・ゲストIDを変更すると、前の比較元の候補は閉じる

#### 一括整備

- フィールドコードへのプレフィックス一括追加 / 削除（計算式・ルックアップのコピー先・関連レコード一覧の条件が参照するコードも、新しいコードに合わせて書き換える。コードを変えない定義でも参照先が変わるなら JSON に含める。生成した JSON は既存フィールドのコード変更として扱うため、反映時は上書き更新をオン。重複するコードは生成前に中止）
- 未使用候補の調査は「分析」タブの影響分析サブタブに集約

### 4. JS/CSS 設定

JS/CSS 設定パネルは「取得」「JSON 保存」「比較先プレビューへ反映」「全アプリの ZIP 一括取得」から操作を選び、確認画面を経て実行します。

#### 設定編集

- 取得元アプリ（本番 / プレビュー、ゲストスペース指定可）の JS/CSS 設定取得
- JSON 表示 / 編集（手入力・貼り付けも可）
- JSON 出力（ファイル名は取得時のアプリIDを使用。確認画面に JSON の取得元と取得後の編集有無を表示。編集中の JSON を取得で上書きする前に確認）
- 比較先プレビューへ反映（revision を送り、取得後に別の更新が入っていれば中止。反映先のプレビューから取得した JSON は取得時の revision を基準にし、それ以外は反映直前の revision を基準にする。最終確認に比較先の現在件数と、全置換で外れる件数を表示。js / css が配列でない JSON は反映前に止める）
- 反映先は常にプレビュー環境で、デプロイは行わない（管理画面から手動）

#### FILE 形式（アップロード済みファイル）の別アプリへの反映

fileKey は取得元のアプリでしか使えないため、プレビュー反映と同じ規則（`reflect/customizeFiles.ts`）で、反映先ごとに扱いを決める。

- JSON を取得したアプリ（アプリ・本番 / プレビュー・ゲストスペース）を、取得時に覚えておく。取得した JSON に含まれていた fileKey だけが取得元のものと分かる
- 反映先プレビューの同じ枠（PC / モバイル × JS / CSS）ですでに使われている fileKey はそのまま使う（同じアプリへ戻すときは、ダウンロードもアップロードもしない）
- それ以外は取得元からファイル本体を取得し、反映先の同じ枠に同名・同内容のファイルがあればそのキーを再利用、無ければ反映先へアップロードして新しいキーで設定する（アップロードしたキーは 1 回しか使えないため、同じファイルを PC とモバイルで使う場合は枠ごとにアップロードする。取得元のキーを書き込みに流用しない）
- 最終確認に、アップロードするファイル（枠・ファイル名・サイズ）、再利用するファイル、そのまま使うファイルと、全置換で外れる件数を示す。複数の反映先では、アップロードするファイルの一覧と反映先ごとの件数を示す。取得元の本体は反映先ごとに取得し直さない
- アップロードは確認後、設定を書き込む直前に行う（複数の反映先では、反映先ごとの書き込みの直前）。本体の取得・アップロードが 1 つでも失敗した反映先には、設定を書き込まない（複数の反映先では、その反映先だけ「失敗」にして残りを続ける）。アップロードの途中で中止したときも書き込まず、「書き込みは行っていません」と示す。使われなかった一時ファイルが残ることがあるが、設定には影響しない
- 取得元が分からない JSON（手入力・ファイルから読み込んだだけ）や、取得後に追加して取得元の JSON に無い fileKey は、推測でアクセスせず「取得元アプリで『取得』してから反映してください」と示して止める（反映先がすでに同じ枠で使っているキーは使える）。バックアップ JSON のようにファイル本体を埋め込んだ JSON は、取得元が分からなくても反映できる
- 操作の確認画面に、FILE の件数と、取得元が分からないファイルの警告を表示する

#### 複数の反映先へ反映

- 操作「複数の反映先プレビューへ反映」で、同じ JS/CSS 設定 JSON を複数アプリのプレビューへ反映する（デプロイはしない）。反映先は表（行ごとにゲストスペースID）で指定し、アプリ検索の「環境内の全アプリ」→「候補 N 件をすべてまとめて反映先に追加」で全アプリを入れられる
- FILE 形式の JS/CSS を含む JSON も、上の規則で反映先ごとに再利用かアップロードかを決めて反映する。取得元が分からないファイルでどの反映先にも渡せないときは、事前確認の段階で 1 回だけ理由を示して止める
- 先に全反映先のプレビュー設定と revision を取得し（FILE があれば、反映先ごとのファイルの扱いも決める。読み取りのみ）、最終確認を 1 回だけ表示する（対象数、枠ごとの件数、適用範囲、外れる件数、アップロードするファイル、事前確認の失敗、反映先一覧は先頭 20 件と件数）。事前確認の後に別の更新が入った反映先は「競合」として上書きしない。失敗・競合があっても残りを続け、「中止」で残りを「未実行（中止）」にする
- 結果は反映先ごとに 成功 / 失敗 / 競合 / 未実行（中止） を表示し、一部成功は警告色

#### 一括ダウンロード

- スペース内の全アプリの JS/CSS 添付（FILE 形式）を本番設定から一括 ZIP 化（ゲストIDは一括ダウンロード欄の指定のみを使用。アプリID・ゲストIDは数値のみ受け付ける）
- ZIP の manifest.json に、アプリごとのフォルダ名・適用範囲（scope）と、各ファイルの ZIP 内パス（ファイル名は使えない文字・`..`・Windows 予約名・大文字小文字だけの重複を避けて安全化し、元ファイル名は name に残す）・読み込み枠（desktop / mobile × js / css）・元ファイル名・fileKey・サイズ、取得に失敗したアプリ／ファイルを記録。URL 形式は含めない
- 一部の取得に失敗した場合は ZIP に download_errors.txt を含めて警告表示。取得できたファイルが 0 件で失敗がある場合は ZIP を作らず、失敗の内訳をログに表示

### 5. ER図

ER図タブは 2 つのサブタブに分かれます。

#### ER図

- 比較元アプリを起点に関連アプリを探索
- ルックアップ / 関連レコードを辿って ER 図生成
- スペース ID 指定でスペース内全アプリを起点に追加（スペース所属アプリは二重枠で表示）
- 「スペース内アプリを読込」で一覧を取得し、アプリ名・ID で絞り込んで起点にするアプリだけを選択。選択件数は確認画面にも表示し、スペース ID や接続先を変えると古い一覧は破棄
- レイアウト指定
- 表示密度指定
- 探索深さ指定
- アプリ検索の「環境内の全アプリ」→「候補 N 件をすべて起点にする」で、全アプリを起点にした ER 図を作れる（起点の入力欄を置き換え、ゲストスペースIDも候補に合わせる）。確認画面の起点は件数と先頭 20 件、状態表示は先頭 5 件と件数で示す。50 起点以上では時間と図の大きさの注意を表示
- 設定の読み取りは、同時に 4 アプリまで並行して行う（1 アプリあたり項目・アプリ情報・アクションの 3 リクエストを並べて送る）。結果の並び・深さ・関連は 1 アプリずつ読んだときと同じ。「中止」すると、読み取りを終えたアプリの数と、中断した・読んでいないアプリの数を示す（図は生成しない）。1 リクエストが 60 ms かかる合成 API で 300 アプリを走査すると、約 43 秒が約 12 秒になる
- 逆引き探索（全アプリを走査して、起点を参照するアプリも辿る）。走査中に設定を読み取れなかった（取得失敗・一部取得の）アプリがある場合は、完了メッセージを警告表示にし、図の上部の「逆引き走査」表示とエクスポートの注意書きで、それらを参照する関連が含まれない可能性を示す
- サブテーブル項目の含有切替
- 生成する HTML は、描画ライブラリ（Cytoscape.js・Dagre・cytoscape-dagre の固定版）を中に埋め込んだ自己完結のファイルで、ネットワークに接続できない環境でも開ける（CDN は使わない。同梱するライブラリの著作権・ライセンス表記は残している）。「ER図を開く」の画面、保存した HTML、図の画面の「出力 → 編集済みHTMLを保存」で保存して開き直したファイルのすべてで同じ。ブラウザの制限などで描画ライブラリを初期化できないときだけ、取得済みアプリの一覧の表を出す。同梱により HTML は約 0.67 MB 大きくなる
- 関連（線）の詳細として、ルックアップは「参照先のどのフィールドをどのフィールドへコピーするか」と取得時の絞り込み条件、関連レコード一覧は表示するフィールドと絞り込み条件、アプリアクションは「どのフィールドを起動先のどのフィールドへコピーするか」と実行条件を持つ。図の詳細パネル・線へのマウスオーバー、出力の Markdown（関連の表の「コピー・表示するフィールド」「絞り込み条件」の列）・関連の CSV（同名の 2 列）・JSON（`copyFields`・`displayFields`・`filterCond`）、パネルの「仕様書をMarkdownで保存」「関連一覧をCSVで保存」に出る
- 検索は、アプリ名・ID と、取得済みの全項目の名前・コードを対象にする。現在の表示密度でカードに出ていない項目で一致したアプリは、一致件数の横に「うち N 件は図に出ていない項目」と示す（表示密度を「詳細」にすると項目を確認できる）
- 取得に失敗した（一部取得を含む）アプリの理由は、kintone の応答の文だけを、構造チェック・アプリの詳細・出力の「取得上の注意」に示す（内部の通信情報の行 `[API] GET …` は出さず、実行ログ（console）にだけ残す）
- 保存形式は HTML、仕様書 Markdown、Mermaid、関連一覧 CSV。ファイル名には起点アプリ・環境・日時が入る（Mermaid は日本語のフィールドコードでも描画できるよう、項目名を `field_1` などにして実コードと表示名を注釈に入れる）
- アプリは見出しと項目行を分けたカードで表示する。項目には PK・FK・関連・一意・必須のバッジが付き、縮小時はアプリ名と件数だけの概要カードに切り替わる。階層配置で1階層のアプリが多い場合は複数列に、階層が多く横に長い場合は複数段に折り返す。フォース・同心円・グリッドなどで配置後にカードが重なったときは、重ならなくなるまで押し広げる（縮小時の概要カードの大きさも含めて重ならないようにする。固定したアプリは動かさない。800 アプリを超える図では行わない）。アプリを選ぶと周辺が強調されるが、PNG・印刷には強調を残さず全体図を出す
- 図の画面の「出力」からは PNG（白背景で起点・接続先・日時・凡例を含み、表示倍率によらず項目入りのカードで描く）、印刷、Mermaid、draw.io、PlantUML、SQL DDL（MySQL 形式。テーブル内のルックアップや外部キーにできない関連は理由をコメントで示す）。Markdown 仕様書には Mermaid の ER 図を埋め込む（4万字を超える図は省略）、JSON、Markdown、CSV を保存できる

#### 依存関係

- フィールド間の依存関係マップ生成
- 計算式、条件、プロセスなどの参照関係を可視化

### 6. プロセス図

- プロセス管理が無効なアプリは失敗ではなく「無効」として一覧に残す。取得失敗は理由つきで一覧とログに残し、完了メッセージを警告色にする。「中止」では取得済みの分だけを保存し、残りを「未実行（中止）」と記録する（何も取得できていない・全件失敗のときは ZIP を作らない）
- 通し検証（`npm run test:record-explore`）で、状態 40・アクション 90、分岐・差し戻し・終端が複数、記号や HTML に見える長い名前、同名アクション、プロセス無効、複数アプリ ZIP を確認済み（Mermaid を読み込めない環境の簡易表示では HTML を実行しない）。簡易表示は表のままで、図（SVG）にはしていない
- 状態遷移シミュレーション（最初から開始 → 現在状態から実行できるアクションを選んで実行）。開始前や終端のステータスで実行を押した場合は理由を表示。プロセス管理が無効なアプリではソースを出力しない

### 7. 設計書

設計書タブは 2 つのサブタブに分かれます。

#### 設計書出力

- 設計書 JSON 出力
- 設計書 Markdown 出力
- Markdown コピー
- 設計書 Excel 出力: 「プレビュー環境から取得」に合わせて本番／プレビューの設定を取得する（複数アプリ ZIP も同じ。ZIP の名前と manifest に環境を記録する）。項目定義シートのグループ名はフィールド設定の表示名（コードではない）。グラフの集計 `AVERAGE`（平均）・作業者の選び方 `ANY` も日本語で表示する。取得に失敗した項目は完了メッセージとサマリーシートの「API取得失敗レポート」に残す。出力中の「中断」で取得を止められる
- アプリ検索の「環境内の全アプリ」→「候補 N 件をすべて追加」で全アプリを対象アプリ表に入れ、「全対象をExcel ZIPで保存」で全アプリの設計書をまとめて保存できる（単一出力は表の 1 行目のまま）。50 アプリ以上では時間とメモリの注意を確認画面に表示
- 機微な値: 設計書の Markdown・AI向けMarkdown には、設定JSON由来のプラグインの設定値（`_config`）と JS/CSS ファイルの本文（`_bodyText`）を、原文 JSON にも載せない（kintone から直接取得した場合と同じ）。AI向けMarkdown には「除外した補助情報」として件数を書く。設計書 JSON は設定の写しなので従来どおり含める。Markdown の設計書は JS/CSS 本文・プラグインの設定値を kintone から取得しない（本文の取得失敗でセクションが取得失敗にならない）
- 設定JSON読込（任意）: 「設定一括取得」で保存したJSON（複数アプリの `apps` 配列にも対応）を読み込むと、kintoneへ接続せずそのJSONの内容だけから設計書（JSON / Markdown / Excel いずれも）を生成できる。設定一括取得タブの結果一覧から「設計書へ」ボタンで直接読み込むことも可能。複数アプリ一括Excel出力（ZIP）でも、対応する設定JSONが読み込まれているアプリはAPI取得をスキップする。設定JSONに含まれないセクションは「取得失敗」として設計書に記載し、完了メッセージにも残す。アプリIDの無い設定や同じアプリIDの重複は読込時に警告する。ZIP は一部のアプリが失敗しても残りを保存し、成功／失敗件数を完了メッセージと manifest に記録する。

#### Markdown 設計書の構成

- 先頭にアプリID・アプリ名・ゲストスペース・取得環境（本番／プレビュー）・取得日時（ISO 形式には日本時間を併記）・取得できなかったセクションをまとめた表
- 目次、件数サマリー、確認ポイント、セクション一覧のあとに各セクションの表を出力
- フィールド表は「参照先/制約」列でルックアップの参照先アプリとキー、関連レコード一覧の条件、単位・桁区切り・文字数や値の範囲、初期値（現在日時）などを表示。テーブル内フィールドも同じ列を持つ
- 取得に失敗したセクションは「0件」と読み違えないよう、本文に「取得できませんでした」と理由を書き、件数欄も「取得失敗」にする
- 「出力セクション」の件数は「取得状態」の件数と同じ数え方（件数の定義が無いアプリ設定などは「-」）。サマリー・確認ポイントのルックアップ数・必須フィールド数・関連レコード一覧数は、テーブル内のフィールドも含めて Excel の設計書と一致させる
- ルックアップは転記（コピー先 ← コピー元）の一覧、関連レコード一覧は表示フィールド、アクションはコピー項目（コピー元 → コピー先。レコードのURLを含む）と実行条件を表に出す。プラグイン表は有効状態、カレンダー一覧は日付・タイトルのフィールドと PC 版のみの表示、グラフは分類の期間（月など）と、フィールドを持たない集計（件数）を出す。作業者の選び方 `ANY`（候補の誰でも）も日本語にする。レイアウトのグループ名はフィールド設定の表示名から出し、名前が無い見出しには「 — 」を付けない
- フィールド名・選択肢・計算式などに含まれる `|`・`<`・`*`・改行は Markdown が崩れたり HTML として解釈されたりしないようエスケープする
- 各セクション末尾の API レスポンス（生データ）は折りたたみで付属

#### 差分レポート

- 比較元と比較先の設計書差分を Markdown レポートとして出力
- 先頭に比較方向（比較元＝追加・更新後の姿、比較先＝現在の設定）、アプリ名・環境、追加／削除の行数を表で示し、「見方」とセクション別の追加・削除件数の表を付ける
- 差分は生データ JSON と取得日時を除いた設計書の表・要約で比較するため、変更点を読み取りやすい。本文は変更行の前後 3 行だけを残し、離れた変更の前に `@@ セクション名（省略 N 行）@@` を入れる（業務アプリ規模でも変更が埋もれない）。追加・削除の件数は全体から数える。生成日時は読める形（`2026-11-09 22:00:00`）厳密な差分は差分比較ツールの HTML / Excel を使う

### 10. レコード管理

レコード管理タブは 5 つのサブタブに分かれます。

対象アプリ欄には、アプリ検索の「環境内の全アプリ」→「候補 N 件をすべて対象アプリにする」で全アプリを入れられます（入力欄を置き換え、ゲストスペースIDも候補に合わせます）。確認画面の対象アプリは件数と先頭 20 件で示し、CSV取込の最終確認も先頭 20 アプリと件数にまとめます。添付ファイル保存とバックアップは、アプリごとに別の ZIP を保存します。データ品質チェック（`データ品質チェック.js`）の対象アプリ欄も同じ操作で全アプリにできます（検査項目は先頭の対象アプリから読み込むため、その項目が無いアプリは検査失敗として表示します）。

#### ステータス更新

- 一覧条件に一致するレコードのプロセス管理を一括実行
- 複数アプリで確認画面をキャンセルしたアプリは、完了扱いにせず「実行していません」と最終メッセージに表示します（ステータス更新・コピー）。
- ステータス更新とアプリ間コピーはアプリごとに確認ダイアログを表示するため、一度に指定できるのは 50 アプリまでです（超える場合は確認画面へ進まずに理由を表示します）
- 追加・更新が100件単位の途中で拒否された場合は、確定済み・未処理の件数に加え、kintone が返したレコード（CSV取込は行番号、ステータス更新・コピーはレコードID）とフィールド名［コード］別の理由を表示します。
- CSV取込・コピーのレコード追加は、応答が届かなかった（通信エラー・タイムアウト）ときに自動で再送しません（サーバー側で確定していると二重に登録されるため）。その塊が書き込まれたかどうか確認できない旨と、再実行する前に kintone で件数を確認する案内を表示します。
- CSV取込の事前検査は、存在しない日付（2026-02-30 など）・日時（13 月・25 時など）も書き込み前に検出します。

#### 添付DL

- 一覧条件に一致する添付ファイルを ZIP で一括ダウンロード
- ZIP が約 2GB（またはファイルとフォルダの合計が約 65,000 件）を超えるときは、取得を始める前にレコード単位で分け、`…_part1.zip`・`…_part2.zip` のように 1 つ分を取得するたびに保存します（1 レコードの添付は同じ ZIP に入ります。10 個以上のときは `_part01` と 0 埋め）。各 ZIP の `manifest.json` の `split` に、分割したこと・ZIP ごとのレコード範囲・保存数・失敗数・未保存数を書きます。
- 1 ファイルで ZIP の上限（4GB 未満）を超える添付は取得せず、その 1 件だけを「ZIP の上限で保存できなかった添付」として理由つきで `download_errors.txt`・`manifest.json`（`unsaved`）・完了メッセージ（警告色）に残して続けます。保存できた添付がまだ 1 件も無い間の ZIP は作らず、記録を次の ZIP へ持ち越します。「中止」では、保存済みの ZIP を示し、中断した ZIP 以降は保存しません。
- ZIP を複数ダウンロードしたとき（分割・複数アプリ）は、完了メッセージに依頼した ZIP の数と名前を示します。ブラウザの許可確認が出たら許可し、ダウンロード一覧の数と照らし合わせてください。

#### CSV

- 一覧条件に一致するレコードの CSV エクスポート
- CSV ファイルからの一括インポート
- 作成者・更新者・作業者はユーザーコード、分類は「,」区切りで出力します。ラベル・スペース・罫線・グループ・関連レコード一覧は値がないため列を作りません。
- 複数アプリで一部が失敗した場合や、閲覧権限などで取得できなかったテーブルがある場合は、成功分を保存したうえで、失敗したアプリと未取得のテーブルの内訳を CSV出力パネルの結果欄にも表示します（ZIP 内の manifest にも記録）。
- エクスポート CSV のうち = + - @ で始まる文字列セルは Excel の数式実行を防ぐため先頭に ' を付けます（数値は対象外）。ZIP 出力の manifest.json notes にも記載します。

#### バックアップ

- 一覧条件に合致するレコードを CSV・添付ファイル・コメント込みで ZIP バックアップ
- 必要に応じてアプリ設定 JSON も同梱（「アプリ設定も保存」を選んだ場合は保存範囲を1つ以上選ぶ必要があります）
- 添付が ZIP の上限に近づくときは、添付だけの ZIP（`…_part1.zip` …）に分け、レコードの CSV/JSON・コメント・設定と全体の `manifest.json`（`split`・全体の保存数・取得失敗・保存できなかった添付）は最後の ZIP に入れます。最後の ZIP が保存されていれば、バックアップは最後まで終わっています。「中止」したときは、保存済みの ZIP は添付の一部で完全なバックアップではないことを示します。

#### アプリ間コピー

- 比較元アプリのレコードを比較先アプリへ一括コピー
- コピー先に必須のフィールドがあり、コピー元から値が入らず初期値も無いとき（すべてのレコードが kintone に拒否される）は、確認の前に対象フィールドを示して止めます（事前確認にも表示）。
- コピー先に一致するフィールドが1つも無い場合は空レコードを作らないよう実行を止めます。コピー先のテーブル内でも、型が違うセルは除外して一覧に表示します。
- 実行確認画面に添付フィールドのコード一覧と添付ありレコード件数を表示します（添付はコピーされないため、必要な場合は手動で再アップロードしてください）。

## 推奨利用フロー

典型的な使い方は以下です。

1. 比較元 / 比較先を設定する
2. 必要なら環境プロファイルを適用する
3. 差分比較で設定差分を確認する
4. 反映プランを確認する
5. 比較先プレビューへ反映する
6. 本番反映で、プレビューの未公開の変更を確認してバックアップを取り、本番へ反映する（アプリの設定画面で「アプリを更新」してもよい）
7. 設計書や差分レポートを出力して記録を残す

## 注意事項

- 反映系処理は比較先プレビューまたは本番データへ影響します
- 全レコード削除、CSV インポート、アプリ間コピーは実データ変更を伴います
- 反映前にバックアップを取得する運用を推奨します
- ルックアップ、添付ファイル、プロセス関連の移送は環境差異の影響を受けやすいです
- プラグイン設定はプラグイン本体の配布や個別設定内容までは含まれない場合があります
