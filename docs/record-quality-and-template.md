# データ検査とCSVひな形

配布スクリプト `tools/kintoneレコード取得.js` の「レコード管理」から使えます。どちらもレコードを書き換えません。

## 重複・未入力を検査

1. 操作で「重複・未入力を検査」を選び、対象アプリIDと必要ならゲストIDを指定します。
2. 「検査フィールド読込」を押し、名前・コードを検索して1〜5項目を選びます。候補は先頭アプリの設定です。
3. 必要ならクエリや「一覧から」で対象を絞り込みます。英字の大小や文字列・リンクの前後空白を無視するオプションもあります。初期状態では区別します。
4. 内容を確認して実行します。結果にアプリ別の検査件数、重複の組数・レコード数、未入力・取得不可の件数が表示されます。
5. 結果のリンクからレコードを開けます。「検査結果をCSVで保存」で集計・全詳細・レコードURL・検査条件・失敗したアプリを保存できます。

選択項目のすべてが同じときに重複と判定します。どれかが空のレコードは未入力として集計し、重複判定に入れません。複数選択は順序を無視し、ユーザー・組織・グループは表示名ではなくコードで比較します。数値は `1.0` と `1` を同じと判定し、大きな桁数を浮動小数点へ変換しません。

項目が応答に存在しない、種類が取得した設定と一致しないなどの場合は「取得不可」です。未入力とは別集計し、両方があるレコードはそれぞれの件数に入ります。詳細表示はアプリごとに先頭50件、CSVは全件です。CSVの閲覧用セルは数式と解釈される文字列の先頭にアポストロフィを付けます。元のレコードの値は変わりません。

対象はテーブル外の文字列1行・複数行、リンク、数値、日付・時刻・日時、ラジオ・ドロップダウン・チェックボックス・複数選択、ユーザー・組織・グループ選択です。テーブル内、添付、計算、リッチエディター、システム項目は対象外です。検査はアプリごとで、別アプリ同士の重複は調べません。各アプリの設定は実行時にも取得します。

取得できたレコードが検査範囲です。権限で見えないレコードや、クエリ外のレコードは含みません。画面上の検査結果を見た後にデータが変わる場合があります。対象・条件・比較方法を変えると古い結果を破棄します。並び順なしはID順に500件ずつ、`order by` ありは既存のカーソル取得を使います。大量データでは取得件数に応じてブラウザーのメモリを使用します。

## CSV取込ひな形を作成

操作で「CSV取込ひな形を作成」を選び、対象アプリを指定して実行します。ZIP内の `app_アプリID/` に次のファイルを保存します。

| ファイル | 内容 |
| --- | --- |
| import.csv | このツールのCSV取込に対応するフィールドコードだけのヘッダ行。UTF-8 BOM付き |
| fields.csv | フィールド名・種類・必須・重複禁止・初期値・選択肢・入力形式・文字数/数値範囲 |
| excluded.csv | ひな形から除外した項目と理由 |
| README.txt | 入力と事前検査の手順 |
| ZIP直下のmanifest.json | 作成日時・対象ゲスト・アプリごとの列数・失敗したアプリ |

`import.csv` の2行目から入力し、UTF-8 CSVとして保存して「CSVからレコードを追加」で選びます。先に「CSVを事前検査」を実行してください。サンプル行を誤登録しないよう、ひな形はヘッダだけです。既存レコードの追加・更新はひな形作成時には行いません。

添付・テーブル・システム項目・計算フィールド・自動計算の文字列・ルックアップのコピー先・未対応の種類を除外します。ルックアップ本体には参照元のキー値を入力します。必須/初期値/選択肢などは取得時点の設定で、実行ユーザーの登録権限や参照元データは別途確認されます。既存CSV取込と同じ言語指定なしの設定APIを使い、選択肢の検査と揃えています。

ガイドの初期値は説明用です。空セルを送ると初期値が入るとは限らないため、初期値を使いたい項目は列を削除するか値を明示してください。ユーザー・組織・グループはコード、複数選択はセル内カンマ区切りです。カンマを含む選択肢は現在のCSV取込では指定できません。Excelの自動変換による先頭ゼロや長い番号の変化にも注意してください。

## 公式仕様と検証

- [フィールドを取得する](https://cybozu.dev/ja/kintone/docs/rest-api/apps/form/get-form-fields/): `properties` のフィールドコード・種類・ラベル・必須・初期値・選択肢・ルックアップのマッピングを使用します。
- [複数のレコードを取得する](https://cybozu.dev/ja/kintone/docs/rest-api/records/get-records/): `fields` に選択項目と `$id` だけを指定して取得量を抑えます。500件とoffsetの上限を踏まえ、既存の全件取得処理を共用します。
- [複数のレコードを登録する](https://cybozu.dev/ja/kintone/docs/rest-api/records/add-records/): 登録できないフィールドの制限を、CSV取込とひな形生成の共通判定へ反映しています。

`npm run test:record-quality` は実画面と実処理をChrome/Chromiumで動かし、API応答とJSZipの出力先だけを合成データへ置き換えます。10,001件、複合キー、取得不可、部分失敗、全件CSV、XSS表示、対象変更、遅延応答、ゲストURL、カーソル、320〜1440px、ひな形の内容を検証します。ZIP圧縮そのものや実kintoneの権限・認証はこのハーネスの検証対象外です。

単体テストは `tests/record/quality.test.ts` と `tests/record/quality-standalone.test.ts`。全体テスト `npm run test:all` とCIにも画面検証を追加しています。
