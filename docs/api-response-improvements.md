# APIレスポンスを利用する補助機能

2026-09-13 時点の公式kintone REST APIドキュメントに基づく仕様です。テストには、公式レスポンスの構造に合わせた独自の合成データを使用しています。実運用環境のレスポンスを取得したものではありません。

## アプリ検索（全10ツール共通）

「アプリを検索（名前・コード・ID）」を開き、検索方法を選びます。名前は部分一致、アプリコードは大文字・小文字を区別する完全一致です。名前・コードは64文字以内です。空の名前で検索すると閲覧可能なアプリを100件ずつ取得できます。

スペースIDを入力すると、名前・コード検索の範囲を絞れます。ゲストIDは接続するゲストスペースの指定です。アプリIDやURLを直接入力した場合、スペースIDによる検索範囲の絞り込みは使いません。

候補には `code`、`spaceId`、`modifiedAt`、`modifier` を表示し、同名アプリを見分けやすくしています。`spaceId: null` は「スペース外」と表示します。更新者情報が空でも候補は表示できます。更新日時はブラウザのタイムゾーンで表示します。アプリIDは文字列として保持し、64bit整数の精度を落とさずに並べます。

- [複数のアプリの情報を取得する](https://cybozu.dev/ja/kintone/docs/rest-api/apps/get-apps/) — `name` / `codes` / `spaceIds` の検索条件と候補のレスポンス項目。
- [アプリの情報を取得する](https://cybozu.dev/ja/kintone/docs/rest-api/apps/get-app/) — ID / URLで直接指定した候補の情報。

## レコード管理の一覧選択

1. 接続情報で「一覧読込」を押します。複数アプリが入力されている場合は先頭アプリから取得します。
2. 一覧を選びます。表・カレンダー・カスタマイズの形式を表示し、kintone設定の表示順に並べます。
3. 各操作のクエリ横にある「一覧から」を押すと、`filterCond` と `sort` を組み合わせた条件が入力されます。

たとえば、絞り込み `amount > 1000` と並び順 `due asc` から、`amount > 1000 order by due asc` を作ります。条件・並び順とも空の一覧を適用すると、入力済みのクエリを空に戻します。絞り込みが同じ一覧でも、IDで区別するため別々の並び順を選べます。

カレンダーの表示月や、カスタマイズ画面のJavaScriptによる独自処理は再現しません。取得するのは保存された設定です。複数アプリへの操作では同じクエリを使うため、各アプリのフィールドコードを確認してください。対象アプリ・ゲストIDが変わると取得済み候補を消し、再取得を案内します。すでに適用したクエリは編集可能な入力として残ります。

[一覧の設定を取得する](https://cybozu.dev/ja/kintone/docs/rest-api/apps/view/get-views/) の `id`、`name`、`type`、`index`、`filterCond`、`sort` を使用します。画面表示用の名称は `lang: user` で取得します。

## 添付フィールドの選択とテーブル内のダウンロード

「添付ファイルを保存」を選び、「添付フィールド読込」を押します。名前を選択すると、添付フィールドのコードと、必要な場合はテーブルのコードが入力されます。コードの手入力もできます。通常フィールドを選び直すと、テーブルコードは空に戻ります。

フィールド候補は先頭アプリから読み込みます。ダウンロード実行時には各対象アプリのフィールド設定を再取得し、指定されたコードが `FILE` か確認します。存在しないコードや文字列フィールドを誤指定した場合、レコード取得前にエラーを表示します。

テーブル内の添付も全行から取得します。空テーブルは正常な空データとして扱い、閲覧権限などで取得できないフィールドとは区別します。添付がない場合はZIPライブラリを読み込まず、対象なしの案内を表示します。

同じフォルダにファイル名が衝突する場合は連番で区別し、上書きを防ぎます。テーブル内の添付はレコード・テーブル・行ごとのフォルダへ保存します。ZIPの `manifest.json` には次の情報を残します。

| 項目 | 内容 |
| --- | --- |
| `recordId` / `tableFieldCode` / `rowId` | 元レコードとテーブル行。通常の添付ではテーブル情報は空文字 |
| `fileFieldCode` / `name` | 添付フィールドコードと元のファイル名 |
| `size` / `contentType` | APIが返したサイズ（バイト数の文字列）とMIMEタイプ |
| `path` / `error` | ZIP内の保存先。取得失敗では保存先を空にして理由を記録 |

一部のファイルだけ取得できない場合は、取得できた分を保存し、`download_errors.txt` にも失敗理由を記録します。複数アプリ処理の終了時も警告件数を表示します。すべて取得できない場合は成功扱いのZIPを保存しません。

- [フィールドを取得する](https://cybozu.dev/ja/kintone/docs/rest-api/apps/form/get-form-fields/) — `properties` と `SUBTABLE.fields` はフィールドコードをキーにしたオブジェクトです。表示には `label`、操作には `code` を使います。
- [フィールド形式](https://cybozu.dev/ja/kintone/docs/overview/field-types/) — `FILE.value` のファイル情報と、`SUBTABLE.value[].id/value` のテーブル行を使用します。取得した `fileKey` はダウンロードに使用します。

## CSV取込の事前検査

レコード管理で「CSVからレコードを追加」を選び、ファイルを指定して「CSVを事前検査」を押します。全対象アプリを調べ、件数・対象列・先頭5行（6列まで）の内容と問題を表示します。このボタンはレコードを追加しません。

検査する内容は次のとおりです。

- 閉じられていないダブルクォート、空・重複ヘッダ、データ行の列数のずれ。
- 存在しないフィールド、自動計算・ルックアップのコピー先など書き込み不可の列。
- 必須項目の空欄と、初期値のない必須フィールドの列不足。初期値や、CSV内のルックアップから自動で入る項目は考慮します。
- 選択肢にない値、数値として解釈できない形式、重複禁止フィールドでのCSV内の同一表記の重複。

問題はCSVの行番号とフィールド名・コードで表示します。行番号はヘッダを1行目とし、引用符内の改行は同じCSV行として数えます。空行は無視します。問題が多い場合は件数を保持し、表示を先頭100件に制限します。

対象やファイルを変えると古い検査結果を消します。「内容を確認する」の後に実行する場合も、ファイルと全対象アプリの設定を再取得・再検査します。2つ目のアプリだけフィールド構成が違う場合も、検査で分かる問題があれば最初のアプリへの書き込み前に中止します。

ファイルの読み取り・CSV解析は1回の操作につき1回です。書き込み用のデータはアプリごとに作り、100件ずつ追加します。実行確認は全対象のアプリID・件数をまとめて1回表示します。登録中のエラーでは、確定済み件数と未処理件数を表示します。

この検査はサーバー側の検証すべてを再現するものではありません。権限、既存データとの重複、数値の範囲・文字数制限、日付形式、ルックアップ先の存在などは登録時にkintoneが検証します。数値や文字列の表記が違う値同士の重複判定もkintoneに委ねます。

- [フィールドを取得する](https://cybozu.dev/ja/kintone/docs/rest-api/apps/form/get-form-fields/) — `required`、`unique`、`options`、`defaultValue`、`defaultNowValue`、`expression`、`lookup.fieldMappings` を利用します。
- [複数のレコードを登録する](https://cybozu.dev/ja/kintone/docs/rest-api/records/add-records/) — 登録できないフィールド、100件の上限、リクエスト単位の失敗と取消の仕様に合わせています。

## ステータス更新のアクション選択

「アクション読込」で、先頭アプリの設定を取得します。同じアクション名でも遷移元が異なれば別の候補として表示します。同じ遷移元に同名アクションが複数ある場合はREST APIで指定できないため、その候補を選択不可にして説明します。アクション名の手入力は引き続き利用できます。

候補を選ぶと、遷移元・遷移先、実行条件、次の作業者の選び方と候補設定、実行者を表示します。「作業者以外でも実行できるアクション」のユーザー・組織・フィールド設定も確認できます。組織やフィールドから実際の候補ユーザーを展開する処理や、実行者の権限判定は行いません。

「選択アクションの対象条件を入力」は、ステータスのフィールドコードを設定から取得し、遷移元の条件と `filterCond` を組み合わせてクエリを置き換えます。必要な条件は続けて編集してください。生成したクエリが残ったまま別のアクションを選んだ場合、条件を入力し直すか編集するまで確認へ進めません。対象変更時には候補を無効にします。

アクション名は実行APIで必要なユーザーの表示言語に合わせて `lang: user` で取得します。作業者欄は遷移後の作業者を指定する欄です。ログイン名が必要になる条件を設定から案内しますが、最終的な可否はkintoneが判定します。

- [プロセス管理の設定を取得する](https://cybozu.dev/ja/kintone/docs/rest-api/apps/settings/get-process-management-settings/) — 状態の作業者、アクションの実行条件・種類・実行者情報を利用します。
- [複数のレコードのステータスを更新する](https://cybozu.dev/ja/kintone/docs/rest-api/records/update-statuses/) — アクション名の表示言語、同名アクションの制約、次の作業者指定、リビジョン検査の根拠です。

## 回帰テスト

`npm run test:all` で型検査・単体テスト・ビルド・全ブラウザハーネスを実行できます。今回のAPI契約データは `tools/統合ツール/tests/fixtures/api-metadata.json`、単体テストは `tests/record/api-metadata.test.ts` にあります。

共通検索の新しい条件と候補表示は `npm run test:lite-shared`、一覧・添付選択の実際の画面操作は `npm run test:record-metadata` で検証します。後者は実装をそのまま読み込み、API通信だけを合成レスポンスに置き換えます。実kintoneの認証・権限や、実サーバーからのファイル取得はこのテストに含みません。

CSVの事前検査とプロセス選択も `test:record-metadata` に含みます。単体テストは `tests/record/csv-preflight.test.ts` と `tests/record/process-metadata.test.ts` にあり、100件を超えた行の不備、複数アプリの構成差、書き込み前停止、キャンセル、実行時の再検査、確定済み件数の保持などを検証します。
